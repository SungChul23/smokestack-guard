- 작성일: 2026-11-17. 브랜치 `20-e-ml-model-training` 유지.
- 상태: 사용자 요청에 따른 설계·사전검토. N1-C 신규 학습 프로토콜은 승인 대기이며, 본 문서는 SPEC-R1 원본을 대체하거나 실제 제출을 승인하지 않는다.
- 현재 목표: 시나리오 B 데이터를 기다리는 동안 시나리오 A의 XGBoost 4종 개선. 국내 K-TMS는 외부 평가 전용. RF는 보류, 시나리오 B 작업 없음.

## 1. S1-C-V1.1-W5 준비 상태

### 확인됨

- 현재 코드의 `--model-id S1-C --experiment-id S1-C-V1.1-W5`가 진입점을 통해 분류 함수에 연결된다. 가중치만 1→5로 변경하고 baseline S1-C V1.0 경로는 유지한다.

- 이번 review_only 재확인: S1-C V1.1 / ml.m5.xlarge 1대 / 7200초 / 별도 S3 출력 prefix / 실험 ID 및 버전 태그 전달. 문법 검사 통과. AWS Session·API·Job 생성 없음.

### 유지할 SPEC-R1 합격 기준

동일 Validation 행에서 F2≥0.326364885620, AP≥0.161162421021, Recall≥0.420241844769, FP≤19,695를 모두 만족해야 한다. 기준 계산은 반올림 표기값이 아닌 저장 원수치를 사용한다. Precision/FN·동일 Recall·동일 경고 예산 결과는 부작용 진단으로 함께 보고하며, 추가 합격선은 승인 없이 만들지 않는다.

- 입력 Validation 결과 재현은 확인했지만, 이것만으로 과거 Train 전체 내용 동일성이 증명되지는 않는다.
- 새 prefix의 현재 권한·충돌·금액 상한과 실제 제출 승인은 별도 확인이 필요하다. review_only는 이러한 AWS 조건을 검증하지 않는다.

### 임계값 분석에서 확인한 재학습 검토 근거

N1-C Validation 1,199,946행에서 baseline Precision23.87% / Recall69.56% / F2 0.503040451666 / AP 0.318142969273. Precision30% 조건의 최대 Recall55.92%, Precision40%는31.72%, Precision50%는11.33%였다. Recall80%를 확보하면 Precision18.31%로 떨어졌다.

임계값 조정만으로 AP나 이미 최적화된 F2 최대값을 높일 수 없다. 따라서 점수 분리도를 개선하기 위한 단일 학습 후보를 검토할 근거는 있다. 다만 이 결과만으로 과적합이나 depth6이 원인이라고 입증되지는 않았다. depth4는 복잡도를 줄이는 해석 가능한 대조 실험이며, 희귀 위험 패턴 손실·Recall/AP 저하가 가능한 후보이지 검증된 개선책이 아니다.

- 실험 ID 제안: `N1-C-V1.1-D4`. 모델 버전 V1.1. 기존 임계값 정책 실험 `N1-C-P1.1-TH`와 구분한다.

### N1-C 채택 기준 제안 — 아직 확정 아님

비교 일관성을 위해 S1-C 내부 기준 구조를 N1-C에도 적용하는 안이다. 운영 안전 기준을 대신하지 않는다.

- F2≥baseline+0.010 → 0.513040451666 이상.
- AP≥baseline+0.005 → 0.323142969273 이상.
- Recall≥baseline−0.020 → 0.675592864638 이상.
- FP≤floor(63,421×1.10)=69,763행.
- 동일 Recall/경고 예산 성능과 날짜·굴뚝별 악화는 반드시 보고하되 별도 합격선을 만들려면 먼저 승인받는다.
- 위 기준·후보1개·최대 시간·비용을 실험 전에 승인한다. 결과를 보고 기준을 완화하거나 다른 후보로 자동 재시도하지 않는다.

RF 보류를 반영한 XGBoost4개 후보의 전체 실행시간 상한 제안은 각7200초·1대일 때8인스턴스·시간이다. 현재 분류2개만의 상한은4인스턴스·시간이다. 이는 금액 승인 또는 실제 실행 예약이 아니며, 회귀 실행과 N1-C 명세 변경 승인 없이 자동 적용하지 않는다.

## 4. 동일 행 평가 및 부작용 비교 설계

### 행·환경 동등성

- 모델별 기존/후보의 같은 CEMS Validation 행을 비교한다. N1-C와 S1-C는 물질이 다르므로 서로 같은 행을 요구하지 않는다.
- 파일 목록/입력 해시·Feature 순서·원본 file_index/row_position·y digest·적격 정책·벽시계 경계·행 수를 대조한다. 불일치면 교집합 축소·원본 보정 없이 중단한다.
- Baseline y/probability/원본 위치와 전체 임계값 곡선은 기존 validation_run에 있으므로 동일 해시일 때 재사용한다. 새 baseline 추론은 불필요하게 반복하지 않는다.
- 각 모델 자체 F2 최대 임계값에서 AP/F2/Precision/Recall/TP/FP/FN/TN·경고 행을 보고한다. 후보별 Validation 임계값 선정 규칙과 반복 사용 이력을 기록한다. Test/국내 점수로 선택하지 않는다.

### 같은 Recall 비교

baseline의 F2 임계값 Recall을 기준 R0로 잡는다. 후보의 실제 고유 확률 경계 중 R≥R0인 가장 가까운 달성 Recall을 택하고, 같은 Recall이면 FP가 적은 후보를 사용한다. baseline/후보의 실제 Recall과 차이를 함께 제시한다. 동점 확률 때문에 정확히 같지 않으면 “동일 Recall”로 단정하지 않고 “R0 이상 근접 비교”로 표시한다. 70%/80% 지점도 진단용으로 병기 가능하다. 부동소수점 허용오차는 원본 TP/양성 수의 정수비로 판정하며 임의 허용폭을 만들지 않는다.

### 같은 경고 건수 비교

baseline F2 임계값의 경고 행 A0를 고정 예산으로 잡는다(N1-C83,308 / S1-C21,036). 후보는 경고 행≤A0인 임계값 중 Recall 최대를 택하고, 동률이면 경고가 적은 지점을 선택한다. 같은 확률 묶음을 임의로 잘라 정확한 top-k를 만들지 않는다. 실제 사용 경고 수와 남은 예산을 같이 보고하고, 정확히 같지 않으면 “같은 경고 예산 이내”로 표시한다. 행 단위 경고를 사건/알림 건수로 바꾸지 않는다.

### 해석

- AP 개선은 순위 분리도, 임계값 변화는 Precision/Recall·FP/FN의 교환관계로 분리한다.
- 평균 개선만 아니라 날짜·굴뚝·현재비율 구간의 FP/FN 집중을 보고한다. 클래스 희소성과 반복 관측 상관성을 명시하며 작은 차이를 통계적 유의성으로 단정하지 않는다.
- 동일 Recall/경고 예산의 보조 비교 임계값은 분석용이며 후보의 공식 F2 임계값을 사후 대체하지 않는다. 운영 정책 적용은 별도 승인이다.

## 5. SageMaker 실행 연결과 필요한 코드 변경

### S1-C

현재 W5 경로는 준비됨. train_s1.py의 분류 함수·진입점·제출 코드에 이전 작업의 단일 실험 라우팅이 존재한다. 이번에는 추가 수정하지 않았다. 전용 환경 고정과 데이터/Validation 행 동등성 검사는 제출 전 보완해야 한다.

### N1-C — 명세 승인 후에만 구현

1. train_n1.py: 분류 함수에 승인된 실험 ID 경로만 추가하여 max_depth4 적용. Baseline 기본 경로 및 회귀 함수 불변. 실제 XGBoost버전·effective config·changed_only 기록.
2. train_entrypoint.py: 현재 허용 실험은 W5뿐이므로 N1-C-V1.1-D4 조합을 별도 허용·검증한다. 잘못된 모델/실험/버전 조합은 fit 전에 차단한다. 평가·저장 흐름은 기존대로 유지한다.
3. sagemaker_job.py: 모델-실험-버전의 명시 매핑 확장, N1-C V1.1 및 max_depth4를 review_only에 표시하고 독립 Job으로 전달한다. N1-C baseline은 여전히 V1.0. W5·회귀·RF 설정을 암묵 변경하지 않는다.
4. 의존성: 실제 V1.0 성공 환경을 대조하고 후보 전용 고정/검증 방식을 결정한다. 공통 requirements를 바꿔 다른 모델 환경을 조용히 변경하지 않는다. 설치·새 패키지 버전 선택은 별도 승인 범위다.
5. 평가 보완: 동일 행 검증과 위 두 보조 비교를 기존 평가와 분리한 분석 코드로 준비한다. 모델 선정 주지표·Label·학습 데이터는 변경하지 않는다.

현재 N1-C D4는 CLI 허용 실험이 아니므로 review_only 검증 완료라고 표시하지 않는다. 임의로 model-version만 바꾸어 depth4 학습이 된다고 간주하지 않는다.
