# Contract: 로컬 질문 도구 `services/rag-docs/ask.py`

A의 PC(WSL)에서 사용자 AWS 프로필로 실행한다. 지식 기반 ID는 코드에 넣지 않고 `--kb` 또는 환경 변수 `RAG_KB_ID`(값은 `terraform -chdir=infra/stacks/tms-rag output -raw knowledge_base_id`).

## 사용

```bash
python ask.py "현행 질소산화물 배출허용기준은?"              # 조각만 (Retrieve)
python ask.py "…" --top 8                                  # 조각 수 (기본 5, 최대 20)
python ask.py "…" --status 현행                             # effective_status 거르기 (여러 번 가능)
python ask.py "…" --answer                                 # 답변 + 인용 (Retrieve → 이름표 머리말 붙여 Converse)
python ask.py "…" --json                                   # 원자료 JSON
```

- 검색 방식: 항상 혼합(HYBRID). 지식 기반 기본값은 벡터만이라 짧은 문서(시행령 별표 8, 2쪽)가 큰 문서(시행규칙 별표 8, 355조각)에 묻힌다(2026-11-24 콘솔 시험). 효력 거르기는 기본 없음(시험이 구판도 보게).
- 문서 지목: 질문에 "시행령 별표 8", "관제센터 규정 별표 1", "시행규칙 제15조"가 있으면 `rag_query.find_targets`가 이름표 필터(`law_name`+`part`)를 만들어 그 문서 안에서 찾는다. 지목이 둘 이상이면 문서마다 따로 찾아 번갈아 합치고("각각" 질문), 결과가 비면 필터 없이 다시 찾는다.
- 현행 우선 섞기: `--status`를 주지 않으면 현행 문서만 찾는 검색을 앞에, 필터 없는 검색을 뒤에 두고 번갈아 합친다. 구판 업무편람(807조각)이 상위를 차지해 현행 근거(예: 정도검사 주기 = 형식승인 고시 별표 7)가 밀리기 때문. 지목 문서가 다른 문서를 가리키는 경우(관제센터 별표 2 → 시행규칙 별표 8)도 필터 없는 검색이 채운다.
- 답변: `RetrieveAndGenerate`는 조각 본문만 모델에 넘겨 본문 중간 조각의 출처(어느 법령의 몇 번 별표인지)를 모델이 모르고 인용도 빠진다(콘솔 시험: 시행규칙 별표 8 조각 4개를 받고도 "없다"고 답함). 그래서 Retrieve 결과마다 `[n] 법령명 별표 제목 (시행일, 효력) · 쪽` 머리말과 `caveat`을 붙여 Converse로 부른다. 공통 함수는 `services/rag-docs/rag_query.py`.
- 답변 모델: `--model` 또는 `RAG_ANSWER_MODEL`(기본 Claude Haiku 4.5 추론 프로필). 별칭 `haiku`(Haiku 4.5)·`sonnet`(Sonnet 4.6 — 4.5는 레거시로 막힘), 그 밖의 값은 추론 프로필 ID로 본다.

```

지목: (질문이 문서를 지목했을 때만)

    파일 laws/대기환경보전법시행규칙_별표8_배출허용기준_현행_제71호_20261112.md  쪽 3
    | 배출시설 | 질소산화물(ppm) | … (본문 앞 200자)
#2  …
```

## 오류

| 상황 | 메시지 | 종료 코드 |
|---|---|---|
| ID 없음 | `지식 기반 ID가 없습니다: --kb 또는 RAG_KB_ID` | 2 |
| 자격 증명 없음·만료 | `AWS 자격 증명을 찾을 수 없습니다 (프로필·리전 ap-northeast-2 확인)` | 2 |
| 권한 없음 | `권한 없음: <API> (<오류 코드>)` | 3 |
| 지식 기반 없음 | `지식 기반 <ID>를 찾을 수 없습니다 (리전·apply 확인)` | 3 |

## 시험 묶음 `run_eval.py`

```bash
python run_eval.py --kb $RAG_KB_ID            # eval_questions.yaml 전체
python run_eval.py --kb … --only q03 q07
```

출력: 질문별 `통과/실패`, 기대 문서 순위, 1위 문서, 전체 통과율, 같은 번호 별표 질문 통과율. 결과 표를 `eval_results/<YYYY-MM-DD>.md`로 저장.
