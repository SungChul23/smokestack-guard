## 배경

에이전트는 "이 굴뚝이 기준을 넘었나", "30분 평균은 어떻게 계산하나", "초과하면 어떤 처분·부과금이 있나" 같은 질문에 **법령과 고시를 근거로** 답해야 하고, 답변에 법령명·조문(또는 별표)·시행일을 인용해야 한다(기획서 요건). 모델이 기억으로 답하면 개정 전 기준이나 다른 법령의 숫자를 섞을 수 있다.

### D 자료(2026-11-23 전달) 반영

| 자료 | 쓰는 법 |
|---|---|
| `manifest.csv` | 메타데이터 값(효력 상태, 문서 등급, 주의사항)의 원천. 용어를 D와 맞춘다 |
| `docs/`(교차검증, 법령체계도 대조) | 품질 문제와 시험 질문의 근거. 임베딩하지 않는다 |
| `law/` 글자 추출본(txt) | 쓰지 않는다. 같은 문서를 원본 PDF로 받았다(txt는 표 칸이 섞이고 띄어쓰기가 빠짐) |
| 근거 카드 8장·사례 6건 | 이번에는 넣지 않는다(draft, 원문이 아닌 요약·해석). D 검토 뒤 "참고 자료" 등급의 별도 데이터 소스로 2차 검토 |
| 질의회신 사례집, "선택" 고시 4개 | 범위 밖(개별 회신 / TMS와 거리가 멀어 검색을 흐림) |

D가 찾은 PDF 품질 문제와 대응:

| 문제 | 대응 |
|---|---|
| 법제처 PDF 쪽마다 머리글 `법제처 N 국가법령정보센터 <법령명>` 반복 | 읽기 단계에서 머리글·쪽 번호를 빼도록 지시 |
| 표가 줄 단위로 펴져 열이 섞임(별표 4·5·8·36, 관제센터 별표 1·2 등) | 쪽을 그림으로 보고 표 구조를 읽는 방식으로 처리, 표는 표 형태로 유지하도록 지시 |
| 업무편람 제목 줄의 글자 겹침(`굴굴뚝뚝`) | 위와 같은 방식으로 읽어 영향 확인, 남으면 지시문 보강 |
| 법 본문 PDF에 아직 시행 전 조문(제3조의3, 제60조의5·6 등, TMS 무관) | 문서 메모에 남기고, 시험 질문으로 현재 답에 섞이지 않는지 확인 |

### 구성

```
PC의 PDF 39개 + 문서마다 메타데이터 파일 ─▶ 새 문서 버킷 (법령·고시 / 편람 두 폴더)
                                                │ 동기화
                       지식 기반: 읽기(표·머리글 처리) → 조각 → 임베딩
                                                │
                       로그 검색 도메인의 새 인덱스 (한국어 형태소 + 벡터)
                                                │
          로컬 시험 도구 / 에이전트(D): 자연어 질문 → 관련 조각 + 출처 → (선택) 인용이 붙은 답변
```

**같은 번호의 별표**: 시행령 별표 8(기본부과금 부과계수)과 시행규칙 별표 8(배출허용기준), 시행령 별표 9(확정배출량)와 시행규칙 별표 9(측정기기 운영·관리기준)처럼 번호가 같은 별표가 있다. 잘린 조각만 보면 구분되지 않으므로 법령명·제목·별표 번호를 조각의 검색 내용에 함께 반영한다. 지식 기반은 본문 속 "별표 1에 따라" 같은 참조를 따라가지 않으므로 문서마다 연결 조문 목록도 붙인다.

**비용**: 추가 서버가 없다(기존 검색 도메인 사용). 약 500쪽 임베딩은 1센트 안팎, 표를 읽는 방식은 쪽당 과금이라 전체 수 달러 이내, 시험 질문의 답변 생성은 1달러 미만. 서버리스 벡터 저장소는 최소 월 $170 이상이라 쓰지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 문서를 올리면 질문으로 찾을 수 있다 (Priority: P1)

A가 PDF 39개와 메타데이터를 문서 버킷에 올리고 동기화하면 모두 색인된다. 자연어 질문을 넣으면 관련 조각이 출처(법령명, 별표·조문, 시행일, 효력 상태, 파일, 쪽)와 함께 나온다.

**Why this priority**: 이 기능의 목적이다. 색인과 검색이 되어야 품질 확인(US3)과 에이전트 연결이 가능하다.

**Independent Test**: 동기화 결과에 39개 문서가 실패 없이 색인되었고, "굴뚝 자동측정기기 부착대상" 질문의 상위 조각에 시행령 별표 3이 법령명·시행일과 함께 나온다.

**Acceptance Scenarios**:

1. **Given** 문서 버킷에 PDF 39개와 메타데이터 39개, **When** 동기화한다, **Then** 39개 모두 색인되고 실패·건너뜀이 0이다.
2. **Given** 색인 완료, **When** "30분 평균치는 어떻게 계산하나"를 묻는다, **Then** 상위 조각에 관제센터 규정 제2조(정의)가 나오고 출처에 고시 번호·시행일이 있다.
3. **Given** 색인 완료, **When** "질소산화물 배출허용기준"을 묻는다, **Then** 상위 조각이 시행규칙 별표 8이고 시행령 별표 8(부과계수)이 아니다.
4. **Given** 색인 완료, **When** "현행 대기 초과배출부과금 산정지수"를 묻는다, **Then** 산정지수 고시(제2025-58호)가 나오고 업무편람(구판)의 지수가 근거로 쓰이지 않는다.
5. **Given** 색인된 조각, **When** 본문을 본다, **Then** 법제처 쪽 머리글이 들어 있지 않다.
6. **Given** 문서 하나를 고쳐 다시 올리거나 새 문서를 추가함, **When** 다시 동기화한다, **Then** 그 문서만 다시 처리되고 예전 조각은 남지 않는다.
7. **Given** 문서 하나를 버킷에서 지움, **When** 동기화한다, **Then** 그 문서의 조각이 검색에서 사라진다.

### User Story 2 - 문서마다 정확한 출처 정보가 붙는다 (Priority: P1)

A는 39개 PDF마다 메타데이터 파일을 한 번에 만들고, 올리기 전에 검사로 빠진 짝·잘못된 이름·허용되지 않는 값·쪽수 불일치를 잡는다. 값은 문서와 D의 manifest에서 확인된 것만 쓰고, 확인되지 않은 값(원본 주소, 공공누리 유형, 편람 발간일 등)은 빠진 목록으로 따로 남긴다.

**Why this priority**: 출처 정보가 틀리면 답변 인용이 틀린다. 같은 번호 별표 구분과 구판 표시도 이 정보에 달려 있다.

**Independent Test**: 생성 명령 → 검사 명령이 39/39 통과를 보고하고, 일부러 짝 파일 하나를 지우거나 값 하나를 비우면 검사가 그 파일과 이유를 짚어 실패한다.

**Acceptance Scenarios**:

1. **Given** PDF 39개가 있는 폴더, **When** 생성 명령을 실행한다, **Then** 각 PDF 옆에 `<PDF 파일명>.metadata.json`이 생기고 원본 PDF는 바뀌지 않는다.
2. **Given** 생성된 파일, **When** 검사 명령을 실행한다, **Then** 짝 존재, 파일명, 형식, 값 종류(글자·숫자·참거짓·글자 목록만), 크기 한도, PDF 쪽수 일치를 확인해 39/39 통과를 보고한다.
3. **Given** 확인되지 않은 값, **When** 메타데이터를 만든다, **Then** 그 항목은 파일에 넣지 않고 빠진 항목 목록에 문서별로 나온다.
4. **Given** 업무편람, **When** 메타데이터를 본다, **Then** 효력 상태가 "구판"이고 "부과금 숫자 인용 금지" 주의가 있다.
5. **Given** 메타데이터, **When** 지식 기반이 조각을 만든다, **Then** 법령명·문서 제목·별표 번호가 조각의 검색 내용에 함께 반영된다.
6. **Given** 업로드 대상 폴더, **When** 올린다, **Then** PDF와 메타데이터 외의 파일(빠진 항목 목록, 스크립트, 원본 별표 8 55쪽)은 올라가지 않는다.

### User Story 3 - 내 PC에서 자연어로 묻고 결과를 확인한다 (Priority: P1)

A는 서버나 화면 없이 내 PC 터미널에서 질문을 입력해, 검색된 조각과 출처·점수를 바로 본다. 필요하면 같은 질문으로 인용이 붙은 답변까지 받아 본다. 정해 둔 시험 질문을 한 번에 돌려 결과를 기록한다.

**Why this priority**: 에이전트(D) 연결 전에 검색 품질을 A가 직접 확인하고 조정(조각 방식, 메타데이터, 읽기 지시)할 수 있어야 한다.

**Independent Test**: 질문 하나를 넣으면 10초 안에 조각 5개가 법령명·별표·시행일·효력 상태·쪽·점수와 함께 나오고, 답변 모드에서는 답변 끝에 인용 출처가 붙는다. 시험 질문 묶음 실행이 질문별 통과·실패 표를 남긴다.

**Acceptance Scenarios**:

1. **Given** 색인 완료와 A의 AWS 자격 증명, **When** "현행 SOx 배출허용기준"을 입력한다, **Then** 조각 목록이 순위·점수·법령명·별표·시행일·효력 상태·파일·쪽과 함께 나온다.
2. **Given** 답변 모드, **When** 같은 질문을 입력한다, **Then** 답변과 함께 근거 조각의 법령명·조문(별표)·시행일이 인용으로 나온다.
3. **Given** 시험 질문 묶음(질문마다 기대 문서), **When** 한 번에 실행한다, **Then** 질문별로 상위 조각에 기대 문서가 있는지 통과·실패와 전체 통과율이 나온다.
4. **Given** 지식 기반이 없거나 권한이 없음, **When** 질문한다, **Then** 무엇이 문제인지(이름·권한·리전) 알 수 있는 오류가 나온다.

### User Story 4 - 에이전트가 같은 지식 기반을 부를 수 있다 (Priority: P2)

D의 에이전트가 로컬 시험 도구와 같은 방법으로 지식 기반을 불러 근거 조각과 출처를 받는다. A는 부르는 방법(식별자, 필요한 권한, 결과 모양, 인용 규칙, 효력 상태 필터)을 정리해 D에게 넘긴다.

**Why this priority**: 최종 목적이지만 대화 처리는 D(#66) 범위다. A는 연결 정보와 권한까지.

**Independent Test**: 에이전트 서버 역할로 같은 질문을 보내 로컬 도구와 같은 조각 목록을 받는다.

**Acceptance Scenarios**:

1. **Given** 에이전트 서버 역할, **When** 지식 기반 검색을 호출한다, **Then** 권한 오류 없이 조각과 출처를 받는다.
2. **Given** 연결 안내 문서, **When** D가 읽는다, **Then** 식별자, 호출 방법, 결과 필드, 인용 형식, 효력 상태 거르기, 비용 주의가 한곳에 있다.

### Edge Cases

- 번호가 같은 별표(시행령 별표 8·9 ↔ 시행규칙 별표 8·9): 조각에 법령명이 함께 반영되어 구분된다(US1 시나리오 3).
- 시행규칙 별표 8의 21쪽 앞부분에는 과거 기준의 비고 몇 줄이 남는다. 현행 기준 숫자 질문의 결과에 섞이지 않는지 시험 질문으로 확인한다.
- 시행령 별표 4·5 제목의 "[시행일: 2020. 1. 1.] 질소산화물 관련 부분" 표기: 시행일 메타데이터는 시행령 기준(2026-11-12)으로 두고 표기는 별도 항목에 남긴다.
- 시행령·법 본문의 시행 예정 부분(시행령 제63조제2항제4호의22·별표 15 일부 2026-12-10, 법 제3조의3 등 2026-12-10~2027-01-10)은 TMS와 무관하다. 메모로 남기고, 시행일이 지나면 효력 상태를 다시 본다.
- 전산기록·보존 고시와 IoT 관제센터 운영규정의 법제처 파일명에 같은 고시 번호(제2025-165호)가 있다. 메타데이터를 만들 때 PDF 본문의 번호를 확인한다.
- 업무편람 질의·회신(Ⅵ장)은 질문과 답이 다른 조각으로 갈라지면 쓸모가 줄어든다. 편람은 법령과 다른 폴더에 두어 조각 방식을 따로 정할 수 있게 한다. 편람 PDF 쪽수 = 인쇄 쪽 + 4.
- 메타데이터 파일이 한도(10KB)를 넘거나 허용되지 않는 값(빈 값 등)이 있으면 그 문서는 동기화에서 실패한다 → 올리기 전 검사로 막는다.
- 문서 버킷에 PDF·메타데이터 외 파일이 올라가면 그것도 문서로 색인된다 → 올리기 대상에서 제외한다.
- 검색 도메인은 로그와 공유한다. 메모리 사용률(최대 약 80%)이 색인 뒤 계속 높아지면 인스턴스를 한 단계 올리거나 인덱스 설정을 줄인다. 로그 수집에 영향이 없어야 한다.
- 검색 도메인을 지웠다 다시 만들면 인덱스를 다시 만들고 다시 동기화하면 복구된다(원본은 문서 버킷).

## Requirements *(mandatory)*

### Functional Requirements

**문서·메타데이터 (US2)**

- **FR-001**: 문서 39개는 받은 PDF 그대로(내용 변환 없이) 쓴다. 쪽 분할은 시행규칙 별표 8(21~55쪽만)에만 한다.
- **FR-002**: 문서마다 같은 위치에 `<PDF 파일명>.metadata.json`을 둔다. 값의 종류는 글자, 숫자, 참거짓, 글자 목록만 쓰고, 파일 하나는 10KB 이하다.
- **FR-003**: 메타데이터 항목: 문서 식별자(영문), 한글 제목, 법령명, 문서 종류(법률·시행령·시행규칙·고시·훈령·별표·편람), 본문/별표 번호, 별표 제목(별표일 때), 호수, 시행일(인용용 글자 `YYYY-MM-DD`와 거르기용 숫자 `YYYYMMDD`), 별표 개정표시(있을 때), **효력 상태(현행·구판·과거)**, **문서 등급(법률·시행령·시행규칙·위임 고시·훈령·업무편람)**, **TMS 관련도(직접·간접)**, 소관 기관, 연결 조문 목록, 표 중심 여부, 쪽수, 주의사항(있을 때). 확인된 값만 넣고, 효력 상태·문서 등급 용어는 D의 manifest와 맞춘다.
- **FR-004**: 법령명, 한글 제목, 본문/별표 번호는 조각의 검색 내용에 함께 반영되도록 표시한다. 나머지는 거르기·인용용으로만 둔다.
- **FR-005**: 연결 조문 목록에 교차 참조를 넣는다: 시행령 제17조 → 별표 1의3·2·3·3의2, 시행령 제24·25·27·28·29조 → 별표 4·5·5의2·6·7·8·9, 시행규칙 제15·33조 → 별표 8, 시행규칙 제37조 → 별표 9·9의2, 시행규칙 제52조 → 별표 11, 시행규칙 제134조 → 별표 36, 관제센터 규정 제7조 → 별표 1, 제9조 → 별표 2 → 시행규칙 별표 8 제3호 라목 6), 관제센터 제1조 → 법 제32조제7항·영 제19조제2항. 그 밖의 연결은 문서 본문의 "(제○조 관련)" 표기에서 확인한 것만 넣는다.
- **FR-006**: 확인되지 않은 값(원본 주소, 공공누리 유형, 편람의 일 단위 발간일 등)은 메타데이터에 넣지 않고, 문서별 빠진 항목 목록을 따로 만든다. 이 목록은 문서 버킷에 올리지 않는다.
- **FR-007**: 메타데이터를 한 번에 만드는 명령과, 짝 존재·파일명·형식·값 종류·크기·PDF 쪽수를 확인하는 검사 명령이 있어야 한다. 검사는 실패한 파일과 이유를 짚는다. 생성은 원본 PDF를 바꾸지 않는다.
- **FR-008**: 시행규칙 별표 8의 21~55쪽을 원본에서 잘라 새 PDF로 만드는 명령이 있어야 한다. 원본 55쪽 파일은 바꾸지 않는다.

**저장·색인 (US1)**

- **FR-009**: 문서는 수집 원본 버킷과 분리된 새 문서 버킷에 둔다. 법령·고시(38개)와 편람(1개)을 다른 폴더에 두어 조각 방식을 따로 정할 수 있게 한다.
- **FR-010**: 지식 기반은 문서 버킷을 동기화해 읽기 → 조각 → 임베딩 → 색인을 한다. 읽기 단계는 표를 표 구조로 읽고, 법제처 쪽 머리글·쪽 번호를 뺀다.
- **FR-011**: 벡터는 기존 로그 검색 도메인(014)의 새 인덱스에 저장한다. 본문은 한국어 형태소 분석으로도 검색되어(키워드 + 의미 혼합 검색) 법령 용어·번호 일치를 보완한다.
- **FR-012**: 다시 동기화하면 바뀌거나 새로 올린 문서만 다시 처리하고, 지운 문서의 조각은 사라져야 한다.
- **FR-013**: 인덱스·역할·권한 설정은 저장소에 정의로 두어, 도메인이나 지식 기반을 다시 만들 때 같은 결과로 복구할 수 있어야 한다.

**권한·보안**

- **FR-014**: 지식 기반은 문서 버킷 읽기, 임베딩 모델(과 읽기 단계 모델) 호출, 새 인덱스 읽기·쓰기 권한만 가진다. 로그 인덱스에는 권한이 없다.
- **FR-015**: 로그 대시보드 사용자(members)의 기존 권한은 바뀌지 않는다. 새 인덱스 쓰기 권한은 지식 기반에만 준다.
- **FR-016**: 문서 버킷은 공개되지 않고, 저장 시 암호화된다.

**시험·연결 (US3, US4)**

- **FR-017**: A의 PC에서 질문을 입력하면 상위 조각(기본 5개)을 순위·점수·법령명·별표·시행일·효력 상태·파일·쪽과 함께 보여 주는 명령이 있어야 한다. 답변 모드는 답변과 인용 출처를 함께 보여 준다. 효력 상태로 거르는 옵션이 있다.
- **FR-018**: 시험 질문 묶음(약 15개, 쉬움·중간·어려움 각 5개, 질문마다 기대 문서)을 저장소에 두고 한 번에 실행해 질문별 통과·실패와 통과율을 보고한다. 질문은 다음을 포함한다: 같은 번호 별표 구분(별표 8, 별표 9), 현행 배출허용기준 값, 표 안의 값, 조문 인용, 30분 평균·무효자료 정의, 행정처분 단계(별표 36), 현행 부과금 산정지수(구판 편람이 아닌 고시), 과태료(별표 15), 정도검사(시험·검사법 간접 문서), 편람 질의·회신.
- **FR-019**: 에이전트 서버 역할이 지식 기반을 부를 수 있는 권한과, 호출 방법·결과 필드·인용 형식·효력 상태 거르기를 정리한 안내를 둔다.

### Key Entities

- **근거 문서**: PDF 한 개. 법령명, 종류, 본문/별표 번호, 호수, 시행일, 효력 상태, 문서 등급, 쪽수를 가진다. 39개.
- **메타데이터 파일**: 문서 하나에 하나. 검색 반영 항목(법령명·제목·별표 번호)과 거르기·인용 항목.
- **빠진 항목 목록**: 문서별 확인되지 않은 항목. 저장소·PC에만 둔다.
- **조각**: 지식 기반이 문서를 잘라 만든 검색 단위. 본문, 벡터, 문서 메타데이터, 쪽 정보를 가진다.
- **시험 질문**: 질문 문장, 기대 문서(법령명 + 별표/조문), 확인 내용.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 동기화에서 39개 문서가 모두 색인되고 실패·건너뜀이 0이다.
- **SC-002**: 메타데이터 검사가 39/39 통과하고, 일부러 깨뜨린 경우(짝 없음, 빈 값, 쪽수 다름) 각각을 실패로 짚는다.
- **SC-003**: 시험 질문의 80% 이상에서 기대 문서가 상위 5개 조각 안에 있다. 같은 번호 별표 구분 질문과 현행 산정지수 질문은 100%다.
- **SC-004**: 답변 모드에서 시험 질문 답변의 80% 이상이 법령명과 조문(또는 별표)과 시행일을 인용한다.
- **SC-005**: 무작위로 고른 조각 20개 중 법제처 쪽 머리글이 남은 조각이 없다.
- **SC-006**: 로컬 도구에서 질문 하나의 조각 결과가 10초 안에 나온다.
- **SC-007**: 색인 뒤 일주일 동안 로그 수집·검색이 계속 정상이고(전달 실패 증가 없음), 검색 도메인 메모리 사용률 최대값이 90%를 넘지 않는다.
- **SC-008**: 구축 비용(읽기·임베딩)이 $10 이하이고, 상시 추가 비용(새 서버)이 없다.

## Assumptions

- 문서 39개의 호수·시행일은 A가 정리한 값과 법제처 파일명·PDF 본문을 따르고, D의 교차검증(같은 판 확인)과 manifest(효력 상태·등급)를 참고한다. 공공누리 유형·원본 주소는 이번 범위에서 확인하지 않는다.
- 검색 도메인(014)은 공개 주소·세분화된 접근 제어·엔진 2.19로, 관리형 지식 기반의 벡터 저장소 조건(공개 접근, 2.13 이상, 세분화된 접근 제어)을 만족한다.
- 임베딩 모델은 한국어를 지원하는 다국어 모델로, 서울 리전에서 쓸 수 있는 것을 고른다. 질문도 같은 모델로 바뀐다. 지식 기반을 만든 뒤에는 바꾸지 않는다(바꾸면 다시 만든다).
- 답변 생성 모델은 시험용으로만 쓴다. 에이전트의 답변 생성·프롬프트는 D(#66)가 정한다.
- 지식 기반 자체와 동기화는 처음에 콘솔에서 만들어 시험하고, 결정이 끝나면 정의를 저장소로 옮긴다(FR-013). 인덱스·역할·버킷은 처음부터 정의로 만든다.
- 범위 밖: 문서 자동 수집·개정 추적, 대기오염공정시험기준(현행본 미확보), 업무편람 2025.12판(미확보), D의 근거 카드·사례(2차 검토), 질의회신 사례집, TMS와 거리가 먼 고시 4개, 지자체 조례.
- 사람이 하는 일: 문서 버킷·권한 적용(plan·apply), 인덱스 생성 명령 실행, 업로드·동기화, 시험 질문 실행.
