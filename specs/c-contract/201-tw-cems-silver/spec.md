# Feature Specification: 대만 CEMS Silver 정제

**Feature Branch**: `10-silver-ktms-contract` (이슈 #10), `14-silver-tw-cems-spark` (이슈 #14)

**Created**: 2026-11-04 | **Updated**: 2026-11-06

**Status**: Implemented (pandas), Spark/Glue 실행 검증 중

**Input**: 대만 CEMS 15분 원본(AQX_P_186)을 K-TMS Silver와 같은 계약의 30분 정제 데이터와 ML 학습용 데이터로 만든다. 1시간 자료(AQX_P_187)는 ML에 쓰지 않고 시간 의미 검증에만 쓴다. 설계 근거는 도은 님의 "굴뚝 TMS | ML-Ready Silver 및 AI 모델링 설계" 문서다. 최종 목표는 대만 CEMS로 학습한 모델로 국내 K-TMS 배출 위험을 예측하는 것이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 신뢰할 수 있는 30분 측정 테이블 (Priority: P1)

데이터·AI 담당자가 모든 항목의 30분 측정값을 사용 가능 여부와 함께 조회한다. 값이 없거나 쓸 수 없는 구간도 행으로 남아 있어, 왜 어떤 구간이 학습에서 빠졌는지 추적할 수 있다.

**Why this priority**: 이후 Feature·Label·모델이 모두 이 테이블에 의존한다. 이것만 있어도 품질 분석과 EDA가 가능하다.

**Independent Test**: 월 하나의 원본으로 테이블을 만들고, 슬롯 수가 `status` 5종의 합과 같은지, 같은 입력을 다시 처리해도 결과가 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 굴뚝·항목·단위의 `:00`·`:15` 15분 값이 모두 숫자이고 상태코드가 `NA10`/`NA11`이며 기준값이 하나다, **When** 30분으로 집계한다, **Then** 평균과 기준 대비 비율이 계산된 `ok` 행이 1개 생긴다.
2. **Given** 15분 값 중 하나가 비었거나 숫자가 아니다, **When** 집계한다, **Then** 값을 0이나 보간으로 채우지 않고 `partial`(숫자 1건) 또는 `invalid`(숫자 없음, 기준값 불일치)로 남는다.
3. **Given** 두 값은 숫자이나 상태코드가 `NA10`/`NA11`이 아니다(`FA10`, `NB`, `AA` 등), **When** 집계한다, **Then** 값과 비율은 보존되고 `other_code`로 표시되어 학습에는 쓰지 않는다. 정책을 넓힐 때 Silver를 다시 만들 필요가 없다.
4. **Given** 기준값이 없는 항목(산소·유량·온도 등)이다, **When** 집계한다, **Then** 값은 보존하고 비율은 비운 `not_monitored`로 남는다.
5. **Given** 같은 키에 완전히 같은 행이 둘 이상이다, **When** 정제한다, **Then** 하나만 남긴다. 같은 시각에 값이 다르면 둘 다 값 없음으로 처리한다.

### User Story 2 - ML 학습용 데이터 (Priority: P2)

AI 담당자가 Silver만으로 분류·회귀 학습을 시작한다. 시계열 Feature와 60분 뒤 정답이 이미 들어 있고, 미래 정보가 Feature에 섞이지 않는다.

**Why this priority**: 설계서의 핵심 원칙("Silver만으로 학습 가능")이다. US1이 먼저 있어야 한다.

**Independent Test**: 임의 시점 t의 Feature가 t 이후 값을 쓰지 않았는지, 정답이 t+60분 실측과 일치하는지 표본으로 대조한다.

**Acceptance Scenarios**:

1. **Given** 현재 시점 포함 연속 6개(3시간)의 `ok` 30분 관측이 있다, **When** Feature를 만든다, **Then** Lag(30~150분), 변화량, 이동통계, 추세, 시간 주기 Feature가 채워지고 `feature_valid`가 참이다.
2. **Given** 중간에 빈 구간이 있다, **When** Lag를 계산한다, **Then** 빈 구간을 건너뛴 값을 쓰지 않고 NULL로 둔다.
3. **Given** 현재 기준 대비 비율이 90% 미만이다, **When** 정답을 만든다, **Then** t+30·t+60에서 90% 이상이 하나라도 있으면 1, 둘 다 유효하고 90% 미만이면 0, 판정 불가면 NULL이다. 회귀 정답은 t+60 비율이며 없으면 NULL이다.
4. **Given** 모델 대상 선택, **When** ML-ready를 만든다, **Then** `status = ok`이고 항목이 `nox`/`sox`이며 단위가 `ppm`인 슬롯만 쓴다.

### User Story 3 - 1시간 자료로 시간 의미 검증 (Priority: P3)

담당자가 공식 1시간 평균(AQX_P_187)과 15분 값 4개 평균을 비교해, 15분 값의 `m_time`이 구간 시작인지 끝인지 판단한다. 이 결과로 30분 격자의 경계를 확정한다.

**Why this priority**: 30분 경계 정의의 근거라 중요하지만, 임시 가정으로 US1을 먼저 만들 수 있었다.

**Independent Test**: 같은 굴뚝·시간에서 해석별 평균 오차를 계산해 어느 쪽이 더 일치하는지 낸다.

**Acceptance Scenarios**:

1. **Given** 같은 굴뚝·물질의 한 시간치 15분 값 4개와 1시간 평균이 있다, **When** 해석별로 평균을 맞춰 본다, **Then** 더 일치하는 해석과 일치율이 기록된다. **결과(2025-10)**: 시작 해석이 4개가 모두 있는 159,979건에서 100% 일치, 종료 해석은 39% 이하.

### User Story 4 - AWS Glue에서 같은 결과로 실행 (Priority: P2)

담당자가 월 단위 원본(S3)을 Glue 작업으로 변환해 pandas 결과와 같은 Silver를 얻는다. 같은 달을 다시 돌리면 그 달만 교체된다.

**Why this priority**: 데이터가 36개월·약 8천만 슬롯으로 커서 PC에서 수동 실행하는 방식으로는 반복 운영이 어렵다.

**Independent Test**: 한 달을 Glue로 처리하고 pandas 결과와 모든 컬럼·행을 비교한다.

**Acceptance Scenarios**:

1. **Given** 같은 원본, **When** Spark로 변환한다, **Then** 모든 컬럼이 pandas 결과와 일치한다. (로컬 Docker 샘플 3개 달에서 확인함. Glue 실제 실행은 남음)
2. **Given** 다른 달이 이미 저장된 출력 위치, **When** 한 달을 다시 쓴다, **Then** 그 달 파티션만 교체되고 다른 달은 유지된다.

---

### Edge Cases

- 기준값(`std`)이 비었거나 0 이하: 비율을 계산하지 않고 `not_monitored`로 값을 보존한다.
- 슬롯 안에서 기준값이 바뀌는 경우: 현재 `invalid`로 처리한다. **Feature 창(150분) 안의 기준 변경 처리는 미정이다** (Open Questions 1).
- `NA10`인데 비율이 100% 이상, `NA11`인데 100% 미만: `flag_code_ratio_mismatch`로 표시하고 삭제하지 않는다. 30분 평균 기준이다.
- 음수·극단값: 삭제하지 않는다. 현재 별도 플래그가 없다 (Open Questions 2).
- 단위가 `ppm`이 아닌 행: 변환하지 않고 `unit`을 보존한 별도 행으로 둔다.
- 시각 형식이 달에 따라 다르다(`T`/공백 구분, 초 유무): 모두 처리한다.
- 원본에 공백이 있는 달(2023-11은 11-27 16:30에서 끊김, 2023-12는 첫 6시간 반 없음): 채우지 않고 빈 구간으로 둔다.
- 같은 월을 다시 처리해도 결과가 같아야 한다(멱등).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 AQX_P_186 월별 원본의 **모든 항목**(`pm`, `sox`, `nox`, `co`, `trs`, `hcl`, `voc`, `o2`, `flow`, `temp`)을 변환해야 한다. 모르는 항목 코드는 번호 그대로 둔다. 모델 대상 선택(NOx·SO₂)은 ML-ready의 일이다.
- **FR-002**: 시스템은 시계열 기준을 측정 시각(`m_time`)으로 통일해야 한다.
- **FR-003**: 시스템은 대만 현지 시각(`ts_local`)과 한국 시각(`ts_kst`, 현지 +1시간)을 구분해 저장하고, `m_time`은 15분 구간의 **시작**으로 해석해야 한다.
- **FR-004**: 시스템은 상태코드가 `NA10`/`NA11`인지로 학습 사용 여부를 정하고, 그 외 코드의 값도 `other_code`로 보존해야 한다.
- **FR-005**: 시스템은 `:00`·`:15` 두 값이 모두 숫자일 때만 30분 평균을 만들고, 하나라도 빠지면 값을 채우지 않아야 한다.
- **FR-006**: 시스템은 값이 없는 슬롯도 행으로 남기고 `status`(`ok`, `not_monitored`, `other_code`, `partial`, `invalid`)로 이유를 표시해야 한다. 원본 15분 행별 제외 사유 컬럼은 두지 않으며 원본 상태코드는 `code2`로 보존한다.
- **FR-007**: 시스템은 완전 중복은 하나로 합치고, 같은 시각에 값이 다른 행은 값 없음으로 처리해야 한다.
- **FR-008**: 시스템은 기준값이 양수일 때만 `ratio = 값 / 기준값`(1.0 = 100%)을 계산해야 한다. ML-ready는 이를 `ratio_pct`(%)로 쓴다.
- **FR-009**: 시스템은 코드와 비율의 불일치에 `flag_code_ratio_mismatch`를 달되 값을 바꾸거나 삭제하지 않아야 한다.
- **FR-010**: 시스템은 단위(`unit`)를 보존하고 환산하지 않아야 한다.
- **FR-011**: 시스템은 Feature를 굴뚝·물질별로 따로 만들고, 현재 시점 이전의 값만 써야 한다. Feature는 `ratio_pct`·`headroom_pct`, Lag 30~150분, 변화량, 3시간 이동통계·추세, 시간 주기(시각·월 sin/cos, 요일)다. 이름은 설계서 9.2를 따른다.
- **FR-012**: 시스템은 현재 포함 연속 6개의 유효 30분 관측이 있는 행만 `feature_valid`로 표시해야 한다. 시간 기준으로 계산해 빈 구간을 건너뛰지 않는다.
- **FR-013**: 시스템은 분류 정답(`label_entry_60m`)과 회귀 정답(`label_ratio_60m`)을 설계서 정의대로 만들어야 한다. 현재 90% 이상인 행은 진입 예측(분류) 대상에서 제외한다. 회귀(`regression_eligible`)는 현재 비율과 상관없이 60분 뒤 값이 있으면 대상이다(2026-11-09 E 결정, `quality_policy_version` v2).
- **FR-014**: 시스템은 정답 값을 학습용으로만 쓰도록 분리할 수 있어야 한다 (`classification_eligible`, `regression_eligible`로 학습 가능 여부 표시).
- **FR-015**: 시스템은 ML-ready에 `feature_version`, `label_version`, `quality_policy_version`을 남겨야 한다.
- **FR-016**: 시스템은 정제 단계별 행 수(입력 → 슬롯 `status`별 → Feature 유효 → 양성 수)를 월별로 기록해야 한다.
- **FR-017**: 같은 입력을 다시 처리하면 같은 결과가 나와야 하며(멱등), 월 단위로 다시 처리할 수 있어야 한다.
- **FR-018**: 정제 코드는 **Spark 3.5 기준**(AWS Glue 5.0/5.1)으로 실행할 수 있어야 하고, pandas 구현을 의미 기준선으로 삼아 두 구현의 결과가 일치해야 한다.
- **FR-019**: 대상 기간은 **2023-11-01~2026-10-31**(36개월)이다. 2023-11, 2023-12는 원본에 공백이 있다.
- **FR-020**: 시스템은 같은 굴뚝·항목에서 한 행의 창(과거 150분 ~ 미래 60분, 슬롯 j−5 ~ j+2) 안에 관측된 `standard_value`가 서로 다르면, 사이에 빈 슬롯이 있어도 그 행의 `classification_eligible`·`regression_eligible`을 False로 해야 한다. 행과 `feature_valid`는 보존한다 (2026-11-09 E 결정, 2026-11-10 E가 빈 슬롯 사이 변경까지 포함하도록 확인, v2).

### Key Entities

- **tw_cems** (Silver): 굴뚝·항목·단위·30분 슬롯 단위 정제 측정값. K-TMS 계약 컬럼 9개(`area_nm`, `fact_manage_nm`, `stack_code`, `item`, `value`, `limit`, `status`, `ts_kst`, `ratio`)와 대만 전용 4개(`unit`, `ts_local`, `code2`, `flag_code_ratio_mismatch`)를 가진다.
- **tw_cems_ml_ready**: `tw_cems`에서 파생한 학습 테이블. Feature, 정답, 학습 가능 여부, 버전을 가진 35개 컬럼.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 월별 슬롯 수가 `status` 5종의 합과 일치하고 슬롯이 말없이 사라지지 않는다.
- **SC-002**: 같은 월을 두 번 처리한 결과가 완전히 같다.
- **SC-003**: 표본 검사에서 Feature가 미래 값을 사용한 사례가 0건이다.
- **SC-004**: 정답 값이 t+60 실측과 일치하는지 표본 1,000행 대조에서 불일치가 0건이다.
- **SC-005**: 0 대체·보간으로 만든 값이 학습 테이블에 0건이다.
- **SC-006**: 36개월 전체 처리 후 월별 `status` 분포와 월별 양성 수가 기록으로 확인된다.
- **SC-007**: 15분 값의 구간 의미(시작/끝)가 근거 수치와 함께 결론으로 기록된다.
- **SC-008**: AI 담당자가 추가 정제 없이 테이블만으로 학습 입력을 만들 수 있다고 확인한다.
- **SC-009**: Glue 실행 결과가 같은 달의 pandas 결과와 모든 컬럼에서 일치한다.

## Assumptions

- Bronze 원본은 확보된 월별 JSONL(S3 `bronze/tw_cems/historical/`)이며 이 spec은 수집을 다루지 않는다.
- 대만 값이 산소 보정이 끝난 기록값이라는 것은 아직 확인하지 못했다 (Open Questions 4).
- 학습·검증·테스트 분할과 모델링은 AI/ML 담당(E)의 일이며, 이 spec은 분할 가능한 데이터와 학습 가능 플래그만 제공한다.
- 국내 K-TMS 적용 시 같은 Feature 규칙을 쓴다. Feature 생성 규칙은 학습과 추론이 공유할 수 있어야 한다.
- Feature 목록·정답 정의·제외 조건은 E와 함께 승인한다(설계서 14장).
- 1시간 자료(AQX_P_187)는 항목 코드 체계가 다르며(NOx 223, SO₂ 222) 시간 의미 검증에만 쓰고 별도 테이블로 저장하지 않는다.

## Open Questions

1. **기준 변경 처리** — 결정됨(2026-11-09, E): 슬롯 안 변경은 `invalid`, 여러 슬롯에 걸친 변경은 창에 들어가는 행을 학습에서 제외한다(FR-020). 36개월 기준 분류 −686행·양성 −11행.
2. **음수·극단값**: 삭제하지 않는 정책이나 플래그가 없다. ML-ready `ratio_pct`에 최소 -7.7, 최대 4,575.7이 있다. 학습 전에 처리 방침이 필요하다.
3. **`NB`/`AA` 학습 포함**: 값은 `other_code`로 보존되어 있다. 코드별 양성 손실률을 분석해 허용 범위를 정한다.
4. **산소 보정과 `std` 일치**, K-TMS와의 측정 기준 비교: 공식 근거를 확인한다. 불명확하면 임의 환산하지 않고 "미확인"으로 기록한다.
