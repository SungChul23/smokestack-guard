# Feature Specification: 대만 CEMS Silver 정제

**Feature Branch**: `10-silver` (이슈 #10)

**Created**: 2026-11-04

**Status**: Draft

**Input**: 대만 CEMS 15분 원본(AQX_P_186)을 30분 격자의 정제 데이터와 ML 학습용 데이터로 만든다. 1시간 자료(AQX_P_187)는 ML에 쓰지 않는 검증 자료로만 정제한다. 설계 근거는 도은 님의 "굴뚝 TMS | ML-Ready Silver 및 AI 모델링 설계" 문서다. 최종 목표는 대만 CEMS로 학습한 모델로 국내 K-TMS 배출 위험을 예측하는 것이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 신뢰할 수 있는 30분 측정 테이블 (Priority: P1)

데이터·AI 담당자가 NOx·SO₂ 30분 측정값을 품질 판정 결과와 함께 조회한다. 쓸 수 있는 행과 제외된 행이 모두 남아 있어, 왜 어떤 구간이 학습에서 빠졌는지 추적할 수 있다.

**Why this priority**: 이후 Feature·Label·모델이 모두 이 테이블에 의존한다. 이것만 있어도 품질 분석과 EDA가 가능하다.

**Independent Test**: 월 하나(예: 2025-12)의 Bronze로 테이블을 만들고, 행 수 대조표(원본 행 = 사용 행 + 제외 행 + 중복·충돌 격리 행)가 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 굴뚝·물질의 연속된 15분 값 2개가 모두 유효하다, **When** 30분으로 집계한다, **Then** 평균과 기준 대비 비율이 계산된 사용 행이 1개 생긴다.
2. **Given** 15분 값 중 하나가 비었거나 무효 코드다, **When** 집계한다, **Then** 값을 0이나 보간으로 채우지 않고 제외 사유가 적힌 행으로 남는다.
3. **Given** 상태코드가 `NA10` 또는 `NA11`이다, **When** 판정한다, **Then** 사용 후보가 된다. `NB`·`AA` 계열은 사용하지 않고 따로 보존한다.
4. **Given** 같은 관측 키에 완전히 같은 행이 둘 이상 있다, **When** 정제한다, **Then** 하나만 남긴다. 같은 키에 값이 다르면 격리한다.

---

### User Story 2 - ML 학습용 데이터 (Priority: P2)

AI 담당자가 Silver만으로 분류·회귀 학습을 시작한다. 시계열 Feature와 60분 뒤 정답이 이미 들어 있고, 미래 정보가 Feature에 섞이지 않는다.

**Why this priority**: 설계서의 핵심 원칙("Silver만으로 학습 가능")이다. 다만 US1이 먼저 있어야 한다.

**Independent Test**: 임의 시점 t의 Feature가 t 이후 값을 전혀 쓰지 않았는지, 정답이 t+60분 실측과 일치하는지 표본으로 대조한다.

**Acceptance Scenarios**:

1. **Given** 현재 시점 포함 연속 6개(3시간)의 유효 30분 관측이 있다, **When** Feature를 만든다, **Then** Lag(30~150분), 변화량, 이동통계, 시간 주기 Feature가 채워진다.
2. **Given** 중간에 결측 구간이 있다, **When** Lag를 계산한다, **Then** 결측을 건너뛴 값을 쓰지 않고 해당 행을 학습 후보에서 제외한다.
3. **Given** 현재 기준 대비 비율이 90% 미만이다, **When** 정답을 만든다, **Then** t+30·t+60에서 유효한 90% 이상 관측이 하나라도 있으면 1, 둘 다 유효하고 90% 미만이면 0, 판정 불가면 NULL이다. 회귀 정답은 t+60 비율이며 없으면 NULL이다.
4. **Given** 학습 기간 경계가 있다, **When** 데이터를 나눈다, **Then** 정답이 다음 구간을 참조하는 행은 제외할 수 있다.

---

### User Story 3 - 1시간 자료로 시간 의미 검증 (Priority: P3)

담당자가 공식 1시간 평균(AQX_P_187)과 15분 값 4개 평균을 비교해, 15분 값의 `m_time`이 구간 시작인지 끝인지 판단한다. 이 결과로 30분 격자의 경계를 확정한다.

**Why this priority**: 30분 경계 정의의 근거라 중요하지만, 임시 가정으로 US1을 먼저 만들 수 있다.

**Independent Test**: 같은 굴뚝·시간에서 두 해석(시작/끝)의 평균 오차를 계산해 어느 쪽이 더 일치하는지 보고서로 낸다.

**Acceptance Scenarios**:

1. **Given** 같은 굴뚝·물질의 한 시간치 15분 값 4개와 1시간 평균이 있다, **When** 두 해석으로 평균을 맞춰 본다, **Then** 더 일치하는 해석과 일치율이 보고서에 남는다.
2. **Given** 1시간 자료를 정제한다, **When** 저장한다, **Then** ML 학습 테이블과 분리된 검증용 테이블에만 들어간다.

---

### Edge Cases

- 기준값(`std`)이 비었거나 0 이하인 행(전체의 약 27%): 비율을 계산하지 않고 사유와 함께 보존한다. 학습 후보에서는 빠진다.
- 한 Feature 창(최대 150분) 안에서 적용 기준(`std`)이 바뀌는 경우: 기준이 바뀐 행은 플래그를 달고 학습 후보에서 제외한다.
- `NA11`인데 비율이 100% 미만인 경우: 불일치 플래그로 보존하고, 학습 포함 여부는 Validation에서 정한다.
- 음수·극단값: 삭제하지 않고 품질 플래그만 붙인다.
- 단위가 ppm이 아닌 행: 변환하지 않고 제외 사유를 적는다.
- 월 경계(월 마지막 구간 ↔ 다음 달 첫 구간)와 파일 사이 중복.
- 같은 월을 다시 처리해도 결과가 같아야 한다(멱등).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 AQX_P_186 월별 원본에서 NOx(923)·SO₂(922)만 정제 대상으로 삼아야 한다. 그 외 물질은 이 데이터셋에 포함하지 않는다.
- **FR-002**: 시스템은 시계열 기준을 측정 시각(`m_time`)으로 통일하고, 적재 시각은 추적용으로만 보존해야 한다.
- **FR-003**: 시스템은 대만 현지 시각과 UTC를 구분해 저장하고, 각 30분 구간의 시작·끝을 명시해야 한다.
- **FR-004**: 시스템은 상태코드를 운전 상태·측정 설비·데이터 상태로 해석해 사용 여부를 판정해야 한다. `NA10`·`NA11`은 사용 후보이고, `NB`·`AA` 계열은 별도 보존하며, 시험·무효·이상·대체값 코드는 제외한다.
- **FR-005**: 시스템은 연속된 15분 값 2개가 모두 유효하고 단위·기준이 같을 때만 30분 평균을 만들어야 한다. 하나라도 빠지면 값을 채우지 않는다.
- **FR-006**: 시스템은 제외된 모든 행을 사유 코드와 함께 보존해야 한다. 어떤 행도 말없이 사라지지 않는다.
- **FR-007**: 시스템은 완전 중복은 하나로 합치고, 키가 같고 값이 다른 충돌은 격리해야 한다.
- **FR-008**: 시스템은 기준값이 양수일 때만 `ratio_pct = 측정값 / 기준값 × 100`을 계산해야 한다.
- **FR-009**: 시스템은 음수·극단값·`NA11`과 비율 불일치에 품질 플래그를 달되 값을 바꾸거나 삭제하지 않아야 한다.
- **FR-010**: 시스템은 각 행에 원본 상태코드, 원본 파일, 처리 시각, 정책·집계·Feature·Label 버전을 남겨야 한다.
- **FR-011**: 시스템은 Feature를 굴뚝·물질별로 따로 만들고, 현재 시점 이전의 값만 써야 한다. Feature는 `ratio_pct`·`headroom_pct`, Lag 30~150분, 변화량, 3시간 이동통계, 시간 주기(시각·월 sin/cos, 요일)다.
- **FR-012**: 시스템은 현재 포함 연속 6개의 유효 30분 관측이 있는 행만 Feature 유효로 표시해야 한다.
- **FR-013**: 시스템은 분류 정답(`label_entry_60m`)과 회귀 정답(`label_ratio_60m`)을 설계서 정의대로 만들어야 한다. 현재 90% 이상인 행은 진입 예측 학습 대상에서 제외한다.
- **FR-014**: 시스템은 정답 값을 학습용으로만 저장하고 추론용 Feature에서 분리할 수 있어야 한다.
- **FR-015**: 시스템은 AQX_P_187을 같은 정제 규칙으로 정리하되 ML 학습 테이블과 분리해 검증용으로만 저장해야 한다.
- **FR-016**: 시스템은 15분 값의 구간 의미(시작/끝) 검증 결과를 보고서로 남겨야 한다.
- **FR-017**: 시스템은 정제 단계별 행 수(원본 → 사용·제외 사유별 → Feature 유효 → 양성 수)를 월별로 기록해야 한다. 양성이 어느 조건에서 얼마나 줄었는지 보여야 한다.
- **FR-018**: 같은 입력을 다시 처리하면 같은 결과가 나와야 하며(멱등), 월 단위로 다시 처리할 수 있어야 한다.
- **FR-019**: 정제 코드는 Spark 4.1 기준으로 작성하고, 이후 AWS Glue로 옮길 수 있어야 한다.
- **FR-020**: 대상 기간은 2024-11-01~2026-10-31이다. 현재 Bronze는 2024-01~2025-12이므로 2026-01~10 구간은 담당자가 추가 수집 중이다. 수집이 끝나기 전에도 확보된 월부터 월 단위로 처리할 수 있어야 하고, 수집이 끝나면 같은 규칙으로 나머지를 이어 처리한다.

### Key Entities

- **silver_cems_30m**: 굴뚝·물질·30분 구간 단위 정제 측정값. 값, 기준, 비율, 상태, 품질 플래그, 제외 사유, 추적 정보를 가진다.
- **silver_cems_ml_ready**: `silver_cems_30m`에서 파생한 학습 테이블. Feature, 정답, 학습 가능 여부 플래그, 버전을 가진다.
- **silver_cems_1h_check**: AQX_P_187 정제 결과. 검증 전용이며 학습에 쓰지 않는다.
- **정제 보고서**: 단계별 행 수, 제외 사유 분포, 양성 손실, 구간 의미 검증 결과.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 월별 원본 행 수가 사용 행 + 사유별 제외 행 + 중복·충돌 격리 행의 합과 100% 일치한다.
- **SC-002**: 같은 월을 두 번 처리한 결과가 완전히 같다.
- **SC-003**: 표본 검사에서 Feature가 미래 값을 사용한 사례가 0건이다.
- **SC-004**: 정답 값이 t+60 실측과 일치하는지 표본 1,000행 대조에서 불일치가 0건이다.
- **SC-005**: 0 대체·보간으로 만든 값이 학습 테이블에 0건이다.
- **SC-006**: 24개월 전체 처리 후, 월별 양성 수와 조건별 손실이 보고서에서 확인된다.
- **SC-007**: 15분 값의 구간 의미(시작/끝)가 근거 수치와 함께 결론으로 기록된다.
- **SC-008**: AI 담당자가 추가 정제 없이 테이블만으로 학습 입력을 만들 수 있다고 확인한다.

## Assumptions

- Bronze 원본은 이미 확보된 월별 JSONL(S3 `bronze/tw_cems/historical/`와 로컬 사본)이며 이 spec은 수집을 다루지 않는다.
- 대만 값은 산소 보정이 끝난 기록값이라고 임시 가정한다. 산소농도(936)와 비교해 검증하고, 틀리면 이 가정을 고친다.
- 30분 격자의 경계는 US3 결과 전까지 현재 구현(`m_time`을 구간 시작으로 보는 해석)을 임시로 쓴다.
- 학습·검증·테스트 분할과 모델링은 AI/ML 담당(E)의 일이며, 이 spec은 분할 가능한 데이터와 제외 플래그만 제공한다.
- 국내 K-TMS 적용 시 같은 Feature 규칙을 쓰므로, Feature 생성 규칙은 학습과 추론이 공유할 수 있어야 한다. 구체 방식은 plan에서 정한다.
- CO(924)와 그 밖의 항목(산소·유량·온도·HCl)은 이번 범위에 넣지 않는다. 산소는 보정 검증에만 쓴다.
- Feature 목록·정답 정의·제외 조건은 E와 함께 승인한다(설계서 14장).
