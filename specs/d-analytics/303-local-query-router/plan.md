# 구현 계획: 로컬 TMS 자연어 조회·화면 라우터

**기능**: 303 · **날짜**: 2026-11-13 · **명세**: [spec.md](spec.md)  
**현재 Git 브랜치**: `main` 유지. 브랜치를 생성하거나 전환하지 않았다. setup_plan의 `BRANCH=303-local-query-router`는 기능 디렉터리에서 계산된 식별자이며 실제 Git 브랜치 생성 결과가 아니다.

## 요약

사용자가 확정한 11개 결정을 일반 JavaScript의 순수 규칙 파서·문맥 병합·검증기·허용 실행기로 나눈다. 현재 플로팅 질문창에 결과 종류별 표시와 확인 선택지를 연결한다. 최신값은 불변 보관 스냅샷, 이력 계산은 화면을 변경하지 않는 사업장/기간 읽기 어댑터, 법령은 기존 302 검색기를 사용한다. 라우터는 구현 전이다. 2026-11-13 후속 요청에 따라 화면 물질 잠금과 공통 지원 설정만 먼저 적용했다.

## 기술 문맥

도구 우선 후속 구현: `tool-catalogue.js`에 논리 도구 계약 6개와 비교/예측 연결 대기를 둔다. `tool-workflow.js`는 실제 Kiwi 표지와 전체 문법을 함께 사용하고, `tool-session.js`가 등록된 카드 ID·질문 당시 문맥·권한/자료 버전·만료·LLM 해석안 확인을 관리한다. 질의 실행 핸들러/SQL/외부 모델은 없다. `tool-benchmark-20261113`에서 실제 14,265개 Kiwi 결과와 후보 JSON/카드 경로를 검토한다. 별도 자연어 9/30 일치와 총 87개 불일치를 남겼으므로 생성 문법의 통과를 범용 자연어 정확도로 주장하지 않는다.

후속 검토 범위: 기존 92개 불일치와 실제 Kiwi 분석을 보존하고 triage-labels.cjs의 사람 검수 전 기준표를 현재 라우터/카드와 대조한다. context-policy.js는 명시 조건·신뢰된 이전 도구 결과·UI 후보를 분리하는 실행 없는 추가 검증기다. 현재 raw parser의 UI/시간 기본값을 그대로 실행 근거로 쓰지 않아야 하며 최종 웹 통합은 별도 대기다. 카드 fingerprint는 timeBinding=map일 때만 mapTime을 의존하고, 문서 버전을 함께 검사한다. 보고서의 기대값 변경은 파서 개선/자연어 정확도로 표현하지 않는다.

2026-11-13 후속 범위: `exceedance-query.js` 순수 집계/조건 검증 + `agent-exceedance.js` 명시적 질문창 조건 폼을 추가한다. 기존 법령 검색을 유지하고 전체 범용 라우터 완료로 간주하지 않는다. 순위 JSON은 기존 인덱스·자료 계약을 재사용해 사용자 조회 후 필요한 날짜(앞 30분 포함)만 읽고 최대 3개 파일의 Promise를 캐시한다. 사업장 범위는 해당 사업장 이력 파일만 읽는다. 자유문장의 조건은 자동 실행하지 않고 원문을 표시한 뒤 폼에서 확인한다. 새 질문/취소/닫기/조건 수정은 토큰을 무효화해 과거 결과 표시를 막는다. 결과는 DOM textContent로 표시한다. 신규 서버·LLM·SQL·운영 인증은 추가하지 않는다.

## 단계별 설계

1. **연구**: [research.md](research.md). 현재 함수·부분 로딩·대표 상태/물질 잠금·날짜 차이를 읽기 전용 조사했다. Spec Kit plan 지시에 따른 연구 에이전트 1개를 사용했고 외부 조사/수정은 수행하지 않았다.
2. **내부 표현과 계약**: [data-model.md](data-model.md), [contracts/local-query.md](contracts/local-query.md). 서버 API가 아닌 브라우저 내부 인터페이스다.
3. **기반**: 문법 전체를 지원할 때만 후보 IR 생성 → 문맥 결합 → 구조/의미 검증. `UNKNOWN`은 실행하지 않는다. 실패 이유와 누락 슬롯으로 확인 선택지를 만든다.
4. **최신/이력 분리**: 최신값은 원본 최신 스냅샷에서 읽는다. 현재 화면의 observations를 전역 이력으로 사용하지 않는다. 이력 요청은 site+기간+revision으로 파일을 읽되 지도/차트 선택을 바꾸지 않는다.
5. **상태 설정**: 기존 단계/범위를 기본값으로 옮겨 동일 버전에서 소비한다. 수치 `>100`·`≥100`, 화면 대표 상태, 사용자 경고선, 모델 예측은 서로 다른 개념이다. 기존 대표 상태가 7종으로 계산되는 사실을 숨기지 않는다.
6. **작은 실행기**: 최신값·상태 원문·NOx/SOx 최신 조건 목록/순위, 선택 굴뚝 평균/최대, 명확한 화면 변경, 기존 법령 검색. 복잡한 다중 intent는 전체 거절/확인하며 일부만 실행하지 않는다.
7. **결과와 확인**: 명시 조건과 사용한 UI 조건·자료/설정 버전·측정 시점·처리 건수·법령 출처를 노출한다. 확인 버튼에는 자유 임의 JSON/함수명을 받지 않는다. 새 질문/문맥 변경 시 오래된 확인·응답은 무효화한다.

## 경계 및 미확정 항목의 처리

- 운영 인증은 데모 선택 UI로 대체하지 않는다. 로컬 capability 게이트를 서버 권한 검증 완료라고 표시하지 않는다.
- 단위는 기존 `unit_source`를 보존한다. 다른 물질 농도를 직접 합산/변환하거나 표시 참조값으로 법적 기준을 확정하지 않는다.
- 시점이 서로 다른 최신값을 비교할 때는 동일 시각인지 또는 각 굴뚝 최신값을 원하는지 확인한다. 미확정 허용 시간차를 도입하지 않는다.
- 전체 과거 집계/순위는 미지원. 전역 초과빈도 모듈을 일반 농도·비율 순위 실행기로 쓰지 않는다.
- 미래 예측/LLM/서버/팀 계약은 단순 실패 처리로 분리한다. 팀 자료가 없어서 이번 로컬 작업 자체를 대기로 만들 필요는 없다.
- `D/`의 실행 기반과 데이터는 현재 Git ignore 대상이다. 이 계획의 재현 기준은 현재 로컬이다. PR에 포함할 경량 실행 기반/자료 전달 방식은 별도 합의가 필요하며 대용량 파일을 자동 커밋하거나 ignore 정책을 변경하지 않는다. 공유 검증 완료로 표시하지 않는다.

## 복잡도 기록

외부 웹 프레임워크·벡터 DB·서버를 도입하지 않는다. 형태소 분석기는 아래 후속 요청에 따라 로컬 검증 랩에 한해 추가했다. 계획된 내부 모듈 경계는 검증기 우회와 읽기/화면 부작용을 분리하기 위한 것이며 운영 계약을 신설하는 목적이 아니다.

## 후속 분기 검증 구현
