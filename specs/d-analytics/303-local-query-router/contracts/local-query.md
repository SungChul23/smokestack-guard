# 로컬 질의 인터페이스 계약

## 적용 범위

브라우저 내부 함수·출력 UI를 위한 계약이다. `POST /api/query/interpret`, SQL 템플릿, 운영 인증을 구현한 계약이 아니다. 추후 서버 연결 시에는 팀 계약과 별도로 매핑한다.

## 진입과 처리

- `controller.submit(question, uiContext)`는 request_id와 문맥을 고정하고 순수 parser/context/validator/router를 통과시킨다.
- `controller.answerClarification(sessionId, optionId)`는 허용된 옵션과 세션의 버전을 확인한 뒤 조건을 보존하여 재검증한다. 임의 함수명·질의문·실행계획을 입력받지 않는다.
- `controller.cancel()`은 늦은 답변/화면 변경을 무효화한다. 일반 조회로 지도·차트 선택을 바꾸지 않는다.
- 화면 문맥은 힌트다. 엔터티 존재/사업장 소속·잠금·단위 출처·기간·자료 버전은 실행 직전에 다시 검증한다.

## 읽기 실행 allowlist

| 도구 | 범위 | 제한 |
|---|---|---|
| `latest_measurements` | 선택 굴뚝/확정 범위의 최신 응답 원문 | 상태문자면 상태를 반환. 과거 숫자 대체 금지. |
| `latest_list` | 확정 사업장/지역/화면/전체 보관 모집단 | NOx/SOx의 명시된 수치·비율·화면 상태 조건만. |
| `latest_rank` | 위 범위 + 확정 지표/N/시점 정렬 | 화면 이력 대신 불변 최신 자료 사용. 시점 정렬이 미확정이면 확인. |
| `single_stack_statistics` | 선택/명시된 단일 굴뚝·물질·기간 | 숫자 원문의 평균/최대, 0 포함, 상태/NULL 제외 건수 표시. |
| `display_status` | 현재 화면 설정과 대상별 적용 물질 범위 | 잠금 물질의 수치 상세를 자동 공개하거나 NOx/SOx 때문이라고 설명하지 않음. |
| `search_regulations` | 302의 확보 문서·기준일 | 현재/과거 날짜를 해석해 asOf에 전달. 기준일 자동 대체 금지. |

전체 기간 집계/순위, 모델 예측/설명, 자유 복합 질의, 물질 간 원시 농도 합산은 미지원이다. 반환 메타에서 첫 버전의 운영 인증 미구현과 로컬 참고 계산임을 구분한다.

## 화면 실행 allowlist

- `select_business`: `StackDashboard.selectSite()`와 기존 지도 엔진의 선택 이동. 지도 좌표/배경을 재생성하지 않는다.
- `select_region`: 기존 지역 식별을 검증한 뒤 `selectRegion()` 사용.
- `set_chart_range` / `set_period`: `TmsReview.range`와 기존 기간 동작을 재사용한다.
- `set_pollutant_visibility`: NOx/SOx의 명시된 표시 변경만. 잠금 물질을 소리 없이 해금하거나 문맥에서 빠뜨리지 않는다.
- `show_measurement_table`: 기존 표 보기 동작 사용.

이 목록 외의 자유 화면 변경은 지원 불가/확인으로 반환한다. 지도 배경 전환·외부 링크 열기·개인 설정 변경 등을 임의 도구로 추가하지 않는다. 모든 화면 명령은 반영 직전 문맥을 재검증하고 적용한 대상/값을 응답한다.

## 자료 읽기 어댑터

1. `snapshotLatest()`는 원본 최신 자료의 불변 읽기 관점을 제공한다. activeSite 변경으로 교체되는 `StackDashboard.data.*.observations`에 의존하지 않는다.
2. `readHistory(siteId, range, revision, cancellation)`는 기존 index/file 캐시와 원문 expand 방식을 재사용하되 화면 선택/활성 observations를 변경하지 않는다.
3. `TmsLocalHistory.load()`를 질의 조회기로 직접 호출하지 않는다. 기존 화면 로더는 유지한다.
4. 파일은 인덱스에서 찾은 same-origin 정적 경로만 읽는다. 질문이 파일 경로/URL로 바뀌지 않는다. 요청 대상 사업장·파일 내용·revision을 확인한다.
5. `TmsReview.localRanking`은 초과 빈도 통계 전용이다. 이번 일반 최신 순위의 대체 출처로 사용하지 않는다.

## 응답과 UI

- 기대값 검수는 실행 결과로 정답을 자동 생성하지 않는다. 원본 질문/기대 파일은 보존하고, 변경한 기준은 ID·원문 해시·판단 근거·카드/도구 조건을 고정한다. 검토 대상 외 사례는 기존 기대를 계속 적용하며, 코드 오류로 분류한 사례는 원래 기대도 반드시 통과해야 한다. 확인·해석 이관을 원문 이해 완료로 합산하지 않는다.

- `service_scope` 카드는 도메인이 불분명한 문맥 요청에서 `tms` 또는 `outside`를 받는다. `tms`는 해석 후보로만 이어지고 명령·자료 조회를 생성하지 않는다. `outside`는 서비스 밖 안내로 끝난다. 세션·권한·버전 검사는 기존 카드와 동일하다.
- `outputFormat` 카드에서 원문/요약/둘 다를 선택하면 이미 확보한 주제·기준일을 보존한 채 같은 검증기를 통과한다. “원문으로 요약”을 “원문과 요약 둘 다”로 자동 단정하지 않는다.
- 후보의 시간·대상·범위에 `0`·`false`·빈 문자열 등 잘못된 자료형을 넣어 필수값 검사를 우회할 수 없다. 도구 모드와 무관한 조건을 혼합하거나 외부 해석안이 현재시각을 바꿔치기하면 완료하지 않는다. 너무 큰 상대 기간은 날짜 계산 전 거절한다.

- 실행 전 로컬 문서 검색 후보의 선택 필드 `outputFormat`은 `original`(원문), `summary`(요약), `original_and_summary`만 허용한다. 명시된 요청만 기록하고 미지정 시 필드를 추가하지 않는다. 다른 도구에는 허용하지 않는다. 원문 조회와 요약 출력을 혼동하지 않기 위한 로컬 표시 조건이며 팀 Silver/서버 계약 변경은 아니다.
- 허용기준값을 실측값으로 대체하지 않는다. 관계가 불명확한 복수 시간/사업장·물질 단독 조건·정의/수치 모호성은 해석/확인으로 넘긴다. 기간 순위의 대표값 계약이 없으면 최신값/평균/최댓값을 임의 선택하지 않는다. LLM 후보도 같은 조건 검증을 통과해야 한다.

- answer: 대상·NOx/SOx·수치/원문·실제 측정시각·보관 기준시각·실시간 아님·단위/기준 출처·자료 버전. 계산은 건수·제외 이유·기간 추가.
- clarification: 짧은 확인 질문, 선택지, 이미 확정한 조건, `executed:false`.
- unsupported: 잠금/지원되지 않는 집계·예측·복합 표현·미확인 단위 등 이유, `executed:false`.
- blocked: 쓰기·삭제·설비 제어·권한 우회 요구, `executed:false`. 도구가 존재하지 않으므로 입력 문자열이 실행되지 않는다.
- error: 로컬 파일 읽기/자료 버전/스키마 불일치. 정상이나 0건으로 위장하지 않는다.

사용자·문서·파일 문자열은 textContent로 렌더링한다. 공식 법령 링크 검사는 302를 재사용한다. 사용자가 명시하지 않은 다운로드·알림·외부 호출은 만들지 않는다.

## 재현 가능한 예시

- 2026-11-13 질문 “어제”: `calendar`, from `2026-11-12T00:00:00+09:00`, to `2026-11-13T00:00:00+09:00`.
- 보관 기준 `2026-11-12T11:30:00+09:00`에 “최근 6시간”: `archive_recent`, from `05:30`, to `11:30`, 두 시각 모두 같은 KST 날짜.
- “NOx 높은 10개”: 범위와 지표 미확정이면 clarification. 이전 옵션 응답은 보존하되 실행 직전 다시 검증.
- “100% 초과”: `gt:100`. “100% 이상”: `gte:100`. “화면상 초과 상태”: 공통 상태 policy 버전.
- “오늘 법령”의 실제 날짜가 확보일과 다름: 302의 `date_unavailable`를 유지한다.
