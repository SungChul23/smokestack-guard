# 연구 결과 — 로컬 질의 라우터

작성일: 2026-11-13. 로컬 파일 읽기와 plan 연구 에이전트 검토를 사용했다. 외부 법령/기술/서비스의 최신성을 새로 조사하지 않았다.

| 결정 | 근거 | 검토한 대안 |
|---|---|---|
| 기존 HTML/JS 확장 | 진입점 `ui-review-20261109/hatch-thin.html`, 상태 `StackDashboard`/`TmsReview`, 서버 질의 endpoint 없음 | React/Next·새 서버: 이번 사용자 선택과 다름 |
| 순수 규칙 + 검증 + 내부 실행기 | 원본 명세 0·4·8·12절, 사용자 로컬 우선 결정 | LLM 해석/형태소 자동 SQL: 미채택 |
| 최신 스냅샷과 이력 분리 | `console-archive-history.js`의 `read()`는 선택 사업장만 교체하고 이전 사업장을 initial로 되돌림 | `records.all()`을 전체 이력으로 집계: 방문 순서 의존 오답 |
| 화면을 바꾸지 않는 이력 읽기 | `getIndex/file()` 캐시를 재사용할 수 있지만 `load()`는 활성 선택과 관측을 바꿈 | 질의 전에 selectSite/load 강제 실행: 명시되지 않은 화면 변경 |
| 순위 출처 분리 | `console-archive-ranking.js`는 NOx/SOx의 숫자/양수 기준 관측 건수와 strict `>` 초과 빈도용 | 농도/비율 최신 순위에 초과빈도 결과 재사용: 지표 오인 |
| 분석 선택은 selectedSite+stack | `state.site`는 지도 공간 선택이며 탐색 시 해제 가능 | 지도 site만 대화 대상으로 사용: 분석 대상 누락 |
| 시간 3종 분리 | `getReferenceTime()`은 전체 보관 기준, 굴뚝마다 실제 측정시각 다름, 질문 시점은 실제 KST | 전부 ‘현재’ 하나로 표현: 보관본·달력 날짜 오해 |
| 최신 상태문자 보존 | 최신 응답이 기기점검 등일 수 있음 | 과거 숫자가 나올 때까지 역탐색: 현재 상태 은폐 |
| 상태/물질/경고선 분리 | `data-model.prepare()`는 7종의 최대 비율을 대표 상태로 사용. 에이전트는 2종만 해금 | HCl 대표 초과를 NOx 원인으로 설명: 오답 |
| 상태 소비자 공통 설정 | `levels/classify`, `urgent>=90`, `allStatuses`, 지도 색상·하단 설명 등이 분산 | classify만 수정: 화면·설명 불일치 |
| 단위 출처 유지 | `unit_source=existing_frontend_reference/unconfirmed`, API에 단위 필드 없음 | `records.series()`가 보충한 단위를 확정 관측 사실로 사용: 근거 오인 |
| 버전/취소 검사 | 기존 이력·법령에는 sequence가 있지만 라우터 문맥 전체 버전 없음 | 완료 순으로 답변/지도 반영: 늦은 작업이 새 선택 덮음 |
| 302 검색 재사용 | `TmsLawSearch.validate/search`와 기존 출처 카드 | 새 문서/LLM 생성: 이번 범위 밖 |
| 법령 날짜를 라우터에서 해석 | 기존 검색의 기본 asOf는 확보일. ‘오늘’ 단어 자체를 날짜로 변환하지 않음 | 11/13 현재 질문을 11/12 기본값으로 검색: 현행 오인 |

## 설계에서 해소한 사항

일부 이력 로딩, 전체/화면 모집단, 잠금 물질, 단위 미확인, 상태 버전, 문맥 경합은 내부 계약과 지원 범위로 제한했다. 새로운 팀 판정이나 모델 스키마를 만들어 해소하지 않았다. 서버 권한·Silver 고유 ID/유효값·ML horizon·법령 갱신은 범위 밖 의존성이며 로컬 설계의 임의 기본값으로 채우지 않는다.
