# 구현 계획: 법령 문서 질문의 요약 답변

## 구조

```
질문(+ 굴뚝 사실)
   │
   ▼  1. 검색 (evidence.py: KeywordRetriever)
후보 조문 ≤5  ── 후보가 비어도 요약기에 보낸다(이유를 분류하려고)
   │
   ▼  2. 요약기 (summarizer.py: GroundedSummarizer, 공용)
{answerable, reason, summary[{text, chunk_ids}], caveats, clarify}
   │
   ▼  3. 코드 검증 (summarizer.py: verify_summary)
   ├─ 통과 + 답할 수 있음  → Part DONE: 요약 + (굴뚝 사실 블록) + 한계 문구
   ├─ 통과 + 이유 있음     → UNAVAILABLE(자료 부족/범위 밖) 또는 NEEDS_INPUT(되묻기)
   └─ 실패·호출 실패       → 원문 발췌 모드(기존)로 되돌림 + notice
```

## 파일

| 파일 | 역할 |
|---|---|
| `app/agent/summarizer.py` (신규) | 공용 요약기: 요청 만들기, 응답 읽기, 검증. 문서·예측 설명이 함께 쓴다 |
| `app/agent/stack_facts.py` (신규) | 굴뚝의 지정 기준·최근 측정값을 도구로 읽어 문장으로 만든다 |
| `app/agent/evidence.py` (수정) | 요약 모드 추가, 관대한 검색(5개), 이유별 안내, 원문 발췌 되돌림 |
| `app/agent/compound.py` (수정) | evidence 부분이 굴뚝을 받아 사실을 붙임, 후속(`follows_last`)이 evidence 부분의 굴뚝도 채움 |
| `app/agent/api.py` (수정) | 요약기를 계획기와 같은 클라이언트로 구성 |
| `tests/test_doc_summary.py` (신규) | 검증기·요약 모드·조합·후속 시험 |

## 결정과 이유

1. **요약 모델에게 굴뚝 수치를 쓰게 하지 않는다.** 굴뚝 사실은 코드가 문장으로 붙인다. 모델에는 맥락으로만 주고, 모델이 쓴 숫자는 후보 원문·굴뚝 사실에 있는 것만 허용한다.
2. **검증 실패는 숨기지 않고 원문 발췌로 되돌린다.** 사용자에게는 "요약을 만들지 못해 원문 발췌로 보여 드립니다"를 알린다.
3. **후보가 비어도 요약기를 부른다.** 후보가 없을 때 자료 부족과 범위 밖과 모호함을 구분하려면 질문을 이해해야 하기 때문이다.
4. **조문 번호는 후보의 `article`과 후보 원문에 나온 번호만 허용한다.** 요약이 다른 조문을 끌어오면 걸러진다.
5. **카드 대신 NEEDS_INPUT 부분으로 되묻는다.** 문서 부분의 되묻기는 새 카드 종류를 만들지 않고 부분 상태와 안내문으로 낸다(공유 응답 형식 유지).
6. **굴뚝 사실은 지도 선택(`selectedStackId`)에서는 가져오지 않는다.** 일반 규정 질문에 무관한 굴뚝 수치가 붙는 것을 피한다.

## 시험 전략
- 결정적 시험(가짜 요약기 클라이언트): 검증기, 이유 구분, 되돌림, 굴뚝 사실 연결, 조합, 후속.
- 검색만의 재현율: 문서 질문 300개에서 후보 5개 안의 정답 조문 비율.
- 실제 모델 시험 재료: 요약기 요청 배치(Haiku가 처리)와 평가 스크립트를 준비한다.

## 색인 카드와 로컬 벡터 색인 (2026-11-19 추가)

요약기에 조문 원문을 줄줄이 보내던 방식(요청당 평균 약 2,800자, 12건 배치 약 2.1만 토큰)을 바꾼다. 법령은 미리 **색인 카드**로 요약해 두고, 카드를 **로컬 벡터 색인**으로 찾은 뒤, 요약기에는 후보 카드와 상위 한 조문의 필요한 원문만 보낸다.

```
질문 ─▶ HybridRetriever(RRF 순위 합치기, '제33조'처럼 조문을 가리키면 그 조문이 먼저)
          ├ KeywordRetriever (기존: 글자 조각 겹침 + 제목 가중)
          ├ VectorRetriever(TF-IDF)  글자 2·3-gram TF-IDF 카드 색인 — 표준 라이브러리만, 기본
          └ VectorRetriever(신경망)  FastEmbed ONNX 다국어 MiniLM 카드 색인 — fastembed·모델 캐시가 있을 때만
        ─▶ 후보 4개 → 요약기 입력: [후보 카드 4개 + 상위 1개 조문 원문 창(350자)]
        ─▶ 요약 → 코드 검증(전체 원문·카드·굴뚝 사실과 대조) → 실패하면 원문 발췌
```

- **카드(app/agent/cards.py)**: id, 제목, 1~2문장 요약, 키워드·일상어, 대표 질문, 다루지 않는 것, 근거 문장 번호, 원문 길이. 카드 파일(`corpus/law-evidence-cards.json`, LLM 생성·검토 전 `review_status=unreviewed`)의 카드는 원문 지문(sha256)이 맞고 `verify_card`(요약·경계의 조문 번호·숫자가 원문에 있는가, 단정 표현, 근거 문장 범위)를 통과할 때만 쓴다. 없거나 거절된 조문은 **결정적 대체 카드**(제목 + 원문 첫 문장 + 제목 낱말·일상어 키워드)를 쓴다. 카드는 찾기 위한 보조이며 법적 근거가 아니다. 사용자에게 보이는 근거·발췌는 항상 조문 원문이다.
- **색인(app/agent/vindex.py)**: 카드 글(제목+요약+키워드+대표 질문)을 벡터로 만들어 JSON 파일로 저장·로드한다. 별도 DB 서버는 쓰지 않는다(22조문). 색인에 종류·모델·카드 지문을 적고, 카드가 바뀌면 지문이 달라 `IndexError_`로 거절하고 다시 만든다(`python -m app.agent.build_index`).
- **정직한 이름**: `char-ngram-tfidf-v1`은 글자 조각이 겹치는 정도를 재는 벡터이며 신경망 임베딩도 의미 검색도 아니다. 신경망은 `neural-fastembed`(paraphrase-multilingual-MiniLM-L12-v2, FastEmbed ONNX, 384차원, 로컬 추론)로만 부른다.
- **결합**: 점수 단위가 다르므로 점수가 아니라 순위를 합친다(RRF, 상수 60). 유사도는 정답 확률이 아니다.
- **실패 처리**: 색인 파일이 없거나 카드와 맞지 않으면 TF-IDF 색인을 메모리에서 다시 만들고, 신경망 색인·임베딩기가 없으면 쓰지 않는다. 검색 도중 한 검색기가 실패하면 그것만 빼고 계속하며 `HybridRetriever.degraded`에 남기고, 응답 안내문에 "일부 검색을 쓰지 못해 키워드 중심으로 찾았습니다"를 붙인다.
- **의존성**: 서비스 환경에는 numpy·fastembed가 없고 추가하지 않았다. 신경망 색인과 질문 벡터는 `D/law-vector/.venv`(fastembed 0.9.1, onnxruntime 1.32.0, 모델 캐시 `D/law-vector/cache`)에서 만든다. 서비스가 신경망 검색을 쓰려면 같은 패키지와 `TMS_EMBED_CACHE`(모델 캐시 폴더)가 필요하며, 없으면 TF-IDF·키워드로 동작한다.
- **요약기 지침 보강**: 모호 질문 되묻기 조건(무엇이 일어났는지 모르는 말 / 주어 없는 한두 마디)과 답하는 일반 질문 구분, 문서 밖 주제는 비슷한 조문이 있어도 no_doc, 범위 밖(외국 법·NOx·SOx 외 오염물질·법률 상담) 구분을 `SUMMARY_SYSTEM`에 명시했다. 검증기는 출처에 없는 제재 주제(허가 취소·과태료·초과부과금·벌금·징역·영업정지)가 요약에 나오면 막는다.
