# 구현 계획: 사용자별 관심 사업장·알림 설정

## 기술 맥락

기존 HTML·CSS·JavaScript를 유지한다. 새 라이브러리·서버·AWS 자원은 없다. D의 별도 모듈 user-preferences.js/css를 최신 관제 진입점에 추가한다. 기존 HTML은 적용 전 백업한다.

## 원칙 점검

수집 연속성·원본 보존 영향 없음. 운영 계약·규칙·모델 판정 변경 없음. 실제 자격 증명이나 외부 발송 없음. 비용 영향 없음. 데모라는 상태를 화면과 결과에 표시한다. 실제 인증/발송은 운영 계약 및 서버 권한 확인 후 별도 기능으로 진행한다.

## 구성

- 세션: sessionStorage의 고정 데모 계정 ID. 실제 토큰·비밀번호를 받지 않는다.
- 설정: localStorage의 버전 있는 사용자별 데이터. 즐겨찾기는 사업장 코드만 저장한다.
- UI: 상단 로그인/내 설정, 선택 사업장 즐겨찾기, 모달의 사업장 검색·즐겨찾기·알림 설정·시연 미리보기.
- 알림: 즐겨찾기 사업장과 선택한 유형의 시연 사건만 처리한다. 네트워크 발송 코드는 없다.
- 재현: 키 없는 기존 관제 화면에서 테스트하고 네이버 진입점은 인증 완료 후 같은 모듈을 순차 로드한다.

## 데이터 모델

DemoSession: accountId. Preferences: version, users[accountId]. UserPreferences: favorites[siteId], alerts(enabled, channel, destination, kinds). 게스트에는 사용자 설정을 노출하지 않는다. 알림 발송 이력처럼 저장하지 않고 미리보기만 현재 세션 화면에 둔다.

## 검증

비로그인 변경 차단, A/B 계정 분리, 재로그인·새로고침 복원, 즐겨찾기 이동, 채널·대상·유형 검증, 즐겨찾기 없는 알림 차단, 로그아웃 잔여 UI 제거, 실제 발송 없음, 키보드·모바일 넘침과 기존 지도/차트 공존을 브라우저에서 확인한다.
