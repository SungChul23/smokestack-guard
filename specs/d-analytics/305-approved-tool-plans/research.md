# 설계 결정

- **선택**: 승인 recipe를 코드에 등록한다. **이유**: 임의 DAG/LLM 자율 도구 연결보다 검토·테스트 범위가 작고 예측 가능하다. **대안**: 모든 복합 요청 이관은 과도하고, 범용 실행 엔진은 현재 계약보다 자유도가 크다.
- **선택**: 단일 요청 검증은 303을 재사용한다. **이유**: 대상/시각 정책과 기존 성공 사례를 보존한다. **대안**: 새 파서 전체 교체는 범위가 크다.
- **선택**: NOx/SOx 평균은 각 1물질 집계 2개, 평균/최댓값도 2개. 공유 대상·기간은 같게 검사한다. **이유**: 기존 집계의 maxPollutants=1을 몰래 바꾸지 않는다.
- **선택**: 경고 근거 후 문서 검색은 순차 의존이다. 문서 실패 시 관측 성공은 보존한다. **이유**: 관측 사실과 법적 절차 근거의 유무를 섞지 않는다.
- **선택**: 비교·추세·상태 지속·지역 집계·예측 조합은 정의/연결 대기로 공개한다. **이유**: 목록에 있다는 이유로 임의 계산 정책이나 팀 명세를 만들지 않는다.
- **선택**: 현재 실행기는 연결하지 않고 결과 상태 대조만 표본으로 검증한다. 별도 기술 조사·계정·외부 서비스가 필요한 미해결 사항은 없다. 운영 계약은 이번 범위 밖의 명시적 의존성이다.
