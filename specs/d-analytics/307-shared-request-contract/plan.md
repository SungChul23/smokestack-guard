# 구현 계획: 공통 문서 요청 계약

**Branch**: 기존 브랜치 유지 · **Date**: 2026-11-15 · **Spec**: [spec.md](spec.md)

## 요약

303 요청/문맥 검증,302 검색,305 계획 검증을 재사용한다. 버전 있는 문서 요청 계약으로 출력 형식·범위·목표/참고 역할·부족 슬롯을 연결한다. 새 패키지·외부 서비스는 추가하지 않는다.

## 기술 문맥

JavaScript CommonJS·브라우저 번들과 Node 내장 검사, 기존 Python3.12/Kiwi 랩을 사용한다. Windows python3 별칭은 실행 불가여서 기존 가상환경 Python을 명시한다. 자료는 기존2026-11-12 말뭉치다.

## 원칙 점검 — 설계 전후 통과

수집·원본·Silver·E 판정·AWS를 수정하지 않는다. 외부 비용/자격 증명 사용0. 도구 allowlist·문맥 만료·잠금·원문 인용·독립 검수를 유지한다. 로컬 계약은 운영 데이터 계약을 대신하지 않는다. git 브랜치/push/배포를 실행하지 않는다.

## 구조와 순서

request-contract.js에 생성/검증/출력과 typed 부족 슬롯을 둔다. tool-session과 rag-pipeline이 요청 계약을 보존한다. 검색은 참고 조문과 목표 역할을 구분하고 같은 계약을 답변 패킷에 전달한다. answer-contract는 전문 출처 manifest와 혼합 출력 두 채널을 검사한다.305는 기존 허용 계획만 dry-run 검증하며 문서 외 실행은 연결하지 않는다.

## 검증

출력 부정·원문 입력/요약 출력·전문1/14구간·혼합1채널·조건 위조를 검사한다. 참고 조문/절차 목표, 미지정 법령, 날짜 위치를 대조한다. 기존 라우터·문서·답변 계약·브라우저와34,999 분류 회귀의 준비 명령4,055건을 확인한다. 고정48건과 신규 표현은 별도로 기록한다.

## 위험과 복구

엄격한 전문·혼합 검증으로 과거 허용 초안이 보류될 수 있다. 기대 변경을 기록하고 검사를 약화하지 않는다. 구형 자연어 부족 조건은 값/도구 의미를 새로 확정하지 않고 재입력 안내로만 호환한다. 변경 전 모듈은 D/query-router-lab/shared-contract-20261115/before-*에 보존한다.
