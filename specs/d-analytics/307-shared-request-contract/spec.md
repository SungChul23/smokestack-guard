# 기능 명세: 공통 문서 요청 계약과 출력 충족 검사

**Feature Branch**: 사람이 관리하는 기존 브랜치 유지
**Created**: 2026-11-15
**Status**: 로컬 계약 구현·검증 완료 / 후속 흐름 결함 보강 진행 — 미해결 B005와 운영 연결은 변경 기록 참조
**Input**: 근본 원인 분석 후 사용자 승인: “진행해, 변경점이나 그런 이슈는 변경점 기록만 해줘”.

## 사용자 시나리오와 검증

### US1 — 한 번 확인한 요청 의미 유지 (P1)

사용자는 원문·요약, 일부·전문·전체, 참고 조문과 찾으려는 절차를 구분해 요청한다. 확인한 조건은 검색과 답변에서도 유지한다.

독립 검증: 원문을 제외한 요약 요청, 날짜 앞뒤 변경, 참고 조문을 포함한 제출 규정 질의를 대조한다.

1. 원문을 읽고 요약만 요청하면 원문 입력과 요약 출력을 구분한다.
2. 법 제32조제5항 관련 계획서 제출 규정 요청은 조문번호 일치만으로 검색 완료를 인정하지 않는다.
3. 필요한 법령 식별 정보가 없으면 구체적으로 확인하며 무관한 질문으로 단정하지 않는다.

### US2 — 부족 조건을 같은 의미로 확인 (P1)

부족한 대상·기간·문서 조건을 구체적으로 확인하고 값이나 기능을 추측하지 않는다. 지원 불가 부분은 남기며 가능한 부분만 조용히 실행하지 않는다.

독립 검증: 허용된 조건 종류로 확인 카드를 만들고, 알 수 없는 조건·다른 요청의 확인·개별 진단 우회가 차단되는지 확인한다.

### US3 — 정확한 인용과 완전한 응답을 구분 (P1)

전문 요청에는 일부 인용만으로 완료하지 않는다. 원문과 요약을 함께 요청하면 두 결과가 필요하다. 전체 범위가 입증되지 않으면 미확인 또는 부분 상태를 유지한다.

독립 검증: 14구간 전문 중1구간, 원문+요약 중 원문만, 전체성 미확인, 원문 의무를 뒤집은 요약을 입력한다. 부족한 응답은 전달을 보류한다. 요약의 독립 검수는 유지한다.

### US4 — 허용된 복합 계획의 경계 유지 (P2)

이미 허용된 복합 계획의 작업과 공통 조건을 같은 요청에 보관한다. 실제 자료·화면 실행이 연결되지 않은 단계는 실행하지 않는다.

독립 검증: 허용된 계획과 임의 단계·변조된 공유 조건을 대조하고 문서 외 실행 호출0을 확인한다.

### 경계 사례

- 법령 종류 미지정·오늘의 현행 자료 미확보·조건의 부정·출력 형식의 정정.
- 원문 일부/전문, 요약/원문+요약, 인용 자체는 정확하지만 의무·예외를 누락한 경우.
- 이전 확인 후 원문·자료·시각·권한 변경, 구버전 해석 결과, 허용되지 않은 조건 종류.

## 요구사항

### 기능 요구사항

- FR-001: 최초 원문과 확인한 대상·시각·역할·출력 요구를 요청별로 보존한다.
- FR-002: 확인하지 않은 조건·기능·법령·범위를 채우지 않는다. 역할이 모호하면 확인한다.
- FR-003: 부족 조건의 종류를 검증한 후 그 종류에 맞는 확인을 표시한다. 표현만으로 다른 조건으로 바꾸지 않는다.
- FR-004: 검색은 참고 문서와 실제 목표, 포함·제외·요구 결과물을 구분하며 원문과 기준일을 보존한다.
- FR-005: 전문의 필요한 구간, 원문+요약의 두 출력, 전체 범위 충족을 각각 검사한다.
- FR-006: 출처 일치는 의미 검수 완료가 아니다. 요약은 결속된 독립 검수 없이는 전달하지 않는다.
- FR-007: 기존 허용 도구·계획·문맥 만료·권한·잠금·원문 보존을 약화하지 않는다.
- FR-008: 변경과 호환성 차이·미해결 문제를 변경 기록에 남긴다. 기존 실패 기록을 덮어쓰지 않는다.

### 주요 개체

- 요청: 원문, 버전, 대상 역할, 요구 결과와 확인 출처.
- 부족 조건: 요청/작업 소속, 허용 종류, 아직 없는 값.
- 검색 충족 상태: 직접 근거·관련 근거·미확보·조건 필요와 출처.
- 답변: 원문/요약의 구분, 선택 인용, 충족 범위와 독립 검수 결속.

## 성공 기준

- SC-001: 재현된 전문·혼합 출력 누락과 부정 출력 사례를 모두 탐지한다.
- SC-002: 기존 준비 명령4,055개의 도구·조건을 보존한다.
- SC-003: 잘못된 조건·문맥·임의 계획의 실행은0회다.
- SC-004: 변경 전후 결과와 신규 표현 결과를 구분해 기록하며 미확인을 완료로 보고하지 않는다.

## 가정과 범위

- 국내 TMS 기본안과 기존 로컬 자료·허용 계획만 사용한다.
- 실제 LLM API·AWS·RDS·예측·설비 제어·새 팀 데이터 계약은 추가하지 않는다.
- 자연어 전체의 의미 정확도를 규칙만으로 보장하지 않는다. 명확하지 않은 역할은 확인으로 남긴다.
