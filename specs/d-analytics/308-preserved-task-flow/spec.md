# 기능 명세: 원문 작업 분리와 조건 확인의 연속성

**Feature Branch**: 사람이 관리하는 기존 브랜치 유지
**Created**: 2026-11-16
**Status**: 로컬 구현·검증 완료 (운영 API·메인 관제 연결 제외)
**Input**: “전부 개선할때까지 계속해 모두”. 남은 실패3·추가 검토3 및 새로운 표현을 검증한다.

## 사용자 시나리오와 검증

### US1 — 일반 검색과 개별 판정을 분리 (P1)

일반 규정 검색과 특정 사업장 위반·신고 지연 판정을 함께 요청하면 두 작업을 모두 보존한다. 지원하지 않는 개별 판정은 명시하고, 이미 요청한 일반 검색 의사를 다시 묻지 않는다.

**독립 검사**: 일반 문서+개별 판정 질문을 입력하고 부족한 기준일·문서만 보충한다. 검색 결과 또는 미확보 안내와 개별 판정 미지원이 함께 남아야 한다.

1. 명시된 문서 검색은 기준일 외 조건이 충분하면 진행한다. 판정은 완료했다고 말하지 않는다.
2. 어떤 신고·통지인지 모르면 실제 문서 식별 조건만 받는다. “TMS 관련인가”로 요청 전체를 축약하지 않는다.
3. 조건 입력 이후 두 작업을 그대로 보존하며 같은 조건을 반복 질문하지 않는다.

### US2 — 일반 흐름과 선택한 자체개선을 보존 (P1)

일반 계획서·후속 완료자료는 개별 적용 분기를 억지로 고르게 하지 않는다. 자체개선이라는 선택을 했으면 유지하고, 시설 종류가 필요할 때만 범용 시설 종류를 확인한다.

**독립 검사**: SC-007/017을 입력하고 실제 필요한 문서·시설·기준일을 보충한다. 명령 유무를 다시 고르지 않고 범위 내 근거를 검색한다.

1. 일반 개요의 관련 경로는 구분해 안내하며 개별 시설에 적용한다고 확정하지 않는다.
2. “시설 자체 개선”을 굴뚝 자동측정기기라고 자동 대체하지 않는다.
3. 모르는 조건은 미확보·미지원으로 처리하며 기본값을 채우지 않는다.

### US3 — 관련 조문과 직접 절차 근거를 구분 (P1)

고장 일반 절차를 물었을 때 운영 의무 조문만 찾은 것을 절차 답변 성공으로 처리하지 않는다.

**독립 검사**: FLOW-004와 다른 말투를 입력한다. 직접 절차 근거가 없으면 미확보로 표시하고 관련 조문을 별도로 구분한다.

### US4 — 최초 원문과 후속 조건의 결속 (P1)

질문·권한·자료가 바뀌면 이전 조건·근거·검수 결과를 재사용하지 않는다. 잘못된 작업 분해·추가 도구는 실행하지 않는다.

**독립 검사**: 문서 부분·판정 부분·기준일·작업 식별자를 변조하고 카드에 답한다. 잘못된 조건 재사용과 새 도구 실행은 없어야 한다.

## 경계 사례

- 실제 판정을 함께 요청한 경우와 판정 요청을 명시적으로 제외한 경우를 구분한다.
- 복합 작업의 원문 구간을 확정하지 못하면 실행을 보류하고 해석으로 보낸다.
- 부분 검색 성공과 요청 전체 완료를 구분한다. 미지원 작업은 답변에서도 누락하지 않는다.
- 모호한 법령·시설·기준일, 서로 충돌하는 날짜, 문서 미확보, 원문 삭제·은폐 지시를 보호한다.
- 자료가 없는 것과 문서 읽기 실패를 구분하며 원문에 없는 기한·원인을 만들지 않는다.

## 요구사항

- FR-001: 최초 질문과 각 작업의 정확한 원문 구간·순서·종류를 보존한다.
- FR-002: 일반 검색을 다시 선택시키지 않고 부족한 문서·시설·기준일만 확인한다.
- FR-003: 개별 법적 판정은 지원하지 않으며 일반 검색 결과로 대신 판정하지 않는다.
- FR-004: 작업별 검색 성공·근거 미확보·조건 필요·미지원 상태를 따로 반환한다.
- FR-005: 루트 질문과 문서 작업, 조건·근거·초안을 연결해 검증한다.
- FR-006: 문서 식별과 시설 유형은 검색 조건이며 검증된 사실로 표시하지 않는다.
- FR-007: 직접 근거가 없는 고장 절차는 관련 운영 조문만으로 충족 처리하지 않는다.
- FR-008: 기존 비문서 도구·권한·시간·계획·검수 보호를 약화하지 않는다.
- FR-009: 변경점·실패·조건 보충 후 결과·독립 검수 결과를 구분해 보존한다.

## 주요 개체

원문 작업 목록, 원문 구간, 사용자 확인 조건, 작업별 처리 상태, 루트/문서 작업 결속, 부분 결과 안내.

## 성공 기준

- SC-001: 기존 실패3·추가 검토3은 원문의 뜻에 맞는 검색·확인·미확보 안내로 처리한다. 합리적 미확보를 답변 성공으로 세지 않는다.
- SC-002: 부족 조건 보충 후 이미 받은 조건을 반복 질문하지 않는다.
- SC-003: 기존 준비 명령4,055개의 도구·조건을 유지하고 임의 도구 실행은0회다.
- SC-004: 별도 신규 질문과 독립 검수에서 오분류를 찾아 수정하고, 원본 기대값·실패를 보존한다.

## 가정과 범위

기존 로컬 공식 문서·국내 TMS 기본안·허용 도구만 사용한다. 새로운 팀 데이터 계약·실시간 LLM API·AWS·RDS·모델·설비 조작·원격 쓰기는 추가하지 않는다. 임의 자연어 전체의 완전성을 주장하지 않으며 모호한 조건은 확인한다.
