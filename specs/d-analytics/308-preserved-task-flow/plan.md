# 구현 계획: 원문 작업 분리와 연속 조건 확인

날짜: 2026-11-16 · [명세](spec.md) · 브랜치 변경 없음

## 요약

root 원문과 정확한 부분 구간에 결속된 작업 목록을 만들어, 문서 검색과 미지원 개별 판정을 구분한다. 명확한 요청을 한 도구로 줄이는 기존 흐름을 대신한다. 일반 개요·자체개선의 최소 조건도 같은 로컬 작업 세션에서 확인한다.

## 기술 맥락

- JavaScript CommonJS, 기존 Node26 작업대/브라우저 번들, Python3.12 Kiwi 환경 유지. 외부 의존성 추가 없음.
- `query-router/task-flow.js`에 작업 추출·입력 조건·root/child 결속·상태를 둔다.
- `rag-pipeline.js`는 기존 분류 보호를 먼저 적용한 뒤 명확한 작업 목록만 연결한다. 문서 작업의 원문으로 기존 검색기를 호출하고 root 상태에 미지원 작업을 유지한다.
- `answer-contract.js`는 문서 child와 root manifest를 함께 검증하고 미지원 안내를 전달 결과에서 생략하지 않는다.
- 저장은 기존 로컬 JSON·JSONL, 검증은 node:test·실제 Kiwi·브라우저·Luna 하위 에이전트 재생. 실시간 모델/SQL/원격 쓰기 없음.
- 범위: root 최대1000자, 도구6종/기존 계획 보호 유지, 문서 task1개와 미지원 task1개가 명확한 조합부터 적용. 모르는 분해는 기존 해석 경로로 보류한다.
- 비용 영향: 로컬 검사만 수행, 외부 사용료 없음. 조건 보충은 기존5분 만료와 권한·자료 지문을 유지한다.

## 원칙 점검

수집 코드·스케줄·원본·팀 Silver 계약은 변경하지 않는다. 비밀값 저장·출력·AWS 변경 없음. 문서·판정 상태와 원문·인용을 추적한다. 기존 질문·기대·검수 실패를 보존한다. 설계 전후 모두 원칙 위반 없음.

## 프로젝트 구조

명세·계획·연구·데이터모델·계약·재현·작업 목록은 이 폴더. 소스는 `D/dashboard-preview/regional-console/query-router/`, 테스트는 `tests/query-router/`, 번들은 `D/query-router-lab/build-workbench.cjs`. 검증·백업·변경 기록은 `D/query-router-lab/task-flow-20261116/`.

## 구현 순서

조건 보강: `request-readiness.js`는 원문에서 확인해야 할 의미를 정의하고, `tool-workflow.js`의 공통 검증기가 인자 누락과 함께 검사한다. `tool-session.js`는 카드로 확인한 의미를 후보 인자와 별도로 보존한다. 모델 후보에 확인값을 실어 우회할 수 없고, 후보 변경·확인 버튼·카드 입력 뒤에도 검사한다. 새 도구를 추가하지 않으며 미지원 정의는 안내로 끝낸다. 원문과 사용자 카드 선택을 보존한 검사 요약을 작업대에 표시한다.

작업 원문·결속과 누락 조건 검사를 먼저 고정한다. mixed 문서/판정 연결, general overview/self-improvement, 직접 고장절차 부족 판정을 순차 연결한다. 조건 답변 이후 결과와 기존 회귀를 검사하고 독립 검수에서 남은 사례를 반복 보강한다. 실제 실행기를 늘리지 않는다.
