# 로컬 작업 흐름 계약

원문은 변경하지 않는다. root와 문서 child를 구분해 두 결속을 매 검색·조건 입력·패킷·전달에서 검사한다. binding은 혼선 검사이며 인증 수단이 아니다.

- task 분해가 명확하고 기존 범위·권한·금지 작업 검사를 통과한 경우에만 적용한다.
- 지원 가능한 문서 작업은 실제 부족 조건만 받는다. case task는 항상 unsupported로 보존한다.
- 검색은 문서 task와 확인한 출처·기준일만 사용한다. case의 “지난 일요일”을 법령 기준일로 사용하지 않는다.
- generic 통지 예외는 어떤 신고·법령인지 확인한다. 사용자 입력을 공식 근거로 신뢰하지 않으며 로컬 문서만 검색한다.
- 명령이 미지정된 일반 개요는 분기별 참고 근거를 제시하고 개별 적용은 확정하지 않는다.
- 조건 값·작업 ID·원문 구간·질문·권한·자료 변경 시 기존 근거·검수 결과 재사용을 거부한다.
- 문서 미확보와 읽기 실패를 구분한다. 부분 결과의 미지원 안내는 최종 출력에도 필요하다.
- 범위 자체를 모른다고 답하면 불필요한 기준일을 더 묻지 않고 조건 미확정으로 인한 미지원을 안내한다. 이때 검색 실행은 false다.
- “따로 할게”라는 사용자 설명을 비교 요청으로 바꾸지 않는다. 비교 대상과 계획서/보고 단계는 원문 및 명시적 확인으로만 정한다.
- 휴일의 계획서 제출기간 제외 규정은 통지 의무 예외의 직접 근거로 사용하지 않는다. 직접 근거가 없으면 미확보다.
- 읽기 실패는 동일 검색 입력으로 최대 한 번 재시도한다. 보충한 시설·수령일 등의 조건도 유지하며 재시도 전에 세션 유효성을 다시 검사한다.
- 오래된 DOM의 카드 클릭·조건 폼 제출은 현재 요청을 바꾸지 못한다.
- 문서 요청의 `target.requiredTopics`는 기록 보존·점검 기록·공개 공란 같은 명시된 필수 주제를 보존한다. 복합 요청은 각 주제의 직접 근거가 있어야 하며 초안에서도 필수 근거 그룹을 빠뜨리지 못한다. 단일 절차의 관련 후보는 답변 가능한 직접 근거와 분리한다.
- `target.formComparison`은 비교할 서식 번호를 보존한다. 본문을 확보하지 못하면 다른 번호를 언급한 조문으로 비교하지 않는다.
- “개선명령 뒤 이행보고까지”는 명령 경로의 계획서·보고 두 단계를 보존한다. 실제 사고의 법정 기한 준수 확정은 범위 밖 질문이 아니라 판정 기능 미지원이다.
- 답변 패킷도 명령 경로의 계획·보고 필수 근거를 보존한다. 원문의 보고 표지 필터로 계획 근거를 제거하지 않는다.
- 카드에서 받은 시설 조건은 답변 패킷에서 `source=user_confirmed`, `origin=task_condition_card`로 표시한다. 검색용 자식 문장의 명시 조건을 최초 질문의 사실과 혼동하지 않는다. 답변 작성은 시간순 후속 확인을 반영한다.
- 검사 이력의 기재 항목과 관리기준 본문은 각각 직접 근거가 필요하다. 운영 일반 조문·별표 위임 조문을 본문 확보로 대체하지 않는다. `all_items`의 전체성 미검증 보호도 유지한다.
- 단일 도구의 원문 의미와 인자 완전성은 별도로 확인한다. 초과율·배출량·기간 요약이 모호하면 카드 선택이 필요하며 모델의 일반 해석 확인 버튼으로 대신 확정하지 않는다.
- 필터는 `metric`도 필요하다. 숫자 100만으로 기준대비율이라고 추정하지 않는다. 원문 물질·명시 지표와 다른 후보는 충돌로 보류한다.
- 미지원 의미를 선택하면 다른 지표로 실행하지 않고, 추가 입력을 불필요하게 요구하지 않는다. 새 요청·만료·권한 변경 후 의미 카드 선택을 재사용하지 않는다.
