# 기능 명세: 선택형 실제 로그인과 개인 즐겨찾기

**작성일**: 2026-11-16 · **담당**: D · **상태**: 구현 준비
**브랜치**: 새로 만들지 않음. 사용자가 관리한다.
**요청**: 관제 화면은 로그인 없이 열고 기존 로그인 진입점을 유지한다. 실제 인증은 기존 Cognito를 사용하며 외형 개선은 이후로 미룬다.

## 사용자 시나리오 및 검증

### US1 — 필요할 때 로그인 (P1)

방문자는 관제를 바로 보고, 개인 기능이 필요할 때 로그인한다.
**우선 이유**: 관제 탐색을 막지 않고 실제 사용자 계정을 연결해야 한다.
**독립 검증**: 비로그인 진입에서 지도·차트가 열리고 로그인 선택 시 인증 서비스로 이동하는지 확인한다.
1. 비로그인으로 접속하면 자동 로그인 이동 없이 관제가 표시된다.
2. 로그인 버튼을 누르면 인증 화면으로 이동하고 성공 후 관제로 돌아온다.
3. 인증 실패·취소 시 재시도를 선택할 수 있고 관제는 계속 사용할 수 있다.

### US2 — 로그인 사용자별 즐겨찾기 (P2)

로그인 사용자는 사업장을 즐겨찾기에 넣거나 삭제하고 다시 열 수 있다.
**우선 이유**: 실제 계정으로 개인 설정을 구분한다.
**독립 검증**: 사용자 A/B의 저장값이 섞이지 않고 비로그인 상태에서는 변경이 불가능한지 확인한다.
1. 비로그인 사용자가 즐겨찾기를 추가하려면 로그인을 안내한다.
2. 동일 브라우저의 동일 사용자로 다시 로그인하면 저장된 목록을 복원한다.
3. 다른 사용자로 바뀌거나 로그아웃하면 이전 사용자의 목록이 노출되지 않는다.
4. 서버 저장·외부 알림이 미연결임을 명시한다. 실제 발송은 제공하지 않는다.

### US3 — 로그아웃·만료 처리 (P2)

사용자는 로그아웃할 수 있으며 인증 만료 뒤 개인 설정을 변경할 수 없다.
**독립 검증**: 만료·갱신 실패·다른 탭 로그아웃 시 개인 상태를 해제하고 관제는 유지하는지 확인한다.

### 예외

- 인증 콜백의 상태값이 없거나 잘못되면 로그인을 인정하지 않는다.
- 저장소 차단 시 실패 안내를 표시하고 가짜 로그인으로 대체하지 않는다.
- 네트워크 실패·사용자 취소·콜백 재실행 시 자동 이동을 반복하지 않는다.
- 로컬 주소가 인증 서비스의 허용 목록에 없으면 실제 로그인은 완료할 수 없다.

## 요구사항

- FR01: 관제는 비로그인 상태에서도 사용할 수 있어야 한다.
- FR02: 담당자 A/B 선택형 임시 인증을 제거하고 실제 인증 서비스와 연결한다.
- FR03: 사용자 이름 또는 이메일, 로그아웃 기능을 제공한다.
- FR04: 즐겨찾기는 인증 사용자 식별자별로 저장하며 기존 임시 계정 데이터는 자동 이관하지 않는다.
- FR05: 계정 비밀번호를 관제에서 직접 받지 않고 인증 서비스 화면을 사용한다.
- FR06: 토큰·비밀번호를 로그·문서·공개 저장소에 기록하지 않는다.
- FR07: 인증 상태 변경에 따라 개인 기능을 갱신하며 만료된 계정으로 저장하지 않는다.
- FR08: 기존 지도 자동 등고선·NOx/SOx 차트·테마·질문창 기능을 유지한다.

## 주요 개체

- 인증 사용자: 안정적인 사용자 식별자, 화면 표시 이름, 유효성.
- 개인 설정: 사용자별 사업장 즐겨찾기 목록. 현재는 동일 브라우저 저장만 지원한다.

## 성공 기준

- SC01: 비로그인·로그인 성공·실패·취소·로그아웃·만료 시나리오가 모두 예상 흐름으로 처리된다.
- SC02: 두 사용자 사이 즐겨찾기 혼합·노출이 검증에서 0건이다.
- SC03: 비로그인 관제 주요 기능 검증 16항목을 유지한다.
- SC04: 검증 결과에서 실제 인증 시험과 대체 환경 시험을 구분한다.

## 의존성·가정

기존 Cognito 설정을 재사용한다. 신규 AWS 리소스·플랜 변경·서버 저장 API·외부 알림·S3 배포는 범위 밖이다. Cognito 콜백 허용 URL은 현재 IAM 권한으로 조회할 수 없어 배포 전 별도 확인한다.
