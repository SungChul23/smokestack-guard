# 기능 명세: 질문으로 사업장 지도 이동

**번호**: 306 · D · **작성일**: 2026-11-14 · **상태**: 사용자 승인 범위 구현  
**입력**: ‘사업장 이동 하나만 실제 프론트에 연결하고 성공을 확인한 뒤 안내’ 제안에 대한 사용자 승인. 물질 토글·기간 변경·조회·일반 복합 실행은 이번 범위에서 제외한다.

## 사용자 시나리오와 검증

### US1 — 정확한 이름·코드로 이동 (P1)

사용자가 관제 질문창에서 사업장 위치를 묻거나 이동을 요청하면 해당 사업장을 선택하고 지도에 표시한다.

독립 검증: 현재 다른 지역·검색어·상태 필터가 선택돼 있어도 대상이 바뀌지 않으며 표시 확인 후에만 성공을 안내한다.

1. 유일한 전체 이름/코드 요청은 대상 확인 후 지도·목록·상세를 같은 사업장으로 맞춘다.
2. 이미 보이는 사업장을 반복 요청해도 잘못 실패하거나 불필요하게 재이동하지 않는다.
3. 검색어/상태 필터를 풀어야 표시되면 필요한 변경만 하고 변경 사실을 안내한다.

### US2 — 불확실한 대상은 선택 (P1)

부분 이름·동명은 후보 선택 후에만 이동한다. 후보는 등록 명단에 있는 사업장만 사용한다.

독립 검증: 후보 버튼을 누르기 전 지도 상태 불변, 명단/질문 변경·오래된 후보·취소·창 닫기 이후에는 후보가 실행되지 않는다.

### US3 — 성공·실패·기존 기능 구분 (P2)

지도 표시 확인 실패를 성공으로 안내하지 않는다. 기존 법령 검색과 명시적 초과 이력 조회는 유지한다.

독립 검증: 지도 함수 오류·표시 확인 시간초과·새 질문·수동 선택 변경을 검사한다. 입력 취소는 이미 적용된 지도 이동을 되돌렸다는 의미가 아니다.

## 요구사항

- FR-001: 이번 실행은 등록 사업장 선택/지도 이동 1종만 허용한다. 임의 화면 함수·코드·다른 도구를 실행하지 않는다.
- FR-002: 질문은 기존 공통 분류·조건 검증을 재사용하고, 유일한 정확한 이름/코드 또는 명시적 후보 선택이 있어야 실행한다.
- FR-003: 실행 직전에 등록 대상·위치 표시 가능 여부·지도 준비 상태를 재확인하고, 실제 선택 상태와 지도 표시를 확인한 뒤 성공을 안내한다.
- FR-004: 요청·후보는 5분 후 만료되며 질문·명단 변경·새 요청·취소로 이전 실행/안내가 현재 요청을 덮어쓰지 못한다.
- FR-005: 상태·검색 필터는 대상 표시를 방해할 때만 완화하고 안내한다. 측정 자료·판정 기준·지도 시각·차트 기간은 변경하지 않는다.
- FR-006: 오류 전 미실행과 적용 후 표시 확인 실패를 구분한다. 개별 굴뚝의 정확한 위치를 표시했다고 주장하지 않는다.
- FR-007: 기존 관제 질문창의 법령·초과 조회와 키보드·모바일 동작을 유지한다. 일반 분기 실험실은 실행하지 않는 상태를 유지한다.
- FR-008: 실제 모델·DB·새 외부 API·자격증명 사용·수집기 변경은 없다.

### 핵심 정보

사업장 명단, 지도 이동 명령, 질문/후보 식별자, 필터 변경 내역, 적용한 사업장, 지도 표시 확인 결과.

## 성공 기준

- SC-001: 고정 이름·코드 표본의 실제 선택 사업장과 표시 대상이 모두 기대와 일치한다.
- SC-002: 후보 미선택·미등록·오래된 요청·금지/비대상 질문의 지도 실행은 0회다.
- SC-003: 오류·시간초과·새 요청 표본에서 잘못된 성공 안내는 0회다.
- SC-004: 기존 법령·초과 조회와 지도/차트/시간 보존 검사를 통과한다.

## 전제와 범위

현재 공개 로컬 사업장 명단과 기존 지도 함수를 사용한다. 네이버/관제 공통 지도 인터페이스를 재사용하되 외부 SDK 실제 접속 시험은 별도 권한 사용 없이 강제하지 않는다. 일반 자유문장의 서버 형태소/LLM 연결은 별도이며, 이번 명확한 이름/코드 요청은 브라우저의 등록 명단·규칙으로 처리한다. 운영 사용자 권한/서버 계약을 만든 것이 아니다.
