# 사업장 인식 설계와 측정 (구현: `services/dashboard-agent/app/agent/names.py`)

질문 속 사업장·굴뚝을 사람이 말하듯 줄여 써도 안전하게 찾는 방법이다. 결정 D1(형태소 미사용)·K8(재입력)의 근거 문서다. 관련: [314 contracts-draft](../314-front-interpretation-decisions/contracts-draft.md)

## 1. 왜 형태소 분석기를 쓰지 않나

- 사업장 이름은 고유명사라 쪼개지지 않는다(포스코퓨처엠, 삼성디스플레이 등). 쪼개지 못하면 이름 인식에 도움이 없다.
- 형태소 정보를 LLM 입력에 같이 줘도 정확도가 오르지 않았다(94.0% → 93.5%).
- 에이전트 서버는 형태소 없이 정규식 + 인식기로 충분하다(아래 측정). 옛 Kiwi 라우터는 비교용으로만 남긴다(`D/query-router-lab/`, git 제외).

## 2. 순서와 단계 (지역 → 사업장 → 굴뚝)

1. **정규화:** 유니코드 정규화, 소문자, `주식회사/(주)/㈜` 제거, 공백·기호 제거, 영문 약어의 한글 읽기(SK→에스케이, KCC→케이씨씨), 자주 쓰는 줄임말.
2. **지역 말:** 시·도(표기 무관)와 시·군·구를 읽어 후보를 좁힌다. 후보가 0이 되면 지역은 무시한다.
3. **정확 일치가 먼저:** 질문 속에서 사업장 이름이 그대로 들어 있으면 가장 긴 이름을 고른다. 같은 이름이 여러 사업장이면 지역으로 가르고, 안 되면 카드(`COLLISION`)로 묻는다.
4. **글자 검색(퍼지):** 조각만 말한 경우. 덮는 비율·1위와 2위의 차이·이름 덮는 비율이 모두 기준을 넘을 때만 자동 선택한다. 아니면 후보 카드(최대 3개), 후보가 없으면 `NONE`.
5. **굴뚝 번호:** 사업장이 정해진 뒤에 읽는다. 이름 속 숫자(울산1공장)는 굴뚝 번호가 아니다. 번호는 "굴뚝 N / N번 굴뚝 / N번 / N호기"이거나, 그 사업장의 실제 굴뚝 번호와 같은 단독 숫자일 때만 쓴다. 이름 뒤 숫자가 두 가지로 읽히면(`서해그린에너지 2`) 카드(`NUMBER_AMBIGUOUS`)로 묻는다.

기준값(`names.py`): `AUTO_COVERAGE 0.75`, `AUTO_MARGIN 0.30`, `AUTO_NAME_COVERAGE 0.70`, `MIN_COVERAGE 0.25`, `MAX_CARD 3`. 분석에서는 0.75/0.5/0.5도 나왔다. 바꾸려면 아래 정답 세트로 다시 재고 정한다.

## 3. 해석 분담 (D1)

```
원문 → 가드 → 정규식(확실한 칸만)
  ├ 필요한 칸이 모두 확실 → LLM 없이 진행
  └ 빈 칸·충돌 → 원문 전체를 LLM 해석기로 → 코드가 값 검증
정규식과 LLM이 다르면 → 카드로 묻는다
사업장 선택은 항상 인식기가 한다(LLM은 "말한 이름"만 뽑는다)
```

합성 해석기는 `app/agent/hybrid.py`에 구현했고(가짜 LLM으로 시험), 서버 조립(`api.py`)에는 아직 연결하지 않았다(현재 서버는 정규식만). 합치기 규칙: 정규식이 비운 칸만 LLM 값(검증 통과 시)으로 채운다 / 값이 서로 다르면 비운다(카드) / 정규식이 일반 조회(aggregate)로 읽은 유형은 유지하고 순위·결측·기준시각 유형이 LLM과 다르면 지원하지 않음으로 둔다 / LLM이 말한 사업장 이름은 원문에 실제로 있을 때만 쓴다 / LLM 호출이 실패하면 정규식 결과를 쓴다.

### 실제 Haiku 시험 (2026-11-18, `global.anthropic.claude-haiku-4-5-20251001-v1:0`, 901건)

Haiku 5.5는 이 계정에서 쓸 수 없다(AccessDenied). 모델 ID는 하드코딩하지 않고 설정으로 둔다.

| 항목 | 정규식만 | Haiku만 | 합성(안전 합치기) |
|---|---|---|---|
| 시간 | 98.4% (틀린 값 1) | 99.2% (0) | **99.5% (0)** |
| 물질 | 98.9% (1) | 100.0% (0) | **99.9% (0)** |
| 집계 | 95.9% (0) | 99.7% (0) | **99.7% (0)** |
| 유형 | 99.2% (0) | 97.4% (**8**) | **99.4% (0)** |

- Haiku만 쓰면 유형을 8번 틀린 값으로 냈다(굴뚝 없이 "NOx 최대"를 순위로 읽는 등). 합성은 틀린 값이 0이고 못 읽은 것은 카드로 간다.
- **호출 줄이기:** "빈 칸이 있으면 호출"은 577/901건(64%)을 불렀지만 실제로 필요한 호출은 약 120건(13%)이었다. 빈 물질·기간·집계는 대부분 사용자가 말하지 않은 것이라 카드가 묻는다. 그래서 **유형이나 굴뚝 말을 못 읽었을 때만** 부르도록 바꿨다 → 190건(21%), 필요했던 호출 120건 중 22건은 놓쳐 카드로 간다. 합성 정확도(최종): 시간 98.8%, 물질 98.9%, 집계 98.4%, 유형 99.4%, 틀린 값 시간 1·물질 1(모두 정규식 쪽). 추가로 프런트가 `selectedStackId`를 보내면 굴뚝 칸은 이미 찬 것이라 호출이 더 준다(미반영).
- **저가 모델(Amazon Nova Lite, `apac.amazon.nova-lite-v1:0`):** 같은 901건에서 원본 출력만 보면 시간 55%(틀린 값 257건, 기간 종류를 빠뜨림), 지어낸 사업장명·잘못된 굴뚝 번호가 나왔다. 검증을 거친 합성에서는 시간 98.9%·유형 99.7%지만 물질 틀린 값이 4건 남아 Haiku(0건)보다 안전하지 않다. 호출 16건은 오류(제한). 지금은 채택하지 않는다.
- 사업장 자동 선택은 합성 후 392/773 맞음, 틀림 3(위의 같은 이름 3건).
- 시험 스크립트: `D/morph-router-20261117/redteam/haiku_live.py`(git 제외), 결과 저장: `slot-eval-20261118/haiku-raw.jsonl`.

## 5. 알려진 한계

- "지금·현재"는 인식하지만 아직 지원하지 않는 기간이라 안내만 한다.
- 초성 줄임말("ㅈㄱ", "오들", "어젠")은 정규식이 못 읽는다 → LLM 해석기 몫.
- 같은 이름의 다른 사업부(포스코퓨처엠)·지역을 붙여도 같은 이름(엔아이티)은 자동 선택이 틀릴 수 있다(3건). 정답 세트에서 확인한 전부다.
- 사업장 카드는 3곳, 굴뚝 카드는 번호 8개까지만 보인다.
- 데이터 쪽 사정은 별개다: 한국주강처럼 같은 키에 값이 엇갈리는 경우는 Silver에서만 가를 수 있다(먼지 항목이라 현재 범위 밖).
