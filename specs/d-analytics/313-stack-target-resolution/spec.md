# 기능 명세: 굴뚝 대상 해석과 후보 확인

**기능 번호**: 313 · **담당**: D 분석·화면·RAG
**작성일**: 2026-11-18(KST) · **상태**: 초안 — 사용자 검토 대기, 열린 결정 3건(아래 "열린 결정")
**브랜치**: 만들지 않았다. 사람이 관리한다. 구현 전이며 코드·설정·인프라를 바꾸지 않았다.
**입력**: 2026-11-18 사용자 대화와 그날의 측정(근거는 [research.md](research.md))

## 이 기능이 필요한 이유

사람은 정확한 사업장 이름·주소·굴뚝 번호를 주지 않는다. 카탈로그 굴뚝 3,480개(사업장 905곳) 가운데 약 75%의 이름이 `㈜`를 포함하는데, 사용자는 법인 표기를 거의 쓰지 않고 "포항 2번", "한국지엠 15"처럼 줄여 말한다. 같은 환경에서 LLM이 만든 질문 740건 중 31%(325건)가 약칭이었고, 실제 사용자는 더 흐릿하게 말할 가능성이 크다. 대상을 틀리면 "틀린 굴뚝의 숫자"가 근거와 함께 나가므로, 이 기능은 틀린 자동 선택을 0으로 두고 애매하면 묻는 것을 첫 번째 원칙으로 한다.

## 사용자가 이미 정한 것 (2026-11-18)

1. 입력은 보통 `㈜`·`()` 같은 기호를 쓰지 않는다고 본다. 법인 표기가 **없어도 매칭**하고, 모호하면 **지역을 물어보는 것**으로 방어한다.
2. 후보 카드는 최악을 가정해 설계한다. 약칭 질문의 약 10%는 후보 3곳 안에 정답이 없어 "이 중에 없음" 경로로 간다.
3. 후보 카드에는 "이 중에 없나요?" 선택지를 둔다.
4. **굴뚝을 부르는 방식은 단계로 나눈다(2026-11-18 사용자).** 위 단계에서 하나로 정해지면 그 굴뚝에 붙이고, 정해지지 않으면 카드로 묻는다.
   1. 식별자(id)로 부른다.
   2. 100% 정확한 이름으로 부른다.
   3. `(주)`·`㈜` 같은 표기 없이 부른다.
   4. 사업체의 지역 이름만 잘라서 부른다. 잘라도 **유일한 검색 결과**로 나오면 그쪽에 붙이고, 아니면 카드로 묻는다.
   - 열린 점: 1~3단계는 정확 일치라 점수가 필요 없고, 4단계의 "유일"을 어떻게 판정할지(후보가 하나뿐일 때만 vs 점수 차 임계값)는 정하지 않았다. 지금 FR-005는 점수 차 임계값(2.5)을 쓴다. 단계 구조로 FR-005를 다시 쓸지 사용자와 정한다.

## 사용자 시나리오와 검증

### US1 — 대충 말한 굴뚝을 자동 선택하거나 후보로 확인한다 (P1)

사용자는 "포항 2번 NOx 어제 평균"처럼 이름·지역·번호를 줄여서 묻는다. 시스템은 확실할 때만 확인 없이 진행하고, 애매하면 후보 카드로 묻는다.

**우선 이유**: 대상 오류는 숫자 오답으로 이어지는 가장 큰 위험이다.
**독립 검증**: 약칭 질문 325건과 정식 이름 질문 415건 세트(번호 있음)로 자동 선택 오류, 후보 3위 안 비율, 카드 비율을 잰다.

1. **조건** 질문의 이름+번호가 한 굴뚝으로 충분히 정해진다(점수 차 임계값 이상, 충돌 이름 아님), **행동** 질문 제출, **결과** 확인 없이 그 굴뚝으로 진행하고 어떤 굴뚝을 썼는지 표시한다.
2. **조건** 점수 차가 작거나 충돌 이름이다, **행동** 질문 제출, **결과** 후보 최대 3곳과 "이 중에 없음"을 카드로 보여 준다. 선택하면 진행한다.
3. **조건** 사용자가 "이 중에 없음"을 고른다, **행동** 선택, **결과** 지역(시·도 또는 시·군)을 묻고 그 지역 후보로 한 번 다시 찾는다. 그래도 못 정하면 지도에서 선택하거나 다시 입력하도록 안내한다. 같은 카드를 반복하지 않는다.

### US2 — 화면 선택·직전 조회가 말보다 먼저 후보로 쓰인다 (P1)

사용자가 지도에서 굴뚝을 선택했거나 직전에 조회한 굴뚝이 있으면 질문에 굴뚝 말이 없어도 그것을 쓴다. 모든 굴뚝은 누구나 조회할 수 있으므로 선택은 후보를 제한하지 않고 우선순위만 준다.

**독립 검증**: 선택 맥락 유무, 질문이 다른 굴뚝을 명시하는 경우로 후보 목록을 비교한다.

1. **조건** 화면에서 굴뚝 A를 선택, **행동** "이 굴뚝 NOx 얼마야?", **결과** A를 쓴다.
2. **조건** A 선택, **행동** 질문에 식별 가능한 B를 명시, **결과** B가 우선이고 사용한 대상을 표시한다. (303 US1과 같은 규칙)
3. **조건** 화면에서 굴뚝 A를 선택한 채 질문이 굴뚝 B를 명시, **행동** 질문 처리, **결과** 질문에 적힌 B를 우선한다(선택 맥락은 질문에 굴뚝 말이 없을 때 쓴다).

### US3 — 번호를 모르는 사용자 (P2)

사업장은 말했지만 굴뚝 번호가 없으면 그 사업장의 굴뚝 번호 목록을 보여 주고 고르게 한다. (결정 Q2)

**독립 검증**: 번호 없는 질문 세트에서 사업장 후보→번호 선택까지의 단계 수와 해소율을 잰다.

### US4 — 선택한 후보를 기억한다 (P2)

사용자가 카드에서 고른 선택을 별칭으로 저장해, 다음에 같은 표현이 오면 자동 선택 조건을 통과하는 경우 바로 연결한다. (결정 Q1)

**독립 검증**: 같은 표현을 두 번 보내 첫 번째는 카드, 두 번째는 확인 없는 연결이 되는지, 충돌 이름은 두 번째에도 카드인지 확인한다.

### US5 — 의미 유사도 서비스가 없어도 동작한다 (P3)

임베딩 호출이 실패하거나 느리면 글자 검색만으로 결과를 내고 사용자에게 오류를 노출하지 않는다.

**독립 검증**: 임베딩을 차단한 상태에서 약칭 세트의 3위 안 비율이 SC-007 이상인지 확인한다.

## 경계 사례

- 이름이 같고 법인 표기만 다른 사업장(크나우프석고보드 `㈜`/`(주)`, 한국제지 `㈜`/`(주)`), 이름 하나가 사이트 여러 곳에 걸친 사업장 4곳(동서식품㈜, ㈜금비, 한국주강㈜ 등) → 항상 카드.
- 하위 사업장을 괄호로만 구분하는 이름(`엘지화학 여수공장(용성1단지)` · `(용성2단지)` · `(화치)`) → 검색 이름에는 괄호 안을 넣지 않고, 카드 표시와 주소 색인에만 둔다. 이 이름은 항상 카드.
- 상호 앞부분이 같은 사업장이 많은 묶음(에스케이 16곳, 한국지역난방 15곳, 리뉴에너지 11곳 등) → 번호와 지역으로 좁힌다.
- 영문·한글 표기(SK↔에스케이, LG↔엘지, GS↔지에스), 초성(ㄱㄷ), 오타, 한글 숫자("굴뚝 일 번", "열두 번"), 붙여 쓴 입력("전주페이퍼굴뚝3").
- 번호만 있고 이름이 없는 입력("3번 굴뚝").
- 별명·애칭("포철", "우리 공장", "저번에 본 굴뚝") → 후보가 없으면 카드의 "이 중에 없음" 경로로 간다.
- 임베딩이 그럴듯하지만 틀린 후보를 높은 점수로 내는 경우 → 자동 선택은 점수 차 조건과 충돌 이름 제외를 통과해야 한다.

## 요구사항

- **FR-001** 질문에서 굴뚝 언급(사업장 말, 지역 말, 번호)을 뽑아 후보 순위를 만든다. 법인 표기·공백·부호의 유무는 점수에 영향을 주지 않는다.
- **FR-002** 후보 풀은 전체 굴뚝이다(모든 굴뚝은 누구나 조회할 수 있다). (1) 굴뚝 번호가 질문에 있으면 번호로 줄이고, (2) 화면 선택·직전 조회·즐겨찾기는 우선순위로만 쓴다.
- **FR-003** 기본 검색은 사업장 이름·주소·지역을 색인한 글자 검색이다. 영문·한글 음차 변환표, 초성 매칭, 한글 숫자 정규화를 적용한다.
- **FR-004** 의미 유사도(임베딩)는 글자 점수와 합치는 보조 점수로만 쓴다. 단독 판단에 쓰지 않는다. (결정 Q3)
- **FR-005** 결과는 자동 선택 · 후보 카드 · 후보 없음 중 하나다. 자동 선택은 (a) 1·2위 점수 차가 임계값 이상, (b) 충돌 이름이 아님, 두 조건을 모두 만족할 때만 한다.
- **FR-006** 충돌 이름은 점수와 무관하게 자동 선택하지 않는다. 충돌 이름은 색인 생성 시 미리 표시한다.
- **FR-007** 후보 카드는 최대 3곳과 "이 중에 없음"을 가진다. 후보는 원래 이름(법인 표기·괄호 포함), 시·군, 주소 일부로 표시한다. 카드 문구와 선택지는 코드가 정하고 모델이 쓰지 않는다.
- **FR-008** "이 중에 없음" 뒤에는 지역을 묻고 그 지역 후보로 한 번 다시 찾는다. 그래도 못 정하면 지도에서 선택하거나 다시 입력하도록 안내한다.
- **FR-009** 사업장은 정해졌으나 번호가 없으면 그 사업장의 굴뚝 번호 목록으로 고르게 한다.
- **FR-010** 화면에서 선택한 굴뚝·직전 완료 조회가 있고 질문이 굴뚝을 말하지 않으면 그것을 쓴다. 질문이 다른 굴뚝을 명시하면 질문이 우선한다. 선택 값은 화면에서 서버가 신뢰하는 경로로 전달된 것만 인정한다.
- **FR-011** 카드에서 확인된 선택은 별칭(질문 표현 → 굴뚝)으로 기록한다. 별칭도 FR-005의 자동 선택 조건을 통과해야 쓴다. 저장 범위와 공유 승격 조건은 결정 Q1이 정한다.
- **FR-012** 임베딩 서비스가 실패하거나 응답 시간 상한을 넘으면 글자 검색만으로 진행하고 사용자에게 오류를 노출하지 않는다. 실패는 기록에 남긴다.
- **FR-013** (삭제) 접근 권한 개념이 없다. 2026-11-18 사용자 정정: 모든 굴뚝은 누구나 조회할 수 있다. 번호는 그대로 둔다.
- **FR-014** 해석 시도마다 입력 맥락, 후보 순위와 점수, 점수 차, 선택 경로(자동/카드/지역 질문/지도)를 요청 기록에 남긴다.
- **FR-015** 모델(LLM)은 굴뚝 식별자를 만들지 않는다. 후보 식별자는 검색기가 낸 것만 쓰고, 모델이 낸 사업장 표기는 검색 입력으로만 쓴다.
- **FR-016** 검색 색인은 공식 사업장·굴뚝 키(C가 정하는 중)에서 재생성할 수 있어야 하며, 키가 바뀌어도 이 기능의 규칙은 바뀌지 않는다.

## 주요 개체

굴뚝 후보(굴뚝 식별자, 사업장 원표기, 정리 이름, 시·도·시·군·주소, 번호 집합, 충돌 표시), 해석 시도(질문, 입력 맥락, 후보 순위·점수, 결과 종류, 선택 경로), 별칭(표현 정리값, 굴뚝 식별자, 범위, 확인 시각, 확인 횟수), 색인 문서. 자세한 필드는 [data-model.md](data-model.md), 입출력은 [contracts/stack-resolution.md](contracts/stack-resolution.md).

## 성공 기준

2026-11-18 측정치를 기준선으로 한다(측정 방법과 한계는 [research.md](research.md)). 시험 세트는 LLM이 만든 약칭·정식 이름 질문 740건(번호 있음)이며, 실제 사용자 표현으로 다시 보정하기 전까지는 상한에 가깝다.

- **SC-001** 자동 선택된 결과 중 틀린 굴뚝 0%. (기준선: 약칭 세트 자동 선택 213건 중 0건)
- **SC-002** 약칭 질문에서 정답 사업장이 후보 3위 안에 드는 비율 ≥ 90%. (기준선 90.5%)
- **SC-003** 정식 이름 질문에서 정답이 1위인 비율 ≥ 99%. (기준선 99.0%)
- **SC-004** 약칭 질문에서 후보 카드를 보게 되는 비율 ≤ 35%, "이 중에 없음" 경로 ≤ 10%. (기준선 34.5%, 9.5%)
- **SC-005** "이 중에 없음" 경로의 질문 가운데 지역(시·군)을 알려 준 뒤 3위 안에 드는 비율 ≥ 50%. (기준선 51.5%)
- **SC-006** 충돌 이름의 자동 선택 0건.
- **SC-007** 임베딩이 없을 때 약칭 질문의 3위 안 비율 ≥ 87%. (글자 검색 기준선 88.0%)
- **SC-008** (삭제) FR-013 삭제에 따른다.

## 가정

- 카탈로그는 사업장 905곳, 굴뚝 3,480개(2026-11-12 스냅샷) 기준이다. 공식 키는 담당 C가 정하는 중이다.
- 기준선 세트는 굴뚝 번호가 있는 질문만 포함한다. 번호가 없는 질문의 수치는 낮아질 수 있어 US3에서 따로 잰다.
- 화면에서 선택한 굴뚝을 에이전트 요청에 싣는 경로는 아직 없다(서버는 맥락에 전체 굴뚝 목록만 넘긴다. 이 목록은 접근 제한이 아니라 서버가 아는 전체 굴뚝이다). 이 연결은 이 기능의 선행 의존이며 spec 306·311·314에서 다룬다.
- 임베딩은 서울 리전 Titan 텍스트 임베딩 v2를 2026-11-18에 확인했다(1024차원, 약 0.5초). 다른 임베딩 모델은 서울에서 쓸 수 없었다.

## 열린 결정
