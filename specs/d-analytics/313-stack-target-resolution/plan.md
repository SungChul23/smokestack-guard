# 구현 계획: 굴뚝 대상 해석

**기능**: 313 · **날짜**: 2026-11-18 · **명세**: [spec.md](spec.md) · **상태**: 초안 — 열린 결정 Q1~Q3와 [314](../314-front-interpretation-decisions/spec.md)의 D3(구현 위치)이 정해지기 전에는 구현하지 않는다.

## 요약

굴뚝 말을 후보 순위로 바꾸는 검색 모듈을 만든다. 모든 굴뚝은 누구나 조회할 수 있으므로 전체 굴뚝에서 시작해 굴뚝 번호가 있으면 번호로 후보를 줄이고, 화면 선택·즐겨찾기는 우선순위로만 쓰며, 글자 검색(이름·주소 2-gram, 음차 변환표, 초성, 한글 숫자)에 임베딩 점수를 보조로 합친다. 결과는 자동 선택·후보 카드·없음 중 하나이며, 충돌 이름은 항상 카드로 보낸다. 카드 선택은 별칭으로 기록한다. 모델은 굴뚝 식별자를 만들지 않는다. 오늘 만든 측정용 프로토타입(`entity_search.py` 등)을 기준선 시험으로 삼고, 운영 코드는 새로 쓴다.

## 기술 문맥

| 항목 | 선택과 이유 |
|---|---|
| 언어 | Python. 에이전트 서버·형태소 라우터가 Python이다([314](../314-front-interpretation-decisions/spec.md) D3이 확정하기 전 가정). 기존 JS 라우터(303~312)에 넣으려면 같은 계약으로 이식한다 |
| 색인 | 메모리. 사업장 905곳·굴뚝 3,480개라 별도 DB가 필요 없다. 시작 시 카탈로그에서 만들고 충돌 표시를 함께 계산한다 |
| 임베딩 | Bedrock Titan 텍스트 임베딩 v2(서울, 1024차원). 사업장 문서 임베딩은 카탈로그 버전별로 한 번 만들어 캐시한다. 질문 임베딩은 요청마다 1회(약 0.5초) |
| 외부 패키지 | numpy(코사인 계산)와 boto3(이미 쓰는 것). numpy가 이유다: 905×1024 행렬 곱을 표준 라이브러리로 하면 느리고 번거롭다. 임베딩 기능을 끄면 numpy 없이도 글자 검색만 동작해야 한다(FR-012) |
| 저장 | 별칭·해석 기록은 요청 기록과 같은 저장소(관측 로그 위치는 314 D13). 새 AWS 리소스는 이 기능만으로는 필요 없다 |
| 성능 목표 | 글자 검색 20ms 이내(색인 메모리), 임베딩 포함 700ms 이내(호출 상한 1초, 초과 시 degrade) — 초안 |
| 시험 | 오늘의 세트(`slot-eval-20261118/`, 약칭 325·정식 이름 415)를 회귀 세트로 고정하고, 임계값·변환표를 바꿀 때마다 SC-001~008을 다시 잰다 |

## 원칙 점검 (constitution 0.1.0)

| 원칙 | 판단 |
|---|---|
| I 수집 연속성 | 해당 없음. 수집·원본을 건드리지 않는다. |
| II 비밀값 | 새 비밀값 없음. Bedrock 호출은 기존 역할로 하고 키를 코드에 쓰지 않는다. 별칭·기록에 개인 이메일을 넣지 않고 사용자 식별자만 쓴다. |
| III Terraform·적용은 사람이 | 이 기능만으로 새 리소스가 없다. 임베딩 호출 권한이 필요하면 최소 범위(`bedrock:InvokeModel`을 Titan v2 모델 ARN으로 한정)로 A에게 요청한다. 에이전트는 plan까지만 한다. |
| IV 데이터 계약 우선 | 공식 사업장·굴뚝 키는 C가 정한다. 키가 확정되면 색인 필드를 맞추고, 그 전에는 로컬 키를 쓴다고 계약에 적는다. 이 기능은 계약에 없는 필드를 읽지 않는다. |
| V 같은 조건의 정직한 비교 | 검색 방식 비교는 같은 세트·같은 후보 풀·같은 지표로 한다. 세트의 한계(LLM이 만든 질문, 번호 있음)를 명세에 적었다. |
| VI 설명 가능한 결과 | 해석 시도마다 후보 순위·점수·선택 경로를 기록하고 카드에는 원래 이름·지역을 보여 준다. |

위반 없음. 복잡도 추적이 필요한 항목은 numpy 추가 하나이며 위 표에 이유를 적었다.

## 비용 영향

임베딩 호출: 카탈로그 임베딩 905회(카탈로그 변경 때만), 질문당 1회. Titan v2 요금으로 하루 1,000질문에 1센트 수준이다(2026-11-18 시험 약 2,300회가 몇 센트 미만이었다). 별도 DB·서버를 추가하지 않는다.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 틀린 굴뚝으로 자동 진행 | 점수 차 임계값 + 충돌 이름 제외. SC-001·006으로 회귀 시험 |
| 임베딩이 틀린 후보를 높게 줌 | 임베딩은 보조 점수. 자동 선택 조건에 점수 차가 들어간다 |
| 별칭 오염 | 개인 저장 시작, 공유는 사람 승인 후(Q1) |
| 카드가 너무 자주 뜸 | 임계값 보정, 화면 선택·즐겨찾기 우선순위, 별칭 학습. SC-004로 감시 |
| 화면 선택이 서버에 안 옴 | 선행 의존. 없으면 FR-002·010을 검증할 수 없다 → 314 D10 |
