# 조사 기록: 굴뚝 대상 해석

**작성일**: 2026-11-18 · [명세](spec.md)
모든 수치는 2026-11-18에 로컬에서 잰 것이다. 코드와 데이터는 `D/morph-router-20261117/redteam/`에 있고(저장소에서 제외된 작업 폴더), 재현 명령은 [quickstart.md](quickstart.md)에 있다. 규칙 코드와 운영 설정은 바꾸지 않았다.

## 1. 시험 세트와 한계

- 출제: 사용자 Claude 계정의 Haiku 5.5 하위 에이전트 24명이 굴뚝 목록(출제자마다 16곳)을 보고 질문과 "질문에 적힌 칸"을 정답으로 적었다. 빠진 칸·기대 분기는 코드(`slot_common.py`)가 정답 칸에서 계산한다. 정답 표본 30건을 직접 읽었고 칸 오류는 0건이었다.
- 후속이 아니고 굴뚝(사업장+번호)이 완전한 질문 740건을 쓴다. 이 중 약칭·변형 325건(정답 사업장의 정식 이름이 질문에 들어 있지 않은 것), 정식 이름 415건(법인 표기를 빼고 같은 이름이 들어 있는 것).
- 한계: (1) 약칭도 LLM이 만들어 실제 사용자 표현보다 쉬울 수 있다. (2) 약칭 정답은 출제자가 본 16곳 안에서만 하나다. 905곳 전체에서는 겹칠 수 있어, 약칭 질문에서 "후보 확인 카드"를 정상 결과로 쳤다. (3) 정답을 만든 모델과 푸는 모델이 같은 계열이라 LLM 쪽 수치가 부풀 수 있다. (4) 굴뚝 번호가 있는 질문만 쓴다.

## 2. 규칙(형태소) 쪽 이름 읽기가 약한 이유

| 확인 | 결과 |
|---|---|
| 카탈로그 이름에 한 글자짜리 `㈜`(U+321C)가 들어 있는 굴뚝 비율 | 약 75% (무작위 600개 중 453) |
| 이름이 `(주)`·`주식회사`·괄호·표기 없음인 굴뚝을 카탈로그 글자 그대로 물었을 때 읽은 비율 | 147/147 |
| 이름에 `㈜`가 있는 굴뚝을 같은 방식으로 물었을 때 | 0/453 |
| 원인 | 분석기는 질문을 NFKC로 정규화해 `㈜`를 `(주)`로 바꾼다(`analyzer.py` 128행). 카탈로그 이름은 `㈜` 그대로라 일치하지 않는다. 어떤 표기로 물어도 실패한다. |
| 카탈로그 사본의 이름을 NFKC로 정규화한 뒤 같은 600개 | 598/600 (정식 이름 24% → 100%) |

사용자가 법인 표기를 생략한 입력("이알지서비스 굴뚝 1")은 수정 후에도 못 읽는다(규칙이 글자 그대로의 이름만 찾는다). 규칙 코드는 수정하지 않았고, 사본·전처리로만 확인했다.

## 3. 검색 방식 비교 (정답 사업장이 상위 N위 안)

후보는 굴뚝 번호가 질문에 있으면 그 번호의 굴뚝을 가진 사업장으로 먼저 거른다. 글자 검색은 이름+주소 2-gram의 IDF 가중 합이다. 임베딩은 Titan 텍스트 임베딩 v2(서울, 1024차원)로 사업장 문서(이름+주소)를 한 번 임베딩해 캐시하고 코사인 유사도를 쓴다. 혼합은 후보 안에서 각 점수를 z-점수로 바꿔 더한 것이다.

**약칭 325건**

| 방식 | 1위 | 3위 | 5위 | 10위 |
|---|---|---|---|---|
| 글자 | 77.8% | 88.0% | 90.8% | 92.3% |
| 임베딩(이름 말만 남긴 질문) | 71.7% | 84.9% | 88.9% | 91.1% |
| 임베딩(원문 질문) | 64.9% | 78.5% | 84.6% | 90.2% |
| 혼합(글자+임베딩 이름만) | 80.9% | 89.2% | 91.4% | 93.5% |
| **혼합(글자+임베딩 원문)** | **83.7%** | **90.5%** | **92.6%** | **94.5%** |

**정식 이름 415건**

| 방식 | 1위 | 3위 | 5위 | 10위 |
|---|---|---|---|---|
| 글자 | 94.7% | 97.8% | 97.8% | 98.3% |
| 임베딩(원문) | 82.9% | 91.3% | 93.0% | 95.7% |
| **혼합(글자+임베딩 원문)** | **99.0%** | **99.5%** | **99.8%** | **100.0%** |

- 약칭 중 3위 안 기준으로 임베딩만 맞춘 것 12건, 글자만 맞춘 것 22건. 임베딩은 글자 검색을 대체하지 못하고 보완한다.
- **정성 확인**(사용자 표현이 아니라 내가 임의로 만든 별명 12개): 임베딩은 "SK케미칼 울산 9번"을 "롯데케미칼 울산1공장"으로, "LG화학 여수 2번"을 "롯데지에스화학"으로, "포철 2번"을 "현대제철 포항1공장" 근처로 확신 있게 틀렸다. 글자 검색은 앞의 둘을 맞췄고(변환표 없이도 이름이 겹쳐서) 영문↔한글 음차 자체는 변환표가 필요하다.
- 후보 수별 혼합 1위 정답률: 후보 1~5곳(8건) 87.5%, 6~30곳(68건) 100%, 31~150곳(188건) 93.6%, 151곳 이상(476건) 90.8%. 후보가 적을수록 쉽다.

## 4. 자동 선택·카드·"없음" 경로의 비율 (혼합 점수, 1·2위 점수 차 기준)

| 임계값 | 자동 선택 | 그중 틀림 | 카드로 해결(3위 안) | "없음" 경로 | 카드를 보게 되는 비율 |
|---|---|---|---|---|---|
| 항상 자동 | 100% | 16.3% | 0% | 0% | 0% |
| 1.0 | 78.2% | 4.3% | 13.5% | 8.3% | 21.8% |
| 1.5 | 72.6% | 1.3% | 18.5% | 8.9% | 27.4% |
| 2.0 | 68.9% | 0.9% | 21.8% | 9.2% | 31.1% |
| **2.5** | **65.5%** | **0.0%** | **24.9%** | **9.5%** | **34.5%** |
| 3.0 | 63.7% | 0.0% | 26.8% | 9.5% | 36.3% |
| 4.0 | 58.5% | 0.0% | 32.0% | 9.5% | 41.5% |
| 항상 카드 | 0% | - | 90.5% | 9.5% | 100% |

(약칭 325건.) 740건 전체에서는 2.5에서 자동 80.4%, 카드 해결 15.1%, "없음" 4.5%다. "없음" 경로 비율은 임계값과 무관하게 일정하다(정답이 3위 밖이기 때문). 틀린 굴뚝으로 진행하는 것이 가장 나쁜 결과이므로 임계값은 자동 선택 중 틀림이 0인 값(2.5 이상)으로 정한다. 이 값은 이 세트에 맞춘 값이라 실제 질문이 쌓이면 다시 잡는다.

## 5. "지역을 물어보는 방어"의 효과

지역은 시·도(예: 전라남도)와 시·군(주소의 앞 두 토큰, 예: 전라남도 여수시) 두 단계로 봤다. 사용자가 정답 지역을 알려 줬다고 가정해 그 지역 후보만 남기고 다시 순위를 매겼다.

| 대상 | 단계 | 1위 | 3위 안 | 남은 후보 수(중앙값) |
|---|---|---|---|---|
| 카드 경로 145건(점수 차<2.5) | 지역 없이 | 60.7% | 77.2% | - |
| | 시·도 | 74.5% | 84.8% | 31 |
| | 시·군 | 80.7% | 89.0% | 8 |
| "없음" 경로 33건(3위 밖) | 지역 없이 | 0.0% | 0.0% | - |
| | 시·도 | 24.2% | 33.3% | 46 |
| | 시·군 | 45.5% | 51.5% | 8 |

- 시·도만으로는 후보가 수십 곳 남아 카드로 못 보여 준다. 시·군까지 받아야 효과가 크다.
- 지역을 알려 줘도 "없음" 경로의 절반 가까이는 풀리지 않는다 → 지도에서 선택하는 경로가 마지막 탈출구로 필요하다.
- 정답과 같은 이름(법인 표기 무시)·같은 시·군에 사업장이 둘 이상인 질문은 0/740건이었다. 지역 질문 뒤에 같은 이름 때문에 막히는 경우는 이 세트에 없다.

## 6. 법인 표기를 검색에서 뺐을 때 구분이 안 되는 곳

| 정규화 | 합쳐지는 묶음 | "이름+번호"가 둘 이상의 굴뚝을 가리킴 |
|---|---|---|
| 원래 이름 그대로 | - | 3쌍, 굴뚝 6개 (0.2%) |
| 법인 표기·공백·부호 제거 | 2묶음(사업장 4곳, 굴뚝 8개): 크나우프석고보드 `㈜`(전남)/`(주)`(울산), 한국제지 `㈜`(대구)/`(주)`(울산) | 4쌍, 굴뚝 8개 (0.2%) |
| 위 + 괄호 안 내용 제거 | 3묶음(사업장 7곳, 굴뚝 44개): 위 2묶음 + 엘지화학 여수공장(용성1단지·용성2단지·화치) | 5쌍, 굴뚝 10개 (0.3%) |

- 이름 하나가 사이트 여러 곳에 걸친 사업장이 4곳이다(동서식품㈜ 충북/인천, ㈜금비 경기/충남, 한국주강㈜ 등). 법인 표기와 무관하게 이름+번호만으로는 구분되지 않는다.
- 상호 앞 4글자가 같은 사업장이 많은 묶음: 에스케이 16, 한국지역난방 15, 리뉴에너지 11, 한국남부 9, 엘지화학 8, 한국중부발전 8, 한일시멘트 8, 한화솔루션 6.
- 결론: 법인 표기는 검색에서 빼도 안전하다(굴뚝 기준 0.2~0.3%). 충돌 이름은 색인에서 표시해 항상 카드로 보낸다. 카드에는 원래 이름과 지역을 보여 준다.

## 7. 서울 리전 Bedrock 확인 (2026-11-18)

Titan 텍스트 임베딩 v2는 정상(1024차원, 응답 약 0.5초). Cohere 다국어 임베딩과 Titan 임베딩 v1은 서울에서 모델 ID가 유효하지 않았다. Claude Haiku 4.5(`global.` 프로필)와 Nova Lite(`apac.` 프로필)는 정상. 비교 시험 전체에서 임베딩 호출은 약 2,300번, 비용은 몇 센트 미만이다.

## 8. 검토한 대안과 결정

| 대안 | 평가 | 결정 |
|---|---|---|
| 별도 벡터 DB(pgvector·OpenSearch) | 대상이 905곳이라 메모리 벡터로 충분하다. 법령 문서 RAG에는 필요하지만 굴뚝 이름에는 과하다. | 쓰지 않음. 메모리 색인 |
| 임베딩만 사용 | 글자 검색보다 낮고 틀린 후보에 확신 있는 점수를 준다. | 쓰지 않음 |
| 글자 + 임베딩 혼합 | 약칭 1위 +6%p, 정식 이름 +4%p | 권장(결정 Q3) |
| LLM이 후보 목록에서 선택(905곳 이름을 프롬프트에) | 별명(포철 등)에는 도움이 될 수 있으나 미측정이고 호출마다 이름 목록 비용이 든다. | 보류. 후보 보강 2차 수단으로만 검토 |
| 규칙(형태소) 코드의 이름 매칭 수정 | `㈜` 정규화 한 줄로 정식 이름 읽기 24%→100%. 법인 표기 생략·약칭은 규칙으로 못 푼다. | 별도 결정(314 D2). 이 기능은 규칙 이름 읽기에 의존하지 않는다 |
| 화면 선택·즐겨찾기를 후보 우선순위로 씀(제한하지 않음) | 선택한 굴뚝이 먼저 보이면 카드가 짧아진다. 측정 데이터 없음(선택 맥락 전달 필요) | 채택. FR-002 |
| 카드 선택을 별칭으로 저장 | 남들이 어떻게 부를지 추측하지 않고 쓰면서 모은다. | 채택. 범위는 Q1 |

## 9. 모르는 것

- 실제 현장 담당자가 굴뚝을 부르는 말(별명, 지역 중심 표현, 번호 모르는 경우). 사용자도 알지 못한다고 했다. 별칭 저장(US4)과 질문 기록으로 모은 뒤 기준선을 다시 잰다.
- 번호가 없는 질문에서의 정확도(US3).
- 화면 선택 맥락이 들어왔을 때의 후보 우선순위 효과.
- 임베딩이 다른 모델(Haiku 4.5·Nova)에서도 같은 효과를 내는지는 이 기능과 무관하다(임베딩 모델만 해당). 임베딩 모델은 Titan v2 하나뿐이다.
