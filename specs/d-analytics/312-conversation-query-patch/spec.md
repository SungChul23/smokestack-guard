# 기능 명세: 확정 조회 기반 연속 질문

**작성일**: 2026-11-16 · **담당**: D · **상태**: 로컬 구현·검증 완료, 실제 실행기 미연결 · 브랜치 변경 없음
**요청**: 검증·실행·결과 전달이 끝난 질의의 조건을 복사하고 일부만 바꾸는 방식으로 대화를 연결한다. 완료 후 Mermaid 흐름도를 제공한다.

## 사용자 시나리오 및 검증

### US1 — 같은 조회의 날짜·물질 변경 (P1)

사용자는 완료한 단일 측정 조회 뒤 ‘어제는?’, ‘NOx는?’처럼 짧게 이어 묻는다.
**독립 검증**: 첫 성공 조회 뒤 날짜만·물질만 바뀌고 나머지 조건과 기존 기록이 보존되는지 확인한다.
1. ‘어제’는 이번 요청의 실제 한국 날짜 기준이고 반복해도 그제로 이동하지 않는다.
2. ‘그 전날’은 직전에 확정한 하루 구간의 전날이다. 기간이 모호하면 확인한다.
3. 명확한 변경은 추가 언어모델 해석 없이 재검증된 새 조회로 준비된다.

### US2 — 불확실한 상속 방지 (P1)

법령으로 주제가 바뀌거나 이전 요청이 미완료이면 과거 측정 조건을 자동 상속하지 않는다.
**독립 검증**: 성공 측정→법령 질문→‘어제는?’ 및 실패/준비만 된 요청에서 조건 확인으로 멈춘다.
1. 실행 준비·실행 완료·결과 전달 완료를 구분한다.
2. 모호한 날짜·대상·복합 변경은 짧은 확인 안내로 처리한다.
3. 실패·취소·만료·권한/자료 변경 뒤 자동 재실행하지 않는다.

### US3 — 추적 가능한 새 요청 (P2)

사용자와 검수자는 어떤 조건이 이번 입력·이전 실행·날짜 해석에서 왔는지 확인한다.
**독립 검증**: 부모 질의와 필드별 출처를 확인하고 원본 실행 기록이 변경되지 않는지 검사한다.

## 요구사항

- FR01: 기존 입력 가드레일을 먼저 적용한다. 분류 전에 후속 변경 여부를 검사한다.
- FR02: 재사용 기반은 검증·실행 성공·결과 전달이 확인된 활성 단일 측정 조회로 제한한다.
- FR03: 지원 도구는 단일 굴뚝 값 조회·평균/최댓값 집계이며 첫 자동 변경 필드는 기간·NOx/SOx다. 대상 변경은 정확한 식별을 요구하고 자동 확장하지 않는다.
- FR04: 새 요청은 부모·변경 내역·상속 출처를 남기고 스키마·권한·기간·자료·지원 범위를 재검증한다.
- FR05: 독립 질문은 초점을 전환한다. 과거 성공 기록을 무조건 최신 문맥으로 선택하지 않는다.
- FR06: 과거 기록을 덮어쓰지 않으며 최근 기록 수와 유효기간을 제한한다.
- FR07: 실제 실행기 미연결 상태를 유지하고 가상 시연을 실제 완료 기록과 혼합하지 않는다.
- FR08: 모호한 후속 질문에는 LLM 호출 전에 조건 확인을 우선한다. 미지원 기능을 다른 조회로 대체하지 않는다.
- FR09: 감사·확인·답변 표현 선호처럼 조건 변경 없는 발화는 최대 3턴까지 건너뛰어 활성 초점을 유지한다. 건너뛴 원문·유형·순서를 기록하고 TTL을 연장하지 않는다. 도구가 호출되지 않았다는 사실만으로 새 질의·주제 변경을 건너뛰지 않는다.
- FR10: 존댓말·조사·공통 물질 별칭의 짧은 단일 변경을 정규화하되, 부정·복합 동작·집계 방식 변경을 지우지 않는다.

## 주요 개체

질의 준비 상태, 결과 전달이 확인된 실행 기록, 활성 대화 초점, 필드 변경 요청과 출처.

## 예외와 성공 기준

‘하루 전’, ‘작년’, ‘B는?’·법령 날짜는 추정하지 않는다. 빈 조회 결과는 정상 실행과 데이터 없음으로 구분할 수 있지만 실행 실패는 재사용하지 않는다. 결과 전달 실패·비동기 중 새 주제·자료/권한 변경은 기록 상속을 차단한다.

- SC01: 어제 반복·전날·물질 변경 연쇄에서 기대 기간/조건과 기록 보존을 모두 만족한다.
- SC02: 모호/권한/상태/가드레일 반례에서 잘못된 자동 실행이 0건이다.
- SC03: 기존 라우터 회귀를 유지하고 실제 Kiwi·브라우저 시연 결과를 별도로 기록한다.
- SC04: 실제 실행 여부와 가상 검증 여부를 모든 결과에서 구분한다.
