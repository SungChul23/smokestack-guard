# 구현 계획: 경고 대응·법령 절차 근거 검색

**Branch**: 기존 main 유지 | **Date**: 2026-11-12 | **Spec**: [spec.md](spec.md)

## Summary

확보한 현행 공식 법령 3개, 조문 11개를 원문·메타데이터와 함께 작은 검색 자료로 만든다. 기존 정적 관제의 플로팅 질문창에서 키워드 기반 근거 검색을 제공한다. 이번 단계는 검색 기준선이며 생성 LLM·벡터 검색·운영 Agent는 연결하지 않는다.

## Technical Context

- **Language/Version**: 기존 Python 3.12.10, 브라우저 JavaScript·HTML·CSS.
- **Primary Dependencies**: 추가 패키지 없음. Python 표준 라이브러리, 기존 HTTP 정적 서버와 브라우저 기능 재사용.
- **Storage**: 기존 로컬 JSON 방식. 공식 HTML 원문·출처는 `D/law-evidence-search/`, 브라우저 공개 근거는 관제 assets에 둔다. 신규 DB·인덱스 서버는 채택하지 않는다.
- **Testing**: Node 내장 assert와 기존 CDP 브라우저 검사. 원문 SHA-256·조문 메타·양성/음성 검색·시점·HTML 입력·읽기 실패를 검증한다.
- **Target Platform**: 현재 Windows 로컬 정적 관제, 데스크톱·모바일 브라우저.
- **Project Type**: 기존 화면의 읽기 전용 검색 기능.
- **Performance Goals**: 11개 조문의 로컬 검색은 사용자 입력 후 즉시 처리하고, 원문은 질문창을 열 때 한 번만 읽는다.
- **Constraints**: 입력 최대 1,000자. 공식 URL allowlist. 검색 결과는 최대 4개 후보. 숫자·법률 판단·새 절차를 생성하지 않는다.
- **Scale/Scope**: 2026-11-12 시행·확인본 3개, 11개 조문. 다른 시점·시설별 적용 판단·별표 및 서식 파일 본문은 미확보다.

## Complexity Tracking

### 추가 검색·조건 수집 구현

기존 검색 API에 선택적인 확인 조건을 추가한다. 허용된 항목·열거값·날짜 형식만 통과시키고 임의 tool/sql/url은 받지 않는다. 로컬 메모리의 확인 세션은 원문·기준일·자료 버전에 묶는다. UI는 본문 폼과 분리된 조건 폼에서 입력을 받고, 누락 항목만 다시 표시한다. 확인된 조건은 관련 문서·조문 검색의 범위 선택에 사용하며, 법정 마감일·시설별 적용 결론은 계산·생성하지 않는다.

자료 추가 수집은 공식 부처의 공개 첨부 링크로 확장하되 실제 제목과 버전을 확인한다. 현행·과거·개정안·목록만 확보를 구분한다. 자료를 찾을 가능성과 지금 확보한 근거를 구분하고 공식 접근 제한을 우회하지 않는다.

### 2026-11-14 후속 검색 개선

현재 JSON·JS·Python 표준 라이브러리를 유지한다. 같은 보존 시행본의 미추출 조문을 해시 대조 후 추가하고, 공식 공개 목록의 설명을 저장 HTML에서 추출한다. 메타정보와 조문번호는 구조화된 필터로 처리한다. 주제 분류는 문서 구간별 검색 메타 및 원문 어휘 점수로 순위를 매기며, 필요한 주제 없이 일반 단어만 겹친 결과는 채택하지 않는다. 확인 카드는 명시적인 새 질문 선택으로 처리하며 원래 질문과 구분해 표시한다. 미확정 해석을 LLM이 처리했다고 표시하지 않는다.

검증: 기존 25/39개 경계 검사, 고정된 240개 질문의 개선 전후 결과, 별도 짧은 질문·부정·복합/불법 은폐·문서종류·조문번호·메타·미확보·확인카드 및 실제 브라우저 회귀. 추가 수집 실패도 원본 응답과 시각으로 기록한다.

### 2026-11-14 자료 보강

기존 JSON에 선택적 `supplements` 묶음을 추가한다. 묶음은 확인일·공식 설명 문서·원문 구간·미확보 주제를 담는다. 법령 본문 배열과 법령 기준일은 유지한다. 공공데이터포털·환경공단 호스트는 설명 구간에만 허용하며 법령 본문 호스트 제한은 유지한다. 기존 Python 표준 라이브러리 HTML 파서로 저장 HTML에서 지정 구간을 다시 추출하고 원본·구간 해시를 확인한다. 빌더가 검증 실패하면 파일을 쓰지 않는다.

질문창은 기존 한 번 읽는 자료 요청을 유지하고 추가 요청 없이 보강 자료를 검색한다. 공식 설명에는 확인일과 설명 자료임을 표시하며 시행일을 생성하지 않는다. 미확보 원문을 직접 요구하는 질문은 `not_found` 및 `missing_sources`로 반환한다. 자료 갱신 자동화나 법령 판정 엔진은 만들지 않는다.

원칙 위반 없음. 신규 프레임워크·백엔드·운영 저장소·유료 API 없이 기존 로컬 경로를 유지한다.

### 근거 없는 출력 차단

후속 일반 안내 우선 구현은 기존 로컬 검색에서 일반 절차의 후보를 먼저 반환하고 optional 확인을 별도로 표시한다. 절차/보고 유형을 임의 선택하지 않고 대표 근거를 최대 4개로 유지한다. 직전 문서 대화의 허용 조건만 세션 메모리에 전달해 짧은 서류 후속 질문에 쓴다. 실제 API·패키지·운영 데이터 계약 변경·새 원문 수집은 없다. 추가 질의도 이미 읽은 로컬 코퍼스에서만 수행한다.

검색 결과에 답변 정책을 부착한다. 조건 확인·자료 부족·시행본 없음·입력 오류·범위 밖과 다른 허용 도구가 필요한 경우에는 원문 답변을 열지 않는다. 근거가 있으면 이번 검색의 ID와 실제 원문 인용만 허용하고, 문서 메타정보는 별도 표시한다. 화면은 이 정책을 확인한 후 결과를 렌더링한다.

후속 출력 검증 함수는 검색을 다시 수행해 인용 ID와 원문 부분 문자열을 대조한다. 자유 요약·자유 설명 필드는 거절한다. 이는 인용 출처 일치 검사이며, 문맥·법적 적용·요약의 의미 검증과 동일하지 않다. 실제 LLM 연결 전이므로 운영 API 응답을 검증했다고 표현하지 않는다. 추가 네트워크·패키지·유료 API는 없다.
