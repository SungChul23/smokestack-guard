# 로컬 검색 함수와 화면 계약

이 계약은 D의 공식 문서 검색 원형에만 적용한다. 팀 운영 API·Silver·Gold 계약이 아니다.

2026-11-14 검색 v2는 문서 공포번호/조문 직접 조회, 메타정보, 주제 내 원문 어휘 순위, 확인 카드를 포함한다. 선택 전에는 확인 카드의 question을 실행하지 않으며, 사용자가 버튼을 누르면 그 질문을 입력란에 표시하고 새로운 검색으로 처리한다. 기존 질문의 조건을 몰래 보충하여 실행하지 않는다. 범위 밖·기만·삭제/외부전송에는 확인 카드를 강제로 띄우지 않는다.

동일 문서 내 조문 참조는 원문이 조·항의 사항을 따르라고 명시한 경우만 한 단계 읽고 provenance를 반환한다. 원문에 없는 연결이나 외부 조문 내용을 만들지 않는다. 교정 상세·API 명세·표·고시 본문 미확보는 자료 없음으로 보류한다.

`TmsLawSearch.search(question, corpus, {asOf, conditions, request_context})`는 동기 읽기 전용 함수다. 입력과 corpus를 바꾸지 않는다. 공개 원문에서 찾은 후보를 `data-model.md`의 결과 형식으로 반환한다. Node 검증에서도 같은 검색 함수를 사용한다. 추가 조건은 응답의 question_context와 함께 제출하며 원문·기준일·자료가 일치해야 한다. 허용 필드·열거값·유효 날짜를 검증하고 누락 항목만 다시 요청한다.

응답의 `answer_policy`는 이번 검색에서 허용한 답변 종류와 근거 ID를 담는다. 검색 실패 후 자유 답변 또는 모델 지식으로 우회하지 않는다. `validateGroundedDraft(question,corpus,options,draft)`는 이번 검색 결과의 ID와 정확히 일치하는 원문 인용만 허용하며 임의 요약·설명 필드는 거절한다. 이는 인용 일치 검증으로, 자유 요약의 의미나 법적 적용 검증과 구분한다. 실제 API 연결 전의 로컬 계약이다.

질문창은 corpus를 최초 열기 시 로컬 HTTP에서 읽고 재사용한다. 실패하면 재시도 버튼을 제공한다. 사용자 입력은 textContent로만 표시한다. 검색 결과에 공식 링크를 만들 때 URL protocol·host를 검사한다. 요청이 늦게 끝나도 닫힌 창의 초점을 빼앗거나 이전 질문을 최신 질문으로 덮어쓰지 않는다.

확보한 조문에서 찾지 못한 질문은 `not_found`이며, 비관계 질문은 `out_of_scope`다. 위반 확정·처분 금액·실행 요청은 해당 기능을 수행하지 않고 `needs_context` 또는 범위 안내를 제공한다. 특정 사업장의 실제 신고 의무·기한은 자동 결정하지 않는다.

표시 항목은 검색 상태, 문서 기준일, 관련 원문 후보, 법령명·조문·시행일·확인일·공식 출처와 범위 안내다. 검색 중 “AI가 분석했다”거나 생성 답변을 표시하지 않는다. 입력·날짜 선택은 명시적 label을 가진다.

2026-11-14 보강: 동일 자료 응답에 공식 설명을 포함한다. 별도 네트워크 요청이나 DB를 추가하지 않는다. 법령에는 시행일·확인일, 설명에는 종류·확인일만 표시한다. 법령 날짜 요청은 기존 기준일 검증을 먼저 통과해야 한다. 설명 페이지의 확인일을 입력해 다른 날짜의 법령까지 확보했다고 해석하지 않는다. `not_found.missing_sources`에는 부족한 자료 목록을 담는다. 표·사전·시험기준 미확보는 읽기 오류와 구분한다.
