# 기능 명세: 경고 대응·법령 절차 근거 검색

**Feature Branch**: 기존 `main` 유지. 브랜치 생성·전환 없음.
**Created**: 2026-11-12
**Status**: 로컬 1차 범위 확정. 팀 운영 연결은 별도 합의.
**Input**: 사용자 선택 “경고 대응·법령 절차 — 공식 문서에서 관련 조문·절차와 출처 찾기”.

## User Scenarios & Testing

### User Story 1 - 질문에 맞는 공식 근거 찾기 (Priority: P1)

관제 사용자는 배출허용기준 초과 대응·측정기기 관리·개선명령 관련 질문을 입력해 공식 원문의 관련 구간과 출처를 확인한다.

**Why this priority**: 설명 생성 이전에 어떤 자료를 근거로 쓸지 검증해야 한다.
**Independent Test**: 대표 질문별 기대 조문과 검색 결과의 원문·출처를 대조한다.

**Acceptance Scenarios**:
1. **Given** 확인한 공식 조문이 있을 때, **When** “배출허용기준 초과 시 개선명령 관련 근거는?”을 검색하면, **Then** 관련 원문과 공식 출처가 표시된다.
2. **Given** 측정기기 운영 조문이 있을 때, **When** “측정기기가 고장 나면 어떤 관리 규정을 확인해?”를 검색하면, **Then** 확보한 관련 근거만 제시한다.
3. **Given** 관련 근거가 없을 때, **When** 지원 범위의 질문을 검색하면, **Then** 찾지 못했다고 표시하고 절차를 창작하지 않는다.

### User Story 2 - 적용 시점과 불확실성 확인 (Priority: P1)

사용자는 법령명·조문·시행일·확인일을 보고, 특정 시설 적용과 법적 판단에 필요한 정보가 별도로 있음을 이해한다.

**Why this priority**: 수치 또는 예측 경고만으로 위반·처분을 확정해서는 안 된다.
**Independent Test**: 미확보 시점·개별 위반 확정·처분 수위 질문을 검증한다.

**Acceptance Scenarios**:
1. **Given** 특정 시행본만 확보했을 때, **When** 다른 시점의 적용을 요청하면, **Then** 해당 시점 원문 미확보를 안내한다.
2. **Given** 시설 적용 조건이 없을 때, **When** “우리 사업장은 위반 확정이야?”라고 물으면, **Then** 위반을 판정하지 않고 적용 조건 확인이 필요하다고 안내한다.
3. **Given** 로컬에서 공식 원문을 대조했을 때, **When** 결과를 확인하면, **Then** 팀 운영 승인까지 받았다고 표시하지 않는다.

### User Story 3 - 기존 질문창에서 검색 상태 확인 (Priority: P2)

사용자는 기존 플로팅 질문창에서 검색하고 자료 읽기 실패·범위 밖·검색 결과 없음을 구분한다.

**Why this priority**: 기존 관제 기능을 유지하면서 작은 검색 흐름을 확인한다.
**Independent Test**: 질문부터 근거 카드까지 확인하고 지도·그래프·테마·닫기를 검사한다.

**Acceptance Scenarios**:
1. **Given** 관제가 열려 있을 때, **When** 질문창에서 검색하면, **Then** 관련 근거를 확인하고 관제 탐색을 계속할 수 있다.
2. **Given** 문서를 읽지 못했을 때, **When** 검색하면, **Then** 자료 읽기 실패를 검색 결과 없음과 다르게 안내한다.
3. **Given** 범위 밖 또는 실행 지시 입력일 때, **When** 검색하면, **Then** 외부 실행·지도 조작·판정 변경을 하지 않는다.

### Edge Cases

- 빈 질문·긴 질문·범위 밖·HTML 입력·문서에 포함된 실행 지시.
- 미확보 과거 시행본·미래 시행본·문서 확인 이후 개정 여부 미확인.
- 단어 일부만 일치하는 문서, 서로 다른 시설 적용 조건, 원문 파일 누락·손상.
- 숫자 비율만으로 위반 확정·벌금·조업정지를 요구하는 질문.

## Requirements

### Functional Requirements

- **FR-001**: 기존 플로팅 질문창에서 질문과 공식 근거 검색 결과를 제공한다.
- **FR-002**: 확인한 국가기관 공식 원문만 근거로 사용한다. 기획서·Mock 법령·생성 문장을 법적 근거로 사용하지 않는다.
- **FR-003**: 결과마다 법령명·조문·원문 구간·공식 URL·시행일·확인일을 표시한다.
- **FR-004**: 확보 경로·시행본·원문 해시를 보존해 결과를 추적할 수 있게 한다.
- **FR-005**: 미확보 시점이나 시설 적용 조건을 추정해 위반·처분 수위를 판단하지 않는다.
- **FR-006**: 빈 질문·범위 밖·근거 부족·자료 읽기 실패를 구분하고 절차를 창작하지 않는다.
- **FR-007**: 질문·문서는 검색 자료로 취급한다. 외부 실행·운영 쓰기·모델 호출·지도 조작을 제공하지 않는다.
- **FR-008**: 근거 검색 단계로 표시하며, 생성 답변·벡터 검색·Agent 판단이 실행됐다고 표시하지 않는다.
- **FR-009**: 기존 지도·수치·테마·개인 설정을 유지하고 질문창 변경 전에 백업한다.
- **FR-010**: 대표 검색과 범위 밖·미확보 시점·HTML 입력·문서 누락 사례를 검증한다.

### Key Entities

- **공식 문서**: 제목, 발행 기관, 원문 URL, 시행본, 시행일, 확인일, 해시, 로컬 검토 상태.
- **근거 구간**: 원문 참조, 조문·항, 검토한 본문, 검색 주제.
- **검색 요청·결과**: 질문, 문서 기준 시점, 검색 상태, 관련 근거, 적용 확인이 필요한 사항.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 결과 카드 100%에 공식 원문 출처·조문·시행일·확인일이 있다.
- **SC-002**: 대표 질문 6개 이상에서 기대 근거를 찾고 관련성이 없는 결과를 적합한 근거로 표시하지 않는다.
- **SC-003**: 범위 밖·근거 부족·미확보 시점·읽기 실패 검사에서 절차·수치·판정을 창작한 사례가 0개다.
- **SC-004**: 검색 중 지도·측정 조회·테마·질문창 열기·닫기가 유지된다.

### 일반 안내 우선

사용자는 일반적으로 설명할 수 있는 근거를 먼저 안내하고 개별 적용에 필요한 조건만 추가로 묻는 흐름을 승인했다. 일반 점검·보수·제출자료·보고 절차는 관련 보관 원문을 먼저 보여주며 명령별 분기를 임의 선택하지 않는다. 개별 기한·의무·서식 확정은 필요한 조건 확인을 유지한다. 일반 답변 뒤의 개별 확인은 선택적으로 열고 원문 안내를 가리지 않는다. 직전 문서 대화에서 명시·확인된 조건만 제한된 서류 후속 질문에 재사용한다. 지도 선택·지도 시간은 이 문맥에 자동 포함하지 않는다.

사용자가 후속으로 GPT API 시험을 요청했고 API 키가 준비되어 있다고 답했다. 로컬 CLI 시험 어댑터·무통신 검사·환경변수 안내를 먼저 준비한다. 실제 키 사용·유료 호출은 이전의 명시적 확인 요청을 유지한다. 최초 시험은 공식 근거 인용 선택과 출력 검증이며 화면·운영 API·자유 요약을 완성했다고 보지 않는다.

사용자는 보유 자료·허용 도구 결과 안에서만 답하고, 부족하면 조건 확인·자료 부족·미지원으로 안내하도록 요청했다. 이번 범위는 기존 로컬 문서 검색의 답변 정책과 원문 인용 검증이다. 검색 실패 후 자체 지식 답변으로 우회하지 않는다. 원문 인용 검증은 인용이 실제 검색 결과의 부분 문자열인지 검증하며 자유 요약의 의미 정확도까지 보장한다고 주장하지 않는다. 실제 모델 API·법적 결론 생성·운영 데이터 계약은 추가하지 않는다.

사용자는 자료가 있는 질문의 검색어·참조 연결 보강, 공개 공식 자료 추가 수집, 누락 조건을 인지한 즉시 재질문하는 흐름을 승인했다. 조건 확인은 원래 질문·문서 기준일에 묶어 세션 메모리에 보존한다. 문서 종류·보고 유형·명령 종류·수령일·시설 유형 등 필요한 항목만 묻고, 이미 사용자가 제공한 값은 유지한다. 선택·입력은 명시적 확인 뒤 적용한다. 질문이나 기준일을 바꾸면 이전 확인 값을 자동 재사용하지 않는다.

조건을 모두 받았더라도 없는 원문·미지원 도구·개별 법적 판정을 해결했다고 표시하지 않는다. 조건이 필요한 상태와 자료가 없는 상태는 분리하고, 진행할 수 없는 질문에 불필요한 시설 정보를 계속 요구하지 않는다. 원문과 대화 입력은 코드·쿼리로 실행하지 않으며 브라우저 저장소에 자동 저장하지 않는다.

### 2026-11-14 수집·검색 개선 승인

사용자는 공식 자료 추가 수집과 검색 흐름 보강을 함께 승인했다. 기존 기술로 조문 직접 조회·문서 메타정보 조회·주제 기반 원문 순위를 개선한다. 문서 종류/질문 유형이 불명확한 경우 확인 카드를 제공하고 사용자 선택 전에는 실행하지 않는다. 불필요한 주제 확인 카드를 범위 밖 질문에 보여주지 않는다.

공식 공개 목록의 항목과 실제 TMS 장비 항목을 구분하고, 미확보 API 명세·별표·상태 사전을 일반 설명으로 대체하지 않는다. 해석할 수 없는 자유 질문은 미확정으로 표시한다. 운영 LLM API·인증·DB를 새로 선택하지 않는다. 기존 실패 240문항의 기대값과 실행 결과는 보존하고 개선 버전을 별도로 비교한다.

### 2026-11-14 공식 자료 보강 범위

사용자는 미확보 자료를 계속 수집하면서 확보한 자료부터 연결하도록 승인했다. 기존 2026-11-12 조문 11개는 기준일을 유지한다. 새로 받은 조사 요약 21개는 검증된 원문으로 채택하지 않는다.

- 공식 공공데이터포털·환경공단 HTML에서 원문 위치와 해시를 확인한 설명 구간만 추가한다. 설명 페이지에는 법령 시행일을 만들어 넣지 않고 확인일을 표시한다.
- 검색 결과에서 법령 조문과 공식 서비스 설명을 구분한다. 설명 페이지를 개별 시설의 법적 의무·기준·상태코드 정의의 근거로 대체하지 않는다.
- 별표 8·고시 별표 1·상태코드 사전·공정시험기준이 필요한 질문에는 구체적인 미확보 항목을 알린다. 관련 조문을 찾더라도 해당 상세 원문을 확보했다고 표현하지 않는다.
- 기존 주제 검색·지도 이동·초과 조회는 유지한다. 새로운 모델·벡터 DB·자동 갱신·외부 인증은 범위 밖이다.

인수 기준: 설명 구간 원문 재추출 및 해시 일치, 검색 결과 출처와 문서 종류 표시, 미확보 질문에서 내용 창작 0건, 기존 조문 검색 회귀 통과, 같은 공식 원문 검색 경로로 실제 질문창 연결 확인.

- 사용자는 근거 검색부터 시작하는 범위를 선택했다. 생성 LLM·임베딩·벡터 저장소·운영 서버 선택은 후속 합의로 둔다.
- 기존 로컬 실행 환경과 화면을 재사용한다. 클라우드 자격 증명·유료 모델·외부 서비스 설정을 사용하지 않는다.
- 공식 원문 검토본을 이용한 로컬 기능이다. 팀 승인 운영 컬렉션이나 시설별 법률 판단을 뜻하지 않는다.
- Silver·Gold·모델 판정·법적 사건 정의는 팀 명세를 기다린다.
- 2026-11-12에 확인한 시행본의 범위를 표시한다. 개정 확인 자동화는 후속 작업이다.
