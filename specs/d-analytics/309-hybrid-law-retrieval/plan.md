# 구현 계획: 공식 문서 하이브리드 검색

## 요약과 기술 맥락
기존 JavaScript 문서 검색기에 로컬 다국어 임베딩 후보를 보조로 결합한다. FastEmbed(ONNX CPU)와 sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2를 격리된 Python 가상환경에서 사용한다. 임베딩은 float32 파일·JSON 매핑으로 저장하고 정규화 내적으로 비교한다. 작은 문서 집합이므로 별도 DB 서버는 만들지 않는다.

## 구조와 결정
- D/law-vector/: 모델 캐시·인덱스 생성·로컬 후보 검색과 평가. 다운로드는 공개 모델 파일만, 토큰 없이 한다. HF_TOKEN을 요청에 사용하지 않도록 비활성화한다.
- 기존 검증된 law-evidence-20261112.json의 본문을 조문 내부 단락으로 분할하고 검색 결과는 기존 근거 ID로 되돌린다. 출처/본문은 기존 corpus에서만 가져온다.
- 동일 질문·문서 지문에 결속된 vectorContext를 기존 검색기 옵션으로 전달한다. 정확 조문 조회와 모든 선행 가드는 우선한다. 기존 주제 필터는 유지하되 주제를 못 찾은 일반 문서 질문에는 의미 검색 후보를 허용한다.
- 의미 검색 모델은 소형 다국어 baseline이며 한국어 법령에 최적이라고 주장하지 않는다. score 임계와 평가 문항은 개발/보류 구분해 기록한다.
- 로컬 작업대는 비동기로 후보를 준비한 뒤 기존 동기 검색 검증을 실행한다. 대기 중 요청 교체·취소·권한 변경을 재검사한다. 실패는 lexical_fallback으로 표시한다.

## 원칙 점검
수집 코드·스케줄·원본·Silver 계약은 변경하지 않는다. 실제 문서 내용을 외부 추론 서비스로 보내지 않는다. 공개 모델·패키지 다운로드만 수행하고 모델/캐시를 저장소 밖으로 배포하지 않는다. 실제 키·유료 호출·외부 서비스 설치 없음. 비용은 로컬 저장 공간·CPU이며 공개 모델 파일 수백 MB의 초기 다운로드가 필요할 수 있다. 동작 전후 원칙 위반 없음.

## 구현 순서
spec→문서 범위·모델 확인→인덱스→질문 결속/검색 보조→작업대 비동기 연결→실제 임베딩 비교/보호 회귀→기록. 기존 검색기는 백업하고 원본 평가 기대를 보존한다. 네트워크/패키지 설치가 막히면 텍스트 hash 벡터를 대신 임베딩이라고 부르지 않는다.
