# 기능 명세: 공식 문서 하이브리드 검색

**Feature Branch**: 기존 브랜치 유지 (사람 관리)
**Created**: 2026-11-16
**Status**: 로컬 구현·검증 완료 (운영 DB·LLM 생성·메인 관제 제외)
**Input**: “오케이 백터 붙여 보자, 문서도 그러라고 다 모아둔거 아니야?”

## 사용자 시나리오와 검증

### US1 — 표현이 다른 근거 검색 (P1)
사용자가 일상 표현으로 TMS 법령·대응 문서를 물으면 보관 공식 근거에서 관련 후보를 찾는다. 기존 문자열 검색과 의미 검색을 비교할 수 있다.
독립 검사: 정답 근거를 먼저 고정한 문항으로 두 검색 결과의 적중·누락·오탐을 비교한다. 개선을 미리 보장하지 않는다.

### US2 — 근거·조건 보호 (P1)
유사한 조문이 검색되어도 명령 유무·법령명·기준일·미확보 별표·시설 판정의 제한을 유지한다.
인수 기준: 정확 조문 조회 결과 유지, 날짜·원문·범위 보호 검사 통과, 문서 없는 질문에 창작 답변 없음.

### US3 — 로컬 검색 연결과 실패 안내 (P2)
로컬 작업대의 문서 검색 도구에 연결한다. 의미 검색 실패 시 기존 검색으로 처리했음을 명시한다. 과거 요청의 늦은 결과가 새 요청을 바꾸지 못한다.

## 요구사항
- FR-001: 이미 검증한 공식 문서와 출처·판본을 추적해 검색 후보를 만든다. 미검증 파일을 자동으로 법적 근거에 편입하지 않는다.
- FR-002: 정확 조회와 기존 키워드 검색에 의미 검색 후보를 보조로 결합한다.
- FR-003: 명시 조건 필터와 직접 근거·전체성·생성 제한을 유지한다. 유사도는 적용 가능성의 증명이 아니다.
- FR-004: 검색 질문·문서 지문·모델·인덱스 버전을 연결하고 다른 질문·문서의 후보를 거절한다.
- FR-005: 다운로드 이후 문서·질문 임베딩은 로컬에서 처리한다. 자격 증명·유료 API·외부 서비스는 사용하지 않는다.
- FR-006: 실제 모델로 평가하고 검색 방식별 적중·변경·한계를 기록한다. 문자열 벡터화를 신경망 임베딩으로 소개하지 않는다.
- FR-007: 준비·실패·기존 검색 대체·검색 완료를 구분하고 기존 가드레일과 원문을 보존한다.

## 경계와 주요 개체
CorpusChunk(원문·출처·해시), EmbeddingIndex(모델·벡터·구간 매핑), BoundCandidates(질문·문서 지문·점수), RetrievalResult(검색 방식·근거 후보·한계).
빈 질문, 범위 밖 요청, 미확보 판본, 다른 인덱스, 모델 읽기 실패, 요청 취소·시간 초과를 검사한다.

## 성공 기준
- SC-001: 기존 조문 정확 조회와 보호 검사는 모두 유지한다.
- SC-002: 최소 20개의 사전 고정 질문에서 두 방식의 결과를 비교하고 악화 사례도 남긴다.
- SC-003: 실제 임베딩의 차원·모델·문서 수·검색 지연을 기록한다.
- SC-004: 작업대에서 검색 연결·실패 대체·늦은 응답 보호를 확인한다.

## 범위
로컬 실험이다. 운영 데이터 계약·AWS·벡터 DB 서버·실제 LLM 생성·DB 수치 조회·배포는 추가하지 않는다. 질문을 벡터로 바꿨다고 도구 조건 부족이나 대화 기억이 해결됐다고 하지 않는다.
