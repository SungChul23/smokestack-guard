## 사용 방법

**이 문서는 옛 코드를 옮기는 지침이 아니라, 새로 만들 화면의 구현 지시서(브리프)다.** 새 코드는 디자인(§2), 기능(§3), 구조(§4), 서버 약속(§5), 순서(§6)를 보고 새로 쓴다. 옛 코드에서는 **화면과 무관한 순수 로직만** 가져온다(§4). 옛 코드에 숨어 있는 규칙(상태 분류, 숫자 표시, 공백 처리, 물질 잠금, 안내 문구)은 새로 쓸 때 놓치기 쉬우므로, 각 단계를 시작할 때 해당 옛 파일을 읽어 **규칙을 이 문서의 §10에 옮겨 적고 시험으로 고정한다.** 같은 데이터에서 같은 숫자가 나오는지가 완료 기준이다.

- A가 `dashboard-web`에 Google 로그인 + 초대 코드, 첫 화면(실시간 연출 그래프·사이렌·마스코트·다크/라이트 전환)을 머지했다. CI가 자동 배포해서 **운영 주소는 지금 A의 React 앱**이다. 로그인 뒤 `Dashboard`는 "준비 중" 문구뿐이다.

## 3. 옮길 기능 (재영 님 정리 반영)

**화면 구성**
- 상단바: **일단 비운다.**
- 좌측 레일: 통합 관제 / 경고 목록(개수 배지) / 측정 추세 / 라이트·다크 전환
- 머리말: 제목, 화면 기준 시각(예: 11.02 14:30)
- 지표 카드 **4개**: 주의·경고·위험·초과
- 섹션 01 우선 확인 지역: 지도 패널(경로 표시, 상태 필터, 캔버스, 툴팁, 방위, 이동 버튼 뒤로·상위로·전국, 캡션) + 우선 확인 목록(건수 배지, 사업장명·주소·코드 검색, 맥락 문구, 경고 목록)
- 섹션 02 선택 굴뚝 분석: 차트 패널(위치·제목, 물질 NOx·SOx, 기간 6·12·24시간, 30분 측정 안내, 판독 문구, 추세 차트, 툴팁, **데이터 공백 설명**, 범례, 측정값 표 열기/닫기) + 우측 상세 패널
- 푸터: 상태 분류 기준(≥70·80·90·100), 접근성(건너뛰기 링크, `aria-live`)

**지도**: 전국→시도→시군→사업장 내려가기와 상위로 이동, 자유 이동(선택해도 한 지역에 갇히지 않음), 네이버 지도 전환, 마커 움직임(표현만, 값은 보간하지 않음), 방위, 지형·등고선, **최신 1일치(48시점, 30분)의 흐름만** 보여 주는 지도 시계(과거 날짜를 넘겨 보는 기능은 두지 않는다. 예측값은 만들지 않음), 지도 ↔ 목록 선택 연동

**차트·분석**: 단일·다중 차트, 조회 범위, 확대·포커스, 경고 민감도 패널(표시 민감도만 바꾸고 원본 기준은 안 바꿈), 물질 잠금(NOx·SOx 2종), 선택 사업장 일별 이력
- **새 요구: 차트를 클릭하면 그 시점의 수치를 보여 준다.** 기본은 지금처럼 가장 오른쪽(최신) 값이고, 클릭하면 그 시점으로 옮겨 간다.
- **굴뚝의 이력은 하단 차트가 상세하게 맡는다**(지도는 최신 1일치만 보여 준다). 기간은 6·12·24시간에서 시작하고, RDS에 쌓인 날짜만큼 일 단위로 넓힌다.
- **예측과 설명을 차트에 얹는다**(E의 예측 결과와 설명이 정해진 뒤). "왜 초과를 예측했나"를 물을 때 관측선 위에 예측 구간(점선)과 근거를 이어서 보여 주려는 것이다. 지금은 이 레이어가 들어갈 자리와 데이터 모양만 비워 둔다.

**개인 기능**: Cognito 로그인·로그아웃(이미 A가 구현), 즐겨찾기 사업장, 알림 설정(**"임시" 표기 제거**), 공지 롤링 배너(즐겨찾기 굴뚝의 경고·위험·초과)

**에이전트 창**: 우하단 아이콘 → 사이드 창 → 전체 화면 전환, 창 이동·폭 조절·저장, 마스코트 이동(스위치, 기본 꺼짐), 좁은 화면·모션 감소 처리, **채팅 연결(`/agent/chat`)은 아직 없음**

## 4. 구조 (세 층)

```
        ┌────────── 선택 상태(Zustand 스토어) ──────────┐
        │ 선택 사업장·굴뚝 · 물질 · 기간 · 지도 단계    │
        │ 필터 · 검색어 · 즐겨찾기                      │
        └──▲────────▲────────▲────────▲────────▲────────┘
          지도     목록     차트   에이전트 창  공지 배너
          (읽고, 누르면 스토어에 "선택해라"라고 한 번만 쓴다)
                     ▲
              데이터 훅(useSites, useSeries …) — 정적 JSON → API로 바꿀 때 이 층만 교체
```

- **스토어에는 사용자가 고른 것만** 넣는다. **측정값은 넣지 않는다**(선택으로부터 데이터 훅이 가져온다).
- **시간은 둘로 나눈다.** 지도 시계(최신 1일 안의 시점)는 지도가 갖고, 차트에서 클릭한 시점(이력 안의 시점)은 차트가 갖는다. 서로 영향을 주지 않는다.
- 컴포넌트는 서로를 부르지 않는다. 읽기(값이 바뀌면 자동 갱신)와 쓰기(선택 변경)만 한다.
- 폴더(제안): `src/state/`(스토어), `src/data/`(훅), `src/theme/`(색 변수·테마), `src/components/{map,list,chart,agent,notice}`, `src/logic/`(재사용 순수 로직)

**새로 만드는 것 / 재사용하는 것**

| 대상 | 방식 |
|---|---|
| 지역 지도(SVG) | **새로 만든다**(컴포넌트가 SVG를 렌더). 좌표 변환·확대 계산 같은 순수 함수만 재사용 |
| 네이버 지도 | **감싼다**(`useEffect` 안에서 SDK를 붙임) |
| 추세 차트 | **새로 만든다.** A의 `LiveChart`처럼 직접 그린 SVG, 그라데이션 영역 |
| 순수 로직 | 재사용: `mascot-engine`, `agent-frame-geometry`, `notice-banner-core`, `map-time-model`, `data-model`(이미 DOM 없이 시험됨). 시험(`tests/*.test.mjs`)도 같이 옮긴다 |
| 화면(HTML·CSS) | 전부 새로 만든다(디자인이 바뀌므로) |

## 5. 에이전트 연결 규약 (`POST {API_BASE}/agent/chat`)

- 헤더 `Authorization: Bearer <auth.user.access_token>`.
- 요청: `{conversation_id?, message}` 또는 `{conversation_id, resume:{card_id, option_id}}`, 선택 `context:{selectedStackId}`(필드는 이 셋뿐, 그 밖은 422).
- 응답: `status`(`ANSWERED`·`NEEDS_INPUT`·`PARTIAL`·`REFUSED`), `parts[]`(답·숫자·안내), `card`(옵션 선택 → `resume`으로 재호출), `notices[]`, `data_as_of`. 카드 종류: `STACK_CANDIDATES`, `STACK_CODE`, `POLLUTANT`, `TIME`, `OPERATION`, `CHOOSE_PART`, `MAP_OR_RETYPE`, `SCOPE`, `PERIOD`.
- 오류: `401`(재로그인), **`403 {detail:{code:"not_member"}}`**(초대 코드 전: A의 `Invite` 화면으로 보낸다. 에이전트도 `members` 그룹을 확인한다), `503`(데이터를 읽지 못함, 안내 문구 표시), `422`(계약 위반). 같은 `request_id`로 재시도하면 같은 응답을 돌려준다(spec 319).
- **`selectedStackId`는 `"{site_id}:{굴뚝번호}"`로 보낸다**(제안). 에이전트의 굴뚝 키가 이 형식이고, 화면 데이터에 둘 다 있다. 지도에서 고른 굴뚝이 스토어의 선택 굴뚝이므로 에이전트 창이 그대로 읽는다.
- CORS는 `https://smokestack-guard.store` 한 곳만 허용한다. 로컬 개발은 에이전트를 로컬로 띄우고 `APP_ORIGIN`을 맞춘다.

## 6. 이식 순서 (단계마다 운영에 올라가도 깨지지 않게)

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| ① 테마·공통 틀 | 테마를 최상위로 올리고(`tms-theme`), 색·모서리·글꼴 변수, 좌측 레일·머리말·푸터 틀, 선택 상태 스토어 뼈대 | 라이트·다크 전환, 로그인 뒤 틀이 보임, 빌드·시험 통과 |
| ② 데이터 훅 | `useSites`·`useSeries`(굴뚝 이력)·`useMapTimeline`(**최신 1일**만). 정적 JSON이고, 같은 모양으로 API가 나오면 교체 | 훅 단위 시험, 사업장 909곳 읽기 |
| ③ 지도 + 목록 | 지역 지도(새로), 목록, 검색, 필터, 지표 카드 4개, 선택 연동 | 전국→시군→사업장 이동, 지도 ↔ 목록 선택 동기화 |
| ④ 차트 | 하단 이력 차트(A 느낌, 그라데이션), 클릭 시점 수치, 공백 회색 그라데이션, 물질·기간, 판독 문구, 표, 예측·설명 레이어 자리 | 같은 굴뚝·하루에서 기존 값과 일치 |
| ⑤ 에이전트 창 | 창 이동·폭, 마스코트, `/agent/chat` 연결과 카드·답변 렌더러 | 질문 한 건이 왕복, 카드 선택(`resume`) 동작 |
| ⑥ 공지 배너·즐겨찾기 | 배너, 즐겨찾기, 알림 설정(임시 표기 제거), 서버 저장은 API 뒤 | 즐겨찾기한 굴뚝 상태가 배너에 뜸 |

단계 ②의 정적 JSON(20MB)은 저장소에 올리지 않는다. 배치 위치는 A와 정한다(예: 별도 S3 경로를 CI 동기화에서 제외). 이후 `dashboard-api`가 같은 모양으로 주면 훅만 바꾼다(엔드포인트 후보: `/api/sites`, `/api/sites/{id}/series`, `/api/map/timeline`, `/api/as-of`).

## 8. 확인하지 못한 것

- A의 첫 화면이 실제 기기·해상도에서 어떻게 보이는지, `Pretendard`가 실제로 로드되는지(CSS가 이름만 지정하고 파일을 싣지 않음)
- 중간 프론트의 지도·차트·민감도 패널은 **파일 설명 줄 기준**으로만 파악했다. 각 단계를 시작할 때 해당 파일을 읽고 정확히 확인한다.
- 실제 Cognito 로그인 왕복 이후의 흐름(초대 코드 통과 → 대시보드)은 A의 구현을 읽기만 했다.

## 9. 하지 않는 것

- 이 spec에서는 파일을 옮기거나 `services/dashboard-web`을 수정하지 않는다.
- CI·Terraform·버킷 설정은 A가 한다.
- A의 로그인 화면(`Landing.tsx`, `LiveChart.tsx`)은 건드리지 않는다. 단계 판정 함수 변경은 나중에 A와 같이 한다.

## 10. 옛 코드에서 옮겨 적을 규칙 (단계를 시작할 때 채운다)

새로 만들면서 놓치기 쉬운 규칙의 자리다. 지금은 확인한 것만 적고, 나머지는 각 단계에서 해당 옛 파일을 읽어 채운다.

| 규칙 | 확인 상태 | 옮길 곳(단계) |
|---|---|---|
| 상태 분류 주의 ≥70, 경고 ≥80, 위험 ≥90, 초과 ≥100 (비율 = 측정값 / 허용기준) | 푸터 문구로 확인 | ① 공통, ② 데이터 |
| 데이터 공백은 0이나 정상과 구분해 표시(회색 그라데이션) | 설계 결정 | ④ 차트 |
| 상태 행(미수신·보수 중 등)의 값은 null이고 0으로 채우지 않는다 | RDS 약속(A, spec 012)으로 확인 | ② 데이터 |
| 숫자 표시: 쉼표가 올바르게 묶인 것만 숫자로 읽고 원문 문자열은 보존 | `console-number.js` 설명 줄 | ② 데이터 |
| 물질은 NOx·SOx 2종만 켠다(나머지 잠금) | `pollutant-capabilities.js` 설명 줄 | ④ 차트 |
| 경고 민감도는 표시만 바꾸고 원본 기준값은 바꾸지 않는다 | `review-warning-panel.js` 설명 줄 | ④ 차트 |
| 지도 마커 움직임은 표현만이고 값은 보간하지 않는다 | `map-marker-motion.js` 설명 줄 | ③ 지도 |
| 가이드 선은 관측이나 예측으로 쓰지 않는다 | `review-chart-engine.js` 설명 줄 | ④ 차트 |

| "보관자료·실시간 아님·법적 판정 아님" 같은 정직 문구 | `index.html` 푸터·머리말 | ① 공통 |
