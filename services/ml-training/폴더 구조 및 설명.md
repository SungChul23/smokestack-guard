# E파트 ML Training — 폴더 구조 및 설명

> **2026-11-10 갱신 원칙**: 기존 내용은 삭제하지 않는다. 변경 전 설명은 취소선 또는 과거 기록 표시로 보존하고, 바로 아래에 변경 내용과 이유를 덧붙인다. 현재 구조 변경의 통합 기록은 **11절**을 참고한다. 파일 배치·모델 수는 그대로이며 데이터 처리 내부 구조와 기간 정책이 변경됐다.

## 1. 개요

E파트는 굴뚝 배출 위험 판정·AI 경고·MLOps를 담당한다. 이 폴더는 Issue #20의 **시나리오 A: 대만 CEMS 단독 학습**을 위한 입력 검증, 데이터 구성, 모델 학습, 평가, 저장 및 SageMaker 제출 코드를 담는다.

대상은 NOx(`nox`)와 SO₂(`sox`)다. XGBoost 분류·회귀 및 Random Forest 회귀로 N1-C, N1-R, S1-C, S1-R, RN1, RS1의 **6개 모델 결과물**을 만든다. 현재는 코드 작성 단계이며 실제 학습된 모델이 있다는 뜻은 아니다. 국내 TMS 혼합 학습·Serving API는 이 폴더에 구현되어 있지 않다.

이 문서는 폴더 내부 실제 코드의 정적 확인 결과다. 사용자 확인 완료 사항과 실행하지 않은 항목은 8절에 구분한다. 아래 상대 경로는 저장소 루트 기준이다.

## 4. 파일별 상세 설명

### contract.py

- **위치**: `services/ml-training/contract.py`
- **목적**: 잘못된 입력 구조를 학습 단계 전에 식별한다.
- **주요 함수/클래스**: `validate_contract(data: pd.DataFrame) -> None`. 클래스 없음. `REQUIRED_COLUMNS`, `NUMERIC_COLUMNS`, `STRING_COLUMNS`, `FLAG_COLUMNS` 상수로 검증 대상을 정의한다.
- **입력**: ML-ready pandas DataFrame.
- **처리**: 필수 35개 컬럼의 누락·중복을 검사한다. 비결측 값의 숫자·문자·불리언·시간 기본형을 확인한다. 추가 컬럼은 허용한다. `measured_at` 문자열은 자동 변환하지 않는다.
- **출력**: 정상은 `None`, 오류는 컬럼명이 포함된 `ValueError` 또는 `TypeError`.
- **연결**: `dataset.prepare_datasets()`와 `features.select_features()`가 호출한다. 데이터 수정·삭제·보간은 하지 않는다.
- ~~**상태**: 코드 작성·실데이터 미검증. 세부 dtype, NULL 허용 여부, 버전 허용값, 시간대 계약은 강제하지 않는다. 버전 컬럼의 문자형 검사와 허용 버전 값 검증은 다른 작업이다.~~
- **2026-11-10 변경 / 이유**: C파트 pandas ML-ready v2의 확정 버전 검증을 추가했다. `EXPECTED_VERSIONS`는 `feature_version=v1`, `label_version=v1`, `quality_policy_version=v2`이며 불일치·버전 결측은 오류다. 명확한 숫자·불리언·StringDtype은 컬럼형으로 검사하고 혼합형은 기존 값 검사를 유지해 반복 순회 비용을 줄인다. 기타 세부 dtype·NULL 정책은 임의로 추가하지 않았으며 실데이터 검증은 미실행이다.

- **처리**: 계약 검증 후 `feature_valid`와 목적별 `classification_eligible`/`regression_eligible`이 참인 행만 선택한다. 기존 플래그는 재계산하지 않는다. NULL 플래그는 적격으로 선택하지 않는다.

- **상태**: 코드 작성·미검증. 결측 보완이나 시간 슬롯·기준치 이력 검사는 수행하지 않는다.

### dataset.py

- **위치**: `services/ml-training/dataset.py`
- **목적**: 모델별 X/y와 공통 분할 정보를 같은 인터페이스로 준비한다.
- **주요 함수/클래스**: `prepare_datasets(data, task, pollutant) -> (datasets, metadata)`. 클래스 없음.
- ~~**입력**: 전체 ML-ready DataFrame, `classification`/`regression`, `nox`/`sox`.~~
- ~~**처리**: 전체 계약 검증 → 전체 시간 분할 → 구간별 물질 필터 → 임시 위치 인덱스 부여 → `select_features()` → 선택된 동일 위치의 Label 추출 순서다. Label 결측·무한대·분류 0/1 이외 값은 오류로 알린다. 중복 원본 인덱스로 join하지 않고 결과에 원본 인덱스를 복원한다.~~
- **2026-11-10 변경 / 이유**: `prepare_datasets()`는 기존 DataFrame과 로컬 Parquet 경로를 모두 받는다. `_prepare_parquet(path, task, pollutant, label)`가 1차 전체 35열·버전·관측 기간 검증 후, 2차에 모델별 필요한 열을 읽고 적격 행만 구성한다. 전체 컬럼의 정렬·분할 복사를 줄이기 위한 변경이다. `_collect_rows()`는 같은 위치의 Feature·Label을 함께 선택하고 `_finish_datasets()`는 선택 행만 안정 정렬한다. 원본 인덱스를 join 키로 사용하지 않으며, 배치마다 Lag·Label을 재계산하지 않는다. 기존 `datasets`·`metadata` 반환 형태는 유지한다.
- **2026-11-10 내부 함수 추가**: `_new_metadata(start, end)`, `_update_split_summary(metadata, masks, times)`, `_collect_rows(frame, times, metadata, task, pollutant, label, parts)`, `_finish_datasets(parts, metadata, task, pollutant, label, dtypes, total_rows)`, `_parquet_snapshot(path)`, `_check_snapshot(current, expected)`. 역할·제약은 11절 참조. 자체 클래스는 추가하지 않았다.
- **출력**:

```text
datasets = {
  "train":      {"X": DataFrame, "y": Series},
  "validation": {"X": DataFrame, "y": Series},
  "test":       {"X": DataFrame, "y": Series}
}
metadata = 분할 메타데이터 + prepared_rows + task + pollutant + label_column
```

- **연결**: 모든 `train_*.py` 모델 함수가 호출한다. 분류 Label은 `label_entry_60m`, 회귀 Label은 `label_ratio_60m`이다.
- **상태**: 코드 작성·미검증. 입력은 수정하지 않으며 기준치 변경 제외 로직을 별도로 실행하지 않는다.

### train_n1.py

- **위치**: `services/ml-training/train_n1.py`
- **목적**: NOx의 N1-C/N1-R을 학습한다.
- **주요 함수/클래스**: `train_n1_classifier(data)`, `train_n1_regressor(data)`. 자체 클래스 없음; `XGBClassifier`, `XGBRegressor` 사용.
- ~~**입력**: NOx로 미리 거르지 않은 전체 ML-ready DataFrame.~~
- **2026-11-10 변경 / 이유**: 두 N1 함수는 `pd.DataFrame | str | PathLike`를 받는다. 진입점이 Parquet 경로를 전달해 전체 원본을 fit 중 보관하지 않도록 연결한 변경이며, NOx 선필터링 없이 공통 준비를 호출한다. 모델 설정과 반환값은 그대로다.
- **처리**: `prepare_datasets(..., pollutant="nox")`를 분류/회귀별로 호출한다. 빈 Train은 오류, 분류 Train은 0과 1이 모두 있어야 한다. `random_state=42` 외 설정은 기본값이며 Train X/y만 `fit()`한다. 회귀 100% 초과 Label을 보존한다.

- **상태**: 코드 작성·실제 학습 미실행. import 시 학습하지 않는다.

### evaluation.py

- **위치**: `services/ml-training/evaluation.py`
- **목적**: 임계값 선정과 고정 임계값 평가를 분리한다.
- **주요 함수/클래스**: `select_f2_threshold(y_true, y_probability)`, `evaluate_classifier(y_true, y_probability, threshold)`, `evaluate_regressor(y_true, y_pred)`, 내부 `_validate_pair(y_true, y_prediction, classification=False)`. 자체 클래스 없음. `select_f2_threshold()` 내부 `rank(index)`가 후보를 비교한다.
- **입력**: 같은 행 순서의 1차원 정답·예측 배열. 분류 예측은 양성 클래스 확률이다. 입력 출처나 모델 간 동일 행 여부를 자동 입증하지 않는다.
- **처리**: 빈 입력·차원·길이·NaN/무한대를 검증한다. 분류는 0/1 정답과 0~1 확률을 요구한다. Validation 확률 고유값 후보를 F2 → Recall → 낮은 임계값 순으로 비교하며 정수 건수 기반 유리수 비교를 사용한다. 양성 판정은 `probability >= threshold`다.
- **출력**: 분류는 `threshold`, `precision`, `recall`, `f1`, `f2`, `average_precision`, `tp/fp/fn/tn`, `undefined_metrics` dict. 선정 함수는 `selection_split="validation"`도 반환한다. 회귀는 `mae`, `rmse`, `unit="%p"` dict.
- **연결**: `train_entrypoint.py`가 Validation 선정 결과의 임계값을 Test 평가에 전달한다. 지표는 `artifacts.py`로 저장한다.
- **상태**: 코드 작성·실제 평가 미실행. Validation 단일 클래스는 오류다. 일반 평가의 단일 클래스는 계산 가능한 지표를 유지하고 AP 등 해석 불가 지표는 `None`과 사유를 반환한다. 예측 양성 0건이면 Precision은 `None`; 실제 양성이 있으면 F1/F2는 0이다. 사건 단위 탐지율·일일 오경보·합격 기준은 구현하지 않았다.

### artifacts.py

- **위치**: `services/ml-training/artifacts.py`
- **목적**: 완성된 모델·JSON만 최종 경로에 공개하고 저장 모델을 복원한다.
- **주요 함수/클래스**: `save_artifacts(model, model_id, metrics, metadata, output_dir) -> dict`, `load_model(model_path)`, 내부 `_json_value(value)`, `_publish_directory(source, destination)`. 클래스 없음.
- **입력**: 모델 객체, 지원 모델 ID, 지표/메타데이터 dict, 호출자가 지정한 로컬 출력 경로. 복원은 직접 저장한 신뢰 가능한 joblib 파일 경로를 받는다.
- **처리**: 날짜·시간은 ISO 표현, NumPy 지원 기본형은 JSON 호환형으로 변환한다. NaN/Infinity·미지원형은 오류다. 같은 부모의 임시 디렉터리에 3개 파일을 쓰고 모두 닫힌 뒤 최종 경로로 원자적 이동한다. Windows rename 또는 Linux `renameat2(NOREPLACE)`로 충돌 시 덮어쓰지 않는다. 예외 시 임시 경로만 정리하고 원래 예외를 전달한다.
- **출력**: 다음 구조를 생성하고 `model`, `metrics`, `metadata` 키의 최종 `Path` dict를 반환한다. `load_model()`은 역직렬화한 모델 객체를 반환한다.

```text
<output_dir>/<model_id>/
├── model.joblib
├── metrics.json
└── metadata.json
```

- **연결**: 진입점이 저장 함수를 호출한다. `load_model()`은 이 폴더 내 자동 실행 흐름에서 호출되지 않으며 향후 재사용용이다.
- **상태**: 원자적 저장 코드 작성·실제 저장 및 동시 실행 미검증. 강제 종료·정리 권한 오류로 임시 경로가 남을 수 있다. Linux 기능 미지원 시 안전하게 실패하며 다른 OS는 지원하지 않는다. 전원 장애 내구성을 보장하는 fsync 처리는 없다. 외부·출처 불명 joblib는 임의 코드 실행 위험 때문에 로드하면 안 된다.

### sagemaker_job.py

- **위치**: `services/ml-training/sagemaker_job.py`
- **목적**: 학습 컨테이너와 별도 제출 환경에서 단일 Training Job을 구성한다.

- **입력**: 필수 `--model-id`, `--input-s3-uri`, `--output-s3-uri`, `--role-arn`; 선택 `--max-run`(기본 3600초), `--submit`.
- **처리**: 기본 모드는 URI·ARN 형식과 로컬 필수 파일·경로 분리를 확인하고 설정을 JSON 텍스트로 출력한다. 기본 모드에서는 SDK import·Session 생성·S3 접근을 하지 않는다. `--submit` 분기에서만 SDK 버전 확인, Session·객체 생성, 단일 `trainer.train(..., wait=False)`를 호출한다.
- **출력**: 기본 모드는 설정 dict. 제출 모드는 SDK `train()` 반환값을 그대로 반환한다. 서비스 실행 결과의 실제 값은 미확인이다.
- **연결**: `SourceCode`에 현재 폴더·진입점·requirements를 전달한다. `hyperparameters={"model-id": ...}`로 CLI를 연결하고 `train` 입력 채널과 S3 출력 경로를 설정한다. 사용자 출력 버킷/prefix는 Session의 소스 업로드 기본 위치로도 사용한다.
- **상태**: 사용자 확인 review_only 통과, 실제 제출 미실행. 서울 `ap-northeast-2`, `ml.m5.xlarge` 1대, Scikit-learn `1.9-0` 이미지 URI가 코드에 설정되어 있다. Spot 비활성화, 자동 병렬 제출·인스턴스 증설·Job 재시도 설정은 없다. `--submit`은 실행 승인 후에만 사용한다.

## 5. 전체 데이터 처리 흐름

> **2026-11-10 이력 표시**: 아래 첫 번째 흐름도는 변경 전 호출 구조를 삭제 없이 보존한 것이다. 현재 경로는 11절의 “갱신된 호출 흐름”을 따른다. 학습 함수가 공통 데이터 준비를 먼저 수행하고 그 후 fit한다는 순서는 유지된다.

모델 학습 함수가 `dataset.py`를 호출하므로 **데이터 준비보다 학습 함수 호출이 먼저**다. 실제 fit은 데이터 준비가 끝난 후 실행된다.

```text
sagemaker_job.main()  [기본: 설정 출력 후 종료]
  └─ --submit일 때만 ModelTrainer.train()
       ├─ 전체 S3 Parquet → train 채널의 로컬 경로
       ├─ --model-id → train_entrypoint.main()
       └─ SourceCode의 requirements 설치 설정

train_entrypoint.main()
  ├─ pandas.read_parquet(전체 입력)
  ├─ 선택한 train_n1 / train_s1 / train_rf 학습 함수
  │    ├─ dataset.prepare_datasets()
  │    │    ├─ contract.validate_contract(전체 입력)
  │    │    ├─ split.split_by_time(전체 입력)
  │    │    └─ 분할마다 물질 선택
  │    │         ├─ features.select_features()
  │    │         │    └─ contract.validate_contract() 재호출
  │    │         └─ 동일 위치의 Label 선택 → X/y·metadata
  │    └─ Train만 model.fit() → model·datasets·metadata
  ├─ Validation/Test 예측
  ├─ evaluation: Validation 임계값 선정 / 고정 Test 평가 또는 회귀 평가
  └─ artifacts.save_artifacts()
       └─ SM_MODEL_DIR/<model_id>/{model.joblib,metrics.json,metadata.json}
            └─ 정상 SageMaker 완료 시 model.tar.gz로 S3 출력
```

로컬 진입점은 S3를 직접 다운로드하지 않는다. SageMaker 입력 채널이 데이터를 제공한다. 출력 압축·S3 업로드도 `artifacts.py`가 아니라 SageMaker의 역할이다. 한 호출은 모델 하나만 처리하며 비교 실험을 자동 반복하지 않는다.

### 확정 기간과 누수 방지

모든 시각은 `Asia/Taipei`의 `measured_at` 기준이다. 오른쪽 끝은 미포함이다.

| 구간 | 사용자 확정 달력 기간 | 60분 제외 후 실제 선택 조건 |
|---|---|---|
| Train | 2023-11-01~2025-10-31, 24개월 | 2023-11-01 00:00 ≤ t < 2025-10-31 23:00 |
| Validation | 2025-11-01~2026-04-30, 6개월 | 2025-11-01 00:00 ≤ t < 2026-04-30 23:00 |
| Test | 2026-05-01~2026-10-31, 6개월 | 2026-05-01 00:00 ≤ t < 2026-11-01 00:00 |

- 두 분할 경계의 60분 전 행도 제외한다. Test 끝에 새 제외 정책을 추가하지 않는다.
- 전체 입력의 최소 관측일이 2023-11-01, 최대 관측일이 2026-10-31인지 검사한다. 다르면 경계를 재계산하거나 범위 밖 행을 조용히 버리지 않고 오류를 낸다. 이 검사가 매 슬롯의 존재를 보장하는 것은 아니다.
- `metadata`는 `ratios` 대신 `period_policy="24/6/6_months"`, `train_start`, `test_end_exclusive`와 공통 경계·실제 관측 시각·집계 건수를 기록한다.
- 행 개수·양성 수는 실행 입력으로 집계한다. 사용자 제공 집계나 특정 S3 경로를 코드에 고정하지 않았다. pandas 결과와 최종 Glue/Spark 결과의 동등성은 별도 확인 대기다.

### 두 단계 스캔과 입력 불변성

1. `_parquet_snapshot()`에서 파일 목록·상태와 읽기 보호를 확보한다.
2. 1차 스캔: 전체 필수 35열을 배치로 검증하고 전체 시각 범위·행 수·필요 열의 dtype 정보를 확인한다. 비대상 물질·부적격 행의 계약 오류도 숨기지 않는다.
3. 확정 기간 일치 여부와 공통 경계를 확인한다.
4. 2차 스캔: 22개 Feature, 목적별 Label, 시각, 물질, feature_valid, 목적별 eligibility 및 필요한 저장 인덱스를 읽는다. 배치 크기는 현재 65,536행, 미리읽기는 0, 스캔 스레드는 사용하지 않는다. 이 값은 모델 학습 배치나 샘플 수가 아니다.
5. `_collect_rows()`가 고정 경계·물질·적격 조건을 결합한다. `_update_split_summary()`는 물질·적격성 선택 전 전체 분할 건수를 유지한다.
6. `_finish_datasets()`가 선택 데이터를 모아 안정 정렬하고 X/y를 반환한다. 모은 데이터의 병합·정렬과 모델 내부 학습 메모리는 여전히 필요하다. 모든 데이터를 디스크 스트리밍으로 fit하는 구현은 아니다.

**Linux 변경 이유 및 현재 방식**: 초기 메모리 최적화에서 “읽기 전용 파일시스템이 아니면 실패”하도록 작성했던 방식은 이번 Linux 호환 수정에서 제거했다. 현재는 열린 파일에 `F_SETLEASE(F_RDLCK)`를 설정하고 `/proc/self/fd` 경로로 원래 inode를 읽는다. 파일 경로가 교체되더라도 원래 fragment 순서·파티션 표현식·스키마를 유지하는 구조다. SIGIO 쓰기 요청·lease 해제·파일 목록/상태 변경을 감지하면 실패한다. 권한·파일시스템이 lease를 지원하지 않거나 메인 스레드/SIGIO 사용 조건이 맞지 않아도 우회하지 않고 오류를 낸다. 파일을 복제하거나 S3 원본을 수정하지 않는다. 실제 SageMaker 환경에서 동작이 확인된 것은 아니다.

**Windows 유지 방식**: 파일을 읽기 공유만 허용하는 핸들로 유지하여 쓰기·교체를 차단한다. 두 스캔 사이와 완료 시 파일 목록·상태를 확인한다. 실제 OS 잠금·동시 변경 검증은 미실행이다.

```text
      → 전체 적격 Train으로 기존 모델.fit() 한 번
  → 기존 Validation/Test 예측·evaluation
  → 기존 artifacts 원자적 저장 → SageMaker 결과 업로드
```

DataFrame 직접 입력 경로도 유지하지만 그 경로를 호출한 외부 코드가 보관하는 원본 참조까지 자동 해제하지는 않는다. 진입점의 Parquet 경로 실행에서는 전체 원본 DataFrame을 생성하지 않는다. 입력 파일 목록·schema·dtype·인덱스의 동등성을 보장할 수 없는 경우 오류로 중단하며 자동 타입 축소·결측 보정·샘플링은 하지 않는다.
